# タグ絞り込みの設計サンプル（Issue #323）

`index.html`をブラウザーで開く。ネットワーク・依存パッケージは不要。合成30作品・8タグだけを使い、保存、外部ページ起動、Wails APIへの接続を行わない。

- 漫画名検索、タグ候補検索、チェックによるAND条件、個別/全解除、候補件数の変化を試せる。
- 上部の「状態」で多数選択・0件・再取得失敗・初回失敗・選択タグ削除後の合成例へ切り替える。実DBの故障やタグ管理との連携ではない。
- `?open`で候補を開く。`?narrow`は多数選択の例で、幅自体はブラウザーで変更する。併用は`?open&narrow`。
- `?check`でブラウザー内の簡易チェックを実行し、タイトルにCHECK PASS/FAIL、下部に7項目の結果を出す。自動のDOM確認であり、人によるキー操作やWebView2の検証ではない。

2026-10-31に通常幅1200×900・狭い幅520×960をChromeで描画確認し、利用者が配置を承認した。簡易チェック7項目は成功した。確認画像やブラウザープロファイルはGitへ追加しない。

ページ6件・行内のタグ補助表示・簡略な並び順と予定表示は設計確認用で、製品仕様への変更ではない。多数タグ時の折り返しと候補内部スクロールを含む配置を確認する。初回失敗の例でタグ未選択の合成作品が見えても、製品の初回取得成功を示すものではない。

正本は[タグ絞り込み設計](../../../docs/tag-filter.md)、理由と検証状態は[ADR-0020](../../../docs/adr/0020-confirm-tags-with-work-edits.md)。実API・競合・遅延応答・DB停止・3形式・再起動・実WebView2操作は後続で確認する。
