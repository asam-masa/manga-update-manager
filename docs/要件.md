# 要件

## 目的

漫画ごとのブックマークを一つずつ開かなくても、確認が必要な作品を一画面で判断できるようにする。

## 必須機能

- アプリ起動時に作品の状態を確認する
- 任意のタイミングで確認ボタンを押せる
- 設定時刻にアプリが起動していれば自動確認する
- URL、タイトル、表紙画像、定期更新情報を手入力できる
- 許可され、技術的に取得可能な情報は自動入力・自動確認できる
- 自動確認できない作品は、最後に開いてから1週間・2週間・1か月などの期間で「要確認」にする
- 作品を選ぶと既定ブラウザーでURLを開く
- 保持しているデータを表形式でも閲覧・編集できる

## 一覧拡張の合意事項

登録フォームの開閉、漫画名検索、三つの表示形式、タグ付け・絞り込み、表示設定の保持、今日を優先する予定順を合意した。振る舞いと未決定事項の正本は[作品一覧の拡張設計](./library-design.md)、重要な判断の背景は[ADR-0005](./adr/0005-define-library-behavior.md)を参照する。

登録フォームの開閉、漫画名検索、三つの表示形式、フォーム開閉と表示形式の再起動後の復元は実装済みである。Issue #238で小型20件・行20件・カード12件のページ切替、#257/#258で登録・タイトル・最終アクセスの各昇降順と設定保持を追加する。ページ番号と検索条件は保存しない。タグ、更新予定と、それらの設定保持は未実装であり、合意済みであることを実装完了とは扱わない。

## 更新予定日の追加合意

更新予定日の初回仕様は、一作品一日付を登録後の編集で設定し、空欄保存で解除する。日付経過やURL起動では解除せず、日本の日付変更・復帰時に今日優先順を見直す。行とカードへ日付を表示し、未来ON/OFFは予定順だけに適用して保存復元する。これは2026-10-25の追加合意であり、予定日の実装完了を示さない。詳細は[一覧設計](./library-design.md#手入力の更新予定日の合意issue-312026-10-25)と[ADR-0019](./adr/0019-use-manual-japan-schedule-dates.md)を参照する。

## 編集・削除の追加合意

2026-10-21、一覧の表示切替やタグより作品の編集・削除を優先すると合意した。URL・タイトル・サイト名・メモを編集し、画像・登録日時・最終アクセスを保持する。作品削除は作品名とURLの確認後に完全削除し、元画像には触れない。同作品の画像操作・URL起動・編集・削除は重ねない。詳細と未決定の実装契約は[編集・削除設計](./work-edit-delete.md)と[ADR-0018](./adr/0018-edit-and-delete-works.md)を参照する。合意済みであり、まだ実装していない。
