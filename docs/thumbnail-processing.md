# 一覧用画像の生成

Issue #41で追加したGo内部処理の契約を記載する。採用理由は[ADR-0011](./adr/0011-generate-png-cover-thumbnails.md)を参照する。画面からの選択、保存、画像配信はまだ実装していない。

## 入出力

`internal/thumbnail.Generate(io.Reader)`はJPEG・PNG・WebPの静止画からPNGのバイト列を返す。ファイル名・拡張子に依存しない。元画像へ書き込まず、ファイルやDBを操作しない。成功時だけ完全な出力を返し、失敗時はnilを返す。ReaderのCloseは呼び出し元が行う。

| 制限・補正 | 契約 |
| --- | --- |
| 入力容量 | 20 MiB以下。実際の読み取りを20 MiB + 1 byteで制限 |
| 画素数 | 正の幅と高さで2,000万画素以下。乗算のオーバーフローを避けて検査 |
| 出力 | PNG。長辺最大600px、短辺最低1px。小さい画像は拡大しない |
| 比率 | 元の比率で縮小し、端数を切り捨てる。切り抜かない |
| 方向 | TIFF IFD0のOrientation 1〜8を縮小前に補正。未設定は通常方向 |
| 透過 | PNG・WebPのアルファを保持 |
| 同時処理 | 読み取りから生成までプロセス内で1件ずつ |

PNGのアニメーション制御チャンクとWebPのアニメーションフラグ・チャンクを拒否する。バイト列の単純検索ではなく、コンテナ境界から判定する。内容と寸法の確認後に完全デコードし、縮小画像を生成する。

## エラー

`errors.Is`で`ErrTooLarge`、`ErrDimensions`、`ErrUnsupported`、`ErrAnimation`、`ErrOrientation`、`ErrInvalid`を判別できる。読み取り・デコードの原因はラップする。将来のApplication/Wails境界で利用者向け案内へ変換し、低レベルの原因や選択パスをそのまま公開しない。

## 制約と後続

色プロファイル変換、任意のメタデータの完全な検証、元画像の保存は行わない。出力にメタデータを引き継がない。EXIFはIFD0の方向だけを扱い、サブIFD・埋め込みプレビューへ進まない。JPEG・PNG・WebPの完全な仕様適合性検査ではない。

入力が検証できてもデコーダー内部のメモリー使用量を固定できるわけではない。Readerは呼び出し元が制御する。ファイルの通常ファイル判定、キャンセル、既存画像の維持、保存後の後処理とWails配信はIssue #42以降へ分ける。

## 検証

`go test ./internal/thumbnail`で、合成JPEG・PNGとテスト内で生成したWebPを使う。WebPは1pxのVP8と、単色のVP8Lビット列を用いる。利用者の表紙をテストやGitへ追加しない。

`go test ./internal/thumbnail -fuzz=FuzzGenerate -fuzztime=20s -parallel=1`で、形式・コンテナ・メタデータの変異入力も確認できる。有限のテストが全入力の安全性を証明するとは扱わない。
