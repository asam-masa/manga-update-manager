# 現在の機能を試す利用ガイド

Issue #202。2026-10-21、基準main `bc2e6ffcc32e3332dafd6e27f034ac9538829c9d`の機能を案内する。更新予定や通知まで完成した製品ではない。まず少数の作品で操作を確かめ、大量登録や既存の管理手段からの全面移行は急がない。

## 起動する

Windows用のデスクトップアプリであり、通常のブラウザーで画面を開く方式ではない。ビルド環境は[README](../README.md#開発コマンド)を参照する。起動中の旧版と開発モードを通常終了してから、リポジトリで次を実行する。

```powershell
wails build
```

成功したビルドの`build/bin/manga-update-manager.exe`をエクスプローラーから起動する。これはローカルでビルドしたexeであり、インストーラーの作成や公開配布を意味しない。失敗したビルドの後に残る古いexeを、新しい版として起動しない。

`wails dev`は開発用である。通常の環境で起動するとexeと同じ保存先を使い、検証専用データへ自動的に分離されるわけではない。二つを同時に開かない。このガイドではAPPDATA変更・保存先移動・リンク作成を案内しない。

## 保存先と注意

- 通常のDBは`%AppData%\MangaUpdateManager\manga.sqlite`、管理画像は同じフォルダーの`covers`へ保存する。exeの隣やリポジトリ内へ保存する方式ではない。
- 利用者が選ぶ元画像は変更・削除せず、生成したPNGを管理する。画像解除は作品と管理画像の参照を外す操作であり、作品自体の削除ではない。
- 同じ保存先では一つだけ起動できる。終了後の`.instance.lock`残置は正常であり、解除のために手動削除しない。
- DBや管理画像を手動編集・削除してリセットしない。利用者データ・閲覧履歴・元画像をGitや公開Issueへ追加しない。
- バックアップ・復元機能は未実装である。現在のアプリを唯一の記録先とせず、元画像や従来の管理記録を保持する。このガイドはデータ移行・バックアップや復元の成功を保証する手順ではない。

保存先がネットワークやリンクを経由する場合など、画像機能が安全に扱えない条件がある。アクセス権限やリンクを変更して警告を回避せず、[保存契約](./cover-persistence.md)の範囲を確認する。

## 少数の作品で試す

1. 残してよい作品のURLとタイトルを確認して登録する。同じURLの重複登録は拒否される。削除にはUndoがないため、通常保存先で使い捨てのデータを大量登録する試験は避ける。
2. 「漫画名で検索」で絞り込み、検索文字を消して一覧へ戻る。登録フォームは開閉できる。開閉設定は再起動後も保持するが、検索文字とフォームの途中入力は終了後に保持しない。
3. 作品の画像設定ボタンから手元のJPEG・PNG・WebPの静止画像を選ぶ。変更・取消・画像解除を確認する。20 MiB超や2,000万画素超、アニメーションなどは拒否される。入力の詳しい条件は[画像生成契約](./thumbnail-processing.md)を参照する。
4. 外部の既定ブラウザーを開いてよいURLだけを一覧から開く。起動要求成功後に最終アクセスを保存する。最新話への自動移動、ページ表示や読了の確認ではなく、登録したURLをそのまま開く。
5. 処理結果を確認して「×」で終了し、同じexeを再起動して登録内容・画像・保存済み最終アクセスを確認する。操作中は終了案内に従い、完了後にもう一度閉じる。終了要求で操作を取消したり、自動終了を予約したりはしない。

未設定・欠損・破損の画像は仮表示になる。表示失敗だけで作品やDB参照は自動削除されない。元画像から明示的に設定し直すか画像を解除する。欠損・破損を意図的に作るために通常保存先のファイルを操作しない。

## 警告や長い処理が出たとき

- 設定・解除の成功と後処理警告が同時に出る場合、確定済みの変更は維持される。警告を通常の失敗と同じ意味で扱わず、表示された案内を確認する。不要ファイルや未確認出力が残ることがある。
- 「結果を確認できません」「再起動して状態を確認」などの案内では、成功・失敗や旧状態を推測して操作を繰り返さない。画像やDBを手動で戻さず、通常終了できる状態なら終了し、再起動後の状態を確認する。再起動で必ず復旧する保証はない。
- 長時間案内の段階・経過時間は最後の観測情報であり、残り時間や正常動作の保証ではない。処理中は通常終了を拒否する場合がある。時間だけで強制終了やデータ削除を勧めるものではない。
- 解決しない場合は、版、操作、画面の安全な案内文、通常終了できたかを記録して相談する。作品URL・個人パス・画像・DB・ログ全文をそのまま公開しない。

## 更新予定日を設定・解除する（Issue #264）

作品の編集で「更新予定日」を入力して保存する。日本時間の日付を一つだけ指定でき、時刻は入力しない。空欄で保存すると解除する。キャンセルでは変更しない。日付の途中入力は完成させるか、全体を空欄にしてから保存する。現在値は編集を開き直して確認できる。カード・行一覧で現在値を確認でき、予定順・未来ON/OFFも後述の#290で追加した。冒頭の基準版の範囲とは区別する。

## 更新予定日を一覧で確認する（Issue #278）

カードは最終アクセスの下に、行一覧は「更新予定日」列に表示する。未設定は「未設定」と表示する。小型には表示しない。日付を過ぎても自動で消えない。予定日順の並べ替えと未来ON/OFFは下記の#290で追加した。行一覧の狭い画面では横スクロールで右側の列を確認できる。

## 予定順と未来表示を使う（Issue #290）

「並び順」で「更新予定：今日を先頭」を選ぶ。今日、過去の新しい日付、未来の近い日付、未設定の順になる。同日と未設定同士は登録の古い順である。行一覧の「更新予定日」見出しからも同じ順序を選べ、逆順はない。

予定順中だけ出る「未来の予定を表示」をOFFにすると明日以降を隠す。未設定は残り、登録順・タイトル順・最終アクセス順では未来も表示する。並び順と未来設定は再起動後に復元し、検索文字とページ番号は保存しない。未来の切替は1ページ目へ戻る。

日本の日付は午前0時を目標に見直し、アプリへ戻ったときと1分ごとにも確認する。スリープ中や指定時刻ちょうどの実行は保証しない。予定日は自動で消さず、検索・編集中の内容と現在ページを保つ。ページがなくなった場合だけ補正する。保存警告が出た場合も現在の表示は維持し、再起動すると以前の設定へ戻る場合がある。確認済みの範囲は[予定順の検証記録](./verification/scheduled-date-order.md)を参照する。

## 作品情報を編集する（Issue #215）

作品の「編集」でURL・タイトル・サイト名・メモを修正し、「保存する」を押す。画像・登録日時・最終アクセスは保持する。背景の一覧や検索はダイアログを閉じてから操作する。保存せず戻す場合は「キャンセル」またはEscで閉じる。保存中は閉じず結果を待つ。

入力拒否や重複なら入力を残して案内する。「保存結果を確認できません」などの案内では再送せず、入力を控えて再起動後に状態を確認する。保存確定後の警告は成功を取り消すものではない。検索から外れた場合も画面上部の成功通知を確認する。この節は#215の追加機能であり、冒頭の旧基準版には含まれない。

## 作品のタグを付け外しする（Issue #306）

作品の編集で、予定日とメモの間の「タグ」を使う。既存候補をチェックして選択し、選択タグの「×」かチェック解除で外す。候補欄は全角・半角や英字の大小を吸収した部分一致で探せる。新規名を入力したら「新規タグとして仮追加」を押す。複数追加でき、作品の「保存する」でまとめて確定し、キャンセルなら新規タグも作らない。入力しただけの名前は追加されない。似た表記でも保存名は別であり、保存時に完全同名の候補が存在すれば自動再利用する。

タグの読込失敗では他の入力を保持し、再読み込みが成功するまで保存できない。タグの改名・削除を検出した場合も入力を保持し、新しい名前の採用や削除済み選択の解除を案内する。DB停止・結果不明の案内では再保存を繰り返さず、入力を控えて状態を確認する。この編集欄からタグ自体の改名・削除は行わず、次節のタグ管理を使う。一覧のタグ絞り込みは後続である。

## タグを管理する（Issue #315）

作品一覧の「タグ管理」で、未使用を含むタグと全作品の使用数を表示する。検索と自然な昇順でタグを探せる。タグの「名前変更」で1件ずつ保存する。編集中は検索・他タグの変更は無効となり、未保存で閉じる/Escでは破棄確認を行う。現在の名前が変わっていた場合は入力を残し、表示された現在名を確認してから改めて保存する。

「削除」ではタグ名と対象作品のタイトル一覧を確認し、「削除する」でタグと関連だけを外す。作品本体は残る。「一覧に戻る」かEscでは削除せずタグ一覧へ戻り、管理画面の×では管理を閉じる。取得失敗や未確認の間は削除できず、確認後に対象が変わった場合は最新情報を再確認してからもう一度操作する。

改名・削除の結果通知は管理画面を閉じても一覧側へ残る。結果不明では再送せず、アプリを再起動して状態を確認する。「確定しましたが接続を確認できない」という警告は保存/削除の成功とは別であり、操作を重ねない。管理画面の処理中は戻る/閉じるを待つ。AND絞り込みは未実装である。詳しい範囲は[管理画面の契約](./tag-management.md)を参照する。

## 作品を削除する（Issue #224）

作品の「削除」で作品名・URL・タグを確認する。タグは取得が完了するまで「未取得」と表示され、削除できない。取得成功の0件は「タグなし」となる。取り消す場合は「キャンセル」またはEscで閉じる。「削除する」で完全削除する。Undo・ゴミ箱はなく、元画像は削除しない。管理画像は未参照・所有・安全性を確認できるものだけ整理し、共有画像や確認できないファイルは保持する。作品からタグの関連は外れるが、タグ候補自体は残る。

確認後に作品情報やタグが変わっていた場合は両方を読み直し、もう一度確認して「削除する」を押す。初期取得/再取得に失敗したら削除できず、再読込か取消を選べる。初期のタグ読込中は取消可能だが、削除/明示再取得の処理中は取消せず結果を待つ。削除済みと画像整理の警告は別であり、警告だけを理由に削除を繰り返さない。結果不明なら再起動後に状態を確認する。検索文字と画面上部の結果通知は保持する。この節は#224と#310の追加機能であり、冒頭の旧基準版には含まれない。

## 未実装と既知の制約

冒頭の基準版で未実装だった一覧の3形式・基本並び順・手入力の更新予定・作品編集のタグ欄・タグ管理は、後続Issueで追加した。タグ絞り込み、繰り返し予定・アラート、バックアップ・復元、サイト自動取得は未実装である。将来の設計は[一覧拡張設計](./library-design.md)とGitHub Issuesで管理し、画面にある機能と区別する。

#176の、画像選択ダイアログ中の無効な親への特殊な強制前面化で終了する問題は未修正である。アプリ自身はその強制前面化を行っておらず、確認した手動Alt+Tabでは再現していない。通常の切替操作で必ず安全とも、必ず終了するとも扱わない。通常操作で再現した場合は完了判定を再評価する。[再現条件](./verification/webview-focus-exit.md)を参照する。

ADR-0013のVerifiedは[記録した範囲の検証完了](./verification/cover-validation-final.md)であり、無故障・データ無損失・全環境での成功の保証ではない。このガイドの追加に伴う実データでの新たな運用確認は行っていない。
