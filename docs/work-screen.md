# 作品登録と一覧画面

Issue #23で、既存のWails作品APIを登録フォームと一覧画面へ接続する。APIとDBスキーマの変更は行わない。

## 画面と入力

通常幅では左に登録フォーム、右に作品一覧を置く。760px以下では縦に並べる。URLとタイトルは必須、サイト名とメモは任意とする。画像管理は対象外のため、サムネイルパスは空文字で送る。表紙部分は装飾用プレースホルダーを表示する。

一覧はAPIのID昇順を維持し、タイトル、サイト名、URL、メモ、登録日時を表示する。日時は`Intl.DateTimeFormat`で`Asia/Tokyo`を指定し、日本時間と明示する。URLは文字列として表示し、ブラウザー起動や画像取得を行わない。作品の文字列はReactの通常の描画を使い、HTMLとして解釈しない。

## 状態と失敗時の動作

| 状態 | 画面の振る舞い |
| --- | --- |
| 初回取得中 | 読み込み中と表示する。未登録とは表示しない |
| 取得成功・0件 | 未登録の案内を表示する |
| 取得失敗 | エラーと再読み込みを案内する。過去の取得結果は維持する |
| 登録中 | 入力と登録ボタンを無効化し、同じ処理の再送信を拒否する |
| 登録失敗 | 入力を保持し、APIの利用者向けエラーを表示する |
| 登録成功 | 入力をクリアし、成功を表示して一覧を再取得する |
| 登録成功・再取得失敗 | 成功を維持し、再登録せず一覧を再読み込みするよう案内する |

登録と一覧取得の成功・失敗を別々に扱う。一覧の読み込み中と登録中は再読み込みボタンを無効化する。初回取得中でも登録は利用できる。リクエスト番号を更新し、古い一覧応答が新しい結果を上書きしないようにする。

状態は利用するApp内で管理し、カード描画だけをWorkListへ分離する。外部状態管理、ルーター、UIライブラリは使用しない。既存ADR-0003の範囲内の局所的な実装であり、新規ADRは作成しない。

## エラーと操作性

Wailsが返す既知の`{code, message}`だけを利用者向け文言として扱う。未知の文字列や実行時エラーは共通の案内へ置き換える。フォームには入力ラベル、必須指定、フォーカス表示を付ける。エラーは`role="alert"`、成功と読み込み中は`role="status"`で通知する。

## テスト依存

配布アプリの依存は増やさず、開発依存として次を固定する。推移依存は`package-lock.json`で管理する。

| ライブラリ | 採用理由 | バージョン | ライセンス |
| --- | --- | --- | --- |
| Vitest | 既存のVite・TypeScript環境で画面テストを実行する | 5.0.3 | MIT |
| jsdom | Wailsや実DBを起動せずDOM操作を検証する | 30.1.2 | MIT |
| React Testing Library | ラベル・roleから利用者操作を検証する | 16.3.3 | MIT |
| DOM Testing Library | React Testing Libraryのpeer dependency | 10.4.2 | MIT |
| user-event | 入力、クリック、Tab、Enterを実行する | 14.6.7 | MIT |

各ライブラリには公式文書と公開パッケージがあり、今回の環境でテストを実行した。導入時のnpm監査では既知の脆弱性は0件だった。将来の保守・安全性を保証する結果ではない。

APIを差し替えて、登録、空一覧、エラー、二重送信、再取得失敗、古い応答、日本時間、HTML文字列の表示を検証する。DOMテストではWebView2の描画と実SQLiteまでの結合動作は検証できない。

## 手動確認

Windows版アプリで次を確認する。確認前に使用する保存先と既存データの有無を把握する。

1. 起動し、未登録または既存の作品一覧が表示される
2. URLと日本語タイトルを入力し、登録後に一覧へ反映される
3. 同じURLを登録するとエラーになり、入力が残る
4. 終了・再起動後も登録した作品を確認できる
5. 日本語IMEの確定操作、Tab移動、狭いウィンドウの表示を確認する

エージェントによる実利用者DBでの登録は行わない。実機操作の未実施項目を成功扱いしない。
