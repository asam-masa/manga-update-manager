# 作品登録と一覧画面

Issue #23で、既存のWails作品APIを登録フォームと一覧画面へ接続する。APIとDBスキーマの変更は行わない。

この文書は#23の基本画面、#26のフォーム開閉・検索、#27の開閉設定保存を記録する。リンク・最終アクセスの#25の契約は[作品API](./work-api.md)を参照する。以後の仕様と未決定事項は[作品一覧の拡張設計](./library-design.md)を参照する。

## 画面と入力

通常幅では左に登録フォーム、右に作品一覧を置く。760px以下では縦に並べる。URLとタイトルは必須、サイト名とメモは任意とする。登録フォームでの画像選択は対象外のため、サムネイルパスは空文字で送る。表紙部分は#165で現在画像を表示し、未設定時は装飾用プレースホルダーを維持する。

一覧はAPIのID昇順を維持し、タイトル、サイト名、URL、メモ、登録日時、最終アクセスを表示する。日時は`Intl.DateTimeFormat`で`Asia/Tokyo`を指定し、日本時間と明示する。URLは#25のリンク風buttonで既定ブラウザーへ渡す。#23当時の画像取得なしの画面から、#165で作品IDの限定配信を使用する画面へ進める。作品の文字列はReactの通常の描画を使い、HTMLとして解釈しない。

## Issue #165: 現在画像の表示

2026-10-19、まず既存カードの枠に画像を表示し、画像設定ボタンは後続へ分ける方針を承認した。起動時整理の結果取得後に画像を取得する。枠は均一寸法を維持し、切り抜きや小画像の拡大をしない。未設定は「本」のみ、失敗は「本」と当該カード内の「画像を表示できません」に分け、全体警告やダイアログを増やさない。DB参照を自動解除せず、一覧再読み込み成功後に再取得する。[表示の検証と限界](./verification/display-current-cover.md)を参照する。

## Issue #26: フォーム開閉と検索

上部の開閉ボタンは`aria-expanded`と`aria-controls`でフォームの状態と対応を示す。フォームは初回表示する。非表示時は一覧を一列全幅にする。フォームを再生成せず`hidden`で隠し、Reactの入力状態を保持する。登録中は開閉を無効にし、終了後に再び操作できる。開くとURL欄へ、閉じると開閉ボタンへフォーカスを移す。

検索文字、確定した検索条件、取得済み作品はAppが保持する。取得済み配列を副作用のない`titleMatches`で絞り込み、APIの追加呼び出しはしない。表示形式へ検索状態を持たせず、後続の表示形式を追加するときも同じ絞り込み結果を渡す。形式切り替え自体の検証は後続Issueで行う。

検索用の文字だけを全半角・大小文字・正規等価表記について揃え、検索文字の前後の空白を除く。かなの種類と途中の空白は区別する。元のタイトルと入力表示は変更しない。全文字列へNFKCを適用すると丸数字なども変わるため、幅の変換はHalfwidth and Fullwidth Formsに限定する。

入力欄に表示する文字と一覧へ適用する文字を分け、`compositionstart`から`compositionend`まで一覧を維持する。フォーム内のIME確定用Enterでも誤登録しないよう、変換中のキー操作を判別する。実WebView2のIMEは手動でも確認する。

検索条件は登録・再読み込み・フォーム開閉で解除しない。登録成功時は入力をクリアするが、登録したタイトルが現在の条件に一致しなければ非表示の理由を成功通知へ添える。登録中に検索が変わった場合も現在の条件で案内する。未登録の案内と検索結果0件の案内は分ける。件数は「表示件数 / 全件数」とする。

#26ではDB・API・依存ライブラリを追加しなかった。#27で開閉だけを永続化する。検索文字と途中入力は再起動時に初期化する。

## Issue #27: 開閉設定の保存

起動時に`LoadDisplaySettings`を呼び、復元が終わるまではフォームを隠して開閉・登録を待つ。一覧取得・検索は独立して利用できる。未登録ならフォーム表示を正常扱いとし、読み込み失敗なら表示の初期値と警告で続行する。復元だけでは自動保存もフォーカス移動も行わない。StrictModeの古い読み取り結果は無視する。

明示的な開閉のたびに`SetRegistrationFormVisible`を呼ぶ。開閉は即座に反映し、保存要求は前の要求が成功・失敗した後に順に送る。最新の要求が完了するまでは保存中と表示する。保存失敗でも画面を戻さず、再起動後に以前の状態へ戻る場合があると警告する。古い保存応答は最新の通知を上書きしない。明示操作の保存が成功すれば設定の警告を解除する。保存応答前に終了した場合、未送信・処理中の保存完了は保証しない。

保存対象の型は検索・途中入力から独立させる。未実装の設定は先行追加しない。設定だけの失敗は作品一覧を止めず、DB全体の初期化失敗では既存の作品エラーを表示する。保存方式と制約は[ADR-0006](./adr/0006-persist-display-settings.md)、API契約は[作品API設計](./work-api.md)を参照する。

## 状態と失敗時の動作

| 状態 | 画面の振る舞い |
| --- | --- |
| 初回取得中 | 読み込み中と表示する。未登録とは表示しない |
| 取得成功・0件 | 未登録の案内を表示する |
| 取得失敗 | エラーと再読み込みを案内する。過去の取得結果は維持する |
| 登録中 | 入力と登録ボタンを無効化し、同じ処理の再送信を拒否する |
| 登録失敗 | 入力を保持し、APIの利用者向けエラーを表示する |
| 登録成功 | 入力をクリアし、成功を表示して一覧を再取得する |
| 登録成功・再取得失敗 | 成功を維持し、再登録せず一覧を再読み込みするよう案内する |

登録と一覧取得の成功・失敗を別々に扱う。一覧の読み込み中と登録中は再読み込みボタンを無効化する。初回取得中でも登録は利用できる。リクエスト番号を更新し、古い一覧応答が新しい結果を上書きしないようにする。

状態は利用するApp内で管理し、カード描画だけをWorkListへ分離する。外部状態管理、ルーター、UIライブラリは使用しない。既存ADR-0003の範囲内の局所的な実装であり、新規ADRは作成しない。

## エラーと操作性

WailsのError包装を越えて、[ADR-0016](./adr/0016-preserve-safe-api-errors-through-wails.md)の識別可能なJSON文字列を共通処理で復元する。検証済みの既知`{code,message}`だけを利用者向け文言として扱い、DB停止判定にも使う。未知の文字列や生の実行時エラーは共通案内へ置き換える。フォームには入力ラベル、必須指定、フォーカス表示を付ける。エラーは`role="alert"`、成功と読み込み中は`role="status"`で通知する。

## テスト依存

配布アプリの依存は増やさず、開発依存として次を固定する。推移依存は`package-lock.json`で管理する。

| ライブラリ | 採用理由 | バージョン | ライセンス |

| Vitest | 既存のVite・TypeScript環境で画面テストを実行する | 5.0.3 | MIT |
| jsdom | Wailsや実DBを起動せずDOM操作を検証する | 30.1.2 | MIT |
| React Testing Library | ラベル・roleから利用者操作を検証する | 16.3.3 | MIT |
| DOM Testing Library | React Testing Libraryのpeer dependency | 10.4.2 | MIT |
| user-event | 入力、クリック、Tab、Enterを実行する | 14.6.7 | MIT |

各ライブラリには公式文書と公開パッケージがあり、今回の環境でテストを実行した。導入時のnpm監査では既知の脆弱性は0件だった。将来の保守・安全性を保証する結果ではない。

APIを差し替えて、登録、空一覧、エラー、二重送信、再取得失敗、古い応答、日本時間、HTML文字列の表示を検証する。DOMテストではWebView2の描画と実SQLiteまでの結合動作は検証できない。

## 手動確認

Windows版アプリで次を確認する。確認前に使用する保存先と既存データの有無を把握する。

1. 起動し、未登録または既存の作品一覧が表示される
2. URLと日本語タイトルを入力し、登録後に一覧へ反映される
3. 同じURLを登録するとエラーになり、入力が残る
4. 終了・再起動後も登録した作品を確認できる
5. 日本語IMEの確定操作、Tab移動、狭いウィンドウの表示を確認する

エージェントによる実利用者DBでの登録は行わない。実機操作の未実施項目を成功扱いしない。

## 登録済み作品の画像操作（Issue #43）

各カードの日時の下に、未設定なら「画像を設定」、設定済みなら「画像を変更」「画像を外す」を置く。欠損・破損でも参照が残っていれば変更・解除を表示し、画像自体は仮表示にする。画像・作品名にリンクは付けず、URLだけをページへの入口とする。

状態はAppから使う`useCoverActions`で作品IDごとに保持する。カードは検索で非表示になっても処理・通知を失わない。新たな状態管理ライブラリは追加しない。

- 同作品の画像ボタンは処理完了まで無効。選択中だけは全作品の設定・変更を無効にし、別作品の解除は利用できる。検索と別作品のURL操作は継続できる。#211以降は同作品のURL起動と画像操作をバックエンドの共通受付でも重ねず、競合要求は完了後の再操作を案内する。画面の共通ボタン無効化と編集UIへの接続は#205の後続で扱う。
- 選択完了イベントは作品ID・操作IDが現在の要求と一致する場合だけ扱う。Promise完了でも同じ照合で選択中を解放し、通知の到着順に依存しない。
- 処理中は「画像を処理しています…」。結果はカード内で成功・エラー・成功後の後処理警告を分ける。取消は結果通知なし。
- 通知は時間で消さず、閉じる操作か同作品の次回画像操作まで保持する。完了時に検索条件やフォーカスを変えない。通知を閉じる操作では同カードの有効な画像ボタンへフォーカスを戻す。全て無効なら画像操作領域へ戻し、フォーカス枠を表示する。
- 解除は確認・Undoなし。元画像は変更・削除しない。失敗と結果不明を区別し、結果不明や内部エラーでは再起動による状態確認を案内する。

画像操作は`thumbnailPath`と`updatedAt`、URL起動は`lastAccessedAt`だけを画面へ統合する。作品DTO全体の置き換えで、別操作の結果を巻き戻さない。一覧取得開始後に完了した画像・アクセス更新を保持し、古い一覧応答にも上書きさせない。画像成功と一覧成功では画像を再取得する。

再取得では画像要素の作り直しに加え、URLの`v`へ新しいランダムな小文字16進32文字の目印を付ける。通常の再描画だけでは変えない。管理パスや画像の版はURLへ含めず、目印も保存しない。[実WebView2の確認結果](./verification/cover-image-refresh.md)を参照する。

保存・停止の成功境界は[画像保存契約](./cover-persistence.md)、検証と残る実機確認は[画像操作UI](./verification/cover-actions-ui.md)を参照する。

## 長時間の画像処理（Issue #183）

処理中だけ最新の観測状態を約1秒ごとに取得する。バックエンドが選択待ちを除いて計測した経過時間が10秒以上なら、検索結果から独立した画面上部に作品名・段階・最終確認時の経過秒を表示する。起動時整理も同じ案内を使い、進捗率・残り時間は出さない。操作API完了後は案内を消し、既存の成功・失敗・警告へ移る。

取得は重ねず、古い応答や別の操作IDを使わない。取得失敗・不正応答は固定案内に置き換え、前回の情報がある場合は未確認であることを示して保持する。取得配列からの欠落だけで完了と判断せず、未観測の状態も推測しない。時間による中断・停止判定・終了予約はしない。[自動テスト・実画面結果と限界](./verification/cover-progress-ui.md)を参照する。
