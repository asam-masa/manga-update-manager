# 作品登録と一覧画面

Issue #23で、既存のWails作品APIを登録フォームと一覧画面へ接続する。APIとDBスキーマの変更は行わない。

この文書は#23の基本画面、#26のフォーム開閉・検索、#27の開閉設定保存を記録する。リンク・最終アクセスの#25の契約は[作品API](./work-api.md)を参照する。以後の仕様と未決定事項は[作品一覧の拡張設計](./library-design.md)を参照する。

タグ管理のダイアログ・行内編集・削除確認と結果保持は、#322の[画面設計](./tag-management.md#管理画面の合意issue-322未接続)へ記録する。合成サンプルの基本配置は承認済みであり、製品画面の接続と実WebView2確認は#315に残る。

## 画面と入力

### 編集ダイアログ（Issue #215）

各作品の「編集」でURL・タイトル・サイト名・メモを開く。標準モーダルで背景を非活性にし、開始済み処理は継続する。入力は開いた時点から保持し、保存中の連打・キャンセル/Esc閉鎖を防ぐ。失敗時は入力、成功時は検索とカード外の通知を保持する。元の編集ボタンが消えた場合は検索欄へ戻す。古い一覧応答と画像/アクセス応答で保存済み4項目を戻さない。契約・自動テストと実画面確認の区別は[検証記録](./verification/work-edit-dialog.md)を参照する。作品削除は未接続である。

通常幅では左に登録フォーム、右に作品一覧を置く。760px以下では縦に並べる。URLとタイトルは必須、サイト名とメモは任意とする。登録フォームでの画像選択は対象外のため、サムネイルパスは空文字で送る。表紙部分は#165で現在画像を表示し、未設定時は装飾用プレースホルダーを維持する。

一覧はAPIのID昇順を維持する。#23ではメモと登録日時も表示したが、#250で後述の3形式の描画へ進め、一覧からは除いた。日時は`Intl.DateTimeFormat`で`Asia/Tokyo`を指定し、日本時間と明示する。URLは#25のリンク風buttonで既定ブラウザーへ渡す。#23当時の画像取得なしの画面から、#165で作品IDの限定配信を使用する画面へ進める。作品の文字列はReactの通常の描画を使い、HTMLとして解釈しない。

## Issue #165: 現在画像の表示

2026-10-19、まず既存カードの枠に画像を表示し、画像設定ボタンは後続へ分ける方針を承認した。起動時整理の結果取得後に画像を取得する。枠は均一寸法を維持し、切り抜きや小画像の拡大をしない。未設定は「本」のみ、失敗は「本」と当該カード内の「画像を表示できません」に分け、全体警告やダイアログを増やさない。DB参照を自動解除せず、一覧再読み込み成功後に再取得する。[表示の検証と限界](./verification/display-current-cover.md)を参照する。

## Issue #26: フォーム開閉と検索

上部の開閉ボタンは`aria-expanded`と`aria-controls`でフォームの状態と対応を示す。フォームは初回表示する。非表示時は一覧を一列全幅にする。フォームを再生成せず`hidden`で隠し、Reactの入力状態を保持する。登録中は開閉を無効にし、終了後に再び操作できる。開くとURL欄へ、閉じると開閉ボタンへフォーカスを移す。

検索文字、確定した検索条件、取得済み作品はAppが保持する。取得済み配列を副作用のない`titleMatches`で絞り込み、APIの追加呼び出しはしない。表示形式へ検索状態を持たせず、3形式へ同じ絞り込み結果を渡す。#252で形式切替時の検索保持をDOMで確認する。実WebView2の一体確認は#237へ残す。

検索用の文字だけを全半角・大小文字・正規等価表記について揃え、検索文字の前後の空白を除く。かなの種類と途中の空白は区別する。元のタイトルと入力表示は変更しない。全文字列へNFKCを適用すると丸数字なども変わるため、幅の変換はHalfwidth and Fullwidth Formsに限定する。

入力欄に表示する文字と一覧へ適用する文字を分け、`compositionstart`から`compositionend`まで一覧を維持する。フォーム内のIME確定用Enterでも誤登録しないよう、変換中のキー操作を判別する。実WebView2のIMEは手動でも確認する。

検索条件は登録・再読み込み・フォーム開閉で解除しない。登録成功時は入力をクリアするが、登録したタイトルが現在の条件に一致しなければ非表示の理由を成功通知へ添える。登録中に検索が変わった場合も現在の条件で案内する。未登録の案内と検索結果0件の案内は分ける。件数は「表示件数 / 全件数」とする。

#26ではDB・API・依存ライブラリを追加しなかった。#27で開閉だけを永続化する。検索文字と途中入力は再起動時に初期化する。

## Issue #27: 開閉設定の保存

起動時に`LoadDisplaySettings`を呼び、復元が終わるまではフォームを隠して開閉・登録を待つ。一覧取得・検索は独立して利用できる。未登録ならフォーム表示を正常扱いとし、読み込み失敗なら表示の初期値と警告で続行する。復元だけでは自動保存もフォーカス移動も行わない。StrictModeの古い読み取り結果は無視する。

明示的な開閉のたびに`SetRegistrationFormVisible`を呼ぶ。開閉は即座に反映し、保存要求は前の要求が成功・失敗した後に順に送る。最新の要求が完了するまでは保存中と表示する。保存失敗でも画面を戻さず、再起動後に以前の状態へ戻る場合があると警告する。古い保存応答は最新の通知を上書きしない。明示操作の保存が成功すれば設定の警告を解除する。保存応答前に終了した場合、未送信・処理中の保存完了は保証しない。

保存対象の型は検索・途中入力から独立させる。未実装の設定は先行追加しない。設定だけの失敗は作品一覧を止めず、DB全体の初期化失敗では既存の作品エラーを表示する。保存方式と制約は[ADR-0006](./adr/0006-persist-display-settings.md)、API契約は[作品API設計](./work-api.md)を参照する。

## 状態と失敗時の動作

| 状態 | 画面の振る舞い |
| --- | --- |
| 初回取得中 | 読み込み中と表示する。未登録とは表示しない |
| 取得成功・0件 | 未登録の案内を表示する |
| 取得失敗 | エラーと再読み込みを案内する。過去の取得結果は維持する |
| 登録中 | 入力と登録ボタンを無効化し、同じ処理の再送信を拒否する |
| 登録失敗 | 入力を保持し、APIの利用者向けエラーを表示する |
| 登録成功 | 入力をクリアし、成功を表示して一覧を再取得する |
| 登録成功・再取得失敗 | 成功を維持し、再登録せず一覧を再読み込みするよう案内する |

登録と一覧取得の成功・失敗を別々に扱う。一覧の読み込み中と登録中は再読み込みボタンを無効化する。初回取得中でも登録は利用できる。リクエスト番号を更新し、古い一覧応答が新しい結果を上書きしないようにする。

状態は利用するApp内で管理し、カード描画だけをWorkListへ分離する。外部状態管理、ルーター、UIライブラリは使用しない。既存ADR-0003の範囲内の局所的な実装であり、新規ADRは作成しない。

## エラーと操作性

### URL起動の共通通知（Issue #243、親#236）

URL起動の受付と表示状態はAppで保持し、カードの検索非表示・再表示に依存させない。IDと登録日時で通知を区別する。処理中・失敗は一覧上部に作品名付きで表示し、別作品の通知を上書きしない。同じ作品の次のURL操作で通知を更新し、通常成功時は日時へ反映して処理中表示を消す。自動再試行や通常成功の通知は追加しない。

通知を閉じると表示中の対象作品へ戻り、非表示・別登録への置換・操作不能なら検索欄へ戻る。#243の先行段階のURLボタンへの復帰から、#245で合意済みの「⋯」への復帰へ変更した。#247で画像・編集・削除の通知も一覧上部へ集約した。

DOMテストで同時tickの二重要求、検索非表示中の処理・失敗保持、複数通知、閉鎖後の復帰、ID再利用と古い日時応答、内部診断の非公開を確認する。初回テストで復帰先IDの組み立て不一致を検出し、通知と同じID・登録日時の表現に揃えた。実WebView2の確認は[#236の記録](./verification/work-actions-notices.md)を参照する。URL起動の故障・遅延の自動テストと、今回の実画面での画像/編集/削除操作は区別する。

WailsのError包装を越えて、[ADR-0016](./adr/0016-preserve-safe-api-errors-through-wails.md)の識別可能なJSON文字列を共通処理で復元する。検証済みの既知`{code,message}`だけを利用者向け文言として扱い、DB停止判定にも使う。未知の文字列や生の実行時エラーは共通案内へ置き換える。フォームには入力ラベル、必須指定、フォーカス表示を付ける。エラーは`role="alert"`、成功と読み込み中は`role="status"`で通知する。

## 登録済み作品の画像操作（Issue #43）

#245で編集・削除・画像操作を次節の「⋯」へ移した。以下のカード内の個別ボタン・通知は#43時点の記録である。現在は#247の共通通知を使い、通知閉鎖後は「⋯」または検索へ戻す。

各カードの日時の下に、未設定なら「画像を設定」、設定済みなら「画像を変更」「画像を外す」を置く。欠損・破損でも参照が残っていれば変更・解除を表示し、画像自体は仮表示にする。画像・作品名にリンクは付けず、URLだけをページへの入口とする。

状態はAppから使う`useCoverActions`で作品IDごとに保持する。カードは検索で非表示になっても処理・通知を失わない。新たな状態管理ライブラリは追加しない。

- 同作品の画像ボタンは処理完了まで無効。選択中だけは全作品の設定・変更を無効にし、別作品の解除は利用できる。検索と別作品のURL操作は継続できる。#211以降は同作品のURL起動と画像操作をバックエンドの共通受付でも重ねず、競合要求は完了後の再操作を案内する。画面の共通ボタン無効化と編集UIへの接続は#205の後続で扱う。
- 選択完了イベントは作品ID・操作IDが現在の要求と一致する場合だけ扱う。Promise完了でも同じ照合で選択中を解放し、通知の到着順に依存しない。
- 処理中は「画像を処理しています…」。結果はカード内で成功・エラー・成功後の後処理警告を分ける。取消は結果通知なし。
- 通知は時間で消さず、閉じる操作か同作品の次回画像操作まで保持する。完了時に検索条件やフォーカスを変えない。通知を閉じる操作では同カードの有効な画像ボタンへフォーカスを戻す。全て無効なら画像操作領域へ戻し、フォーカス枠を表示する。
- 解除は確認・Undoなし。元画像は変更・削除しない。失敗と結果不明を区別し、結果不明や内部エラーでは再起動による状態確認を案内する。

画像操作は`thumbnailPath`と`updatedAt`、URL起動は`lastAccessedAt`だけを画面へ統合する。作品DTO全体の置き換えで、別操作の結果を巻き戻さない。一覧取得開始後に完了した画像・アクセス更新を保持し、古い一覧応答にも上書きさせない。画像成功と一覧成功では画像を再取得する。

再取得では画像要素の作り直しに加え、URLの`v`へ新しいランダムな小文字16進32文字の目印を付ける。通常の再描画だけでは変えない。管理パスや画像の版はURLへ含めず、目印も保存しない。[実WebView2の確認結果](./verification/cover-image-refresh.md)を参照する。

保存・停止の成功境界は[画像保存契約](./cover-persistence.md)、検証と残る実機確認は[画像操作UI](./verification/cover-actions-ui.md)を参照する。

## 作品操作パネル（Issue #245、親#236）

各作品の「⋯」から既存の編集・削除・画像設定/変更/解除へ接続する。WorkListが開いている作品のID・登録日時を一つだけ保持する。パネルは通常のボタン群として、`aria-expanded`・`aria-controls`・名前付きgroupで対応を示す。メニュー専用のARIA roleや新しいUIライブラリは導入しない。

開くと最初の有効な操作へ、上キーで開くと最後の有効な操作へ移る。上下/Home/Endで有効ボタンを移動し、Enterで実行する。Tabは通常のDOM順に移動する。Escは元の「⋯」へ戻し、外クリック・外へのフォーカス移動・作品の非表示・画面外側のスクロール・サイズ変更ではフォーカスを移さず閉じる。パネル内のスクロールでは閉じない。

viewportを基準に固定配置し、右端と下端で位置を調整する。幅200pxを基準に8pxの余白を取り、狭い画面では幅・高さを制限してパネル内をスクロールする。DOMの模擬矩形に加え、#236で幅640pxの実ウィンドウでの配置も確認した。文字拡大は未確認であり、[確認方法と限界](./verification/work-actions-notices.md)を参照する。

同作品のURL/画像操作中や停止中の無効条件は各操作へ維持し、「⋯」自体は全操作が無効でも開ける。編集・削除には消えるパネル内のボタンではなく「⋯」を復帰先として渡す。#245では画像通知の配置・ID単位の保持方式を維持したが、#247で次節の共通通知へ変更した。

DOMで単一表示・キー移動・外クリック/Tab/Esc・非表示後の再表示・画面端の位置計算・無効操作・既存ダイアログと通知の復帰を確認する。#236で[実WebView2の一体確認](./verification/work-actions-notices.md)、#237で[形式切替時の閉鎖](./verification/library-layouts.md)を確認した。バックエンドの受付・停止・通常終了の条件は変更しない。

## 作品ごとの共通通知（Issue #247、親#236）

URL・画像の処理中/失敗と、画像・編集・削除の完了結果/警告を、検索欄の下の共通欄へ作品名付きで表示する。長時間の画像観測も同じ位置へ置く。通知がなければ共通欄の要素を描画しない。編集・削除ダイアログ内の入力エラーと処理中表示は維持する。

通知はID・登録日時・操作種別で区別し、別作品や別種操作の通知を上書きしない。自動消去せず、閉じる操作か同じ登録の同種操作の再実行で更新する。編集・削除は入力画面を開いただけでは消さず、保存/削除要求の開始時に前の結果を消す。取消・再確認の読込だけでは消さない。

画像フックも登録単位で開始時の作品名を保持する。選択/解除の同作品受付と選択枠は従来どおりID・操作IDで管理し、結果DTOは開始時と同じID・登録日時を要求する。画像・URL・編集の応答は既存の所有項目だけを現在の同じ登録へ統合する。画像の再取得でDOM要素が変わることと、別登録の参照を書き換えることは区別する。

閉じると表示中の同じ登録の「⋯」へ戻し、非表示・削除済み・別登録なら検索へ戻す。Promise完了だけではフォーカスを変えない。編集ダイアログの遅延復帰も、利用者が別要素へ移動済みなら上書きしない。追加DOMテストで別作品の通知閉鎖後に遅延復帰が割り込む状態を検出して修正した。

検索非表示中の結果・警告、複数作品の画像/編集/削除通知、同種操作の更新、取消での保持、ID再利用、通知閉鎖後の復帰、画像結果の登録不一致拒否をDOMで確認する。#236で[専用合成データの実WebView2確認](./verification/work-actions-notices.md)、#237で[3形式をまたぐ処理・成功・整理警告](./verification/library-layouts.md)を補った。保存先・バックエンドの受付・停止・通常終了の契約は変更しない。

## 長時間の画像処理（Issue #183）

処理中だけ最新の観測状態を約1秒ごとに取得する。バックエンドが選択待ちを除いて計測した経過時間が10秒以上なら、検索結果から独立した画面上部に作品名・段階・最終確認時の経過秒を表示する。起動時整理も同じ案内を使い、進捗率・残り時間は出さない。操作API完了後は案内を消し、既存の成功・失敗・警告へ移る。

取得は重ねず、古い応答や別の操作IDを使わない。取得失敗・不正応答は固定案内に置き換え、前回の情報がある場合は未確認であることを示して保持する。取得配列からの欠落だけで完了と判断せず、未観測の状態も推測しない。時間による中断・停止判定・終了予約はしない。[自動テスト・実画面結果と限界](./verification/cover-progress-ui.md)を参照する。

## 一覧の3形式の描画（Issue #250、親#237）

WorkListは`compact`・`rows`・`cards`を受け取り、既定は`cards`とする。#250ではカードだけをAppへ接続し、#252で形式切替ボタン・2行の上部操作欄・保存/復元へ接続する。

- 小型は画像/仮画像だけを起動入口にし、中央画像140×187px・タイトル17px最大3行・タイトル下の横長「⋯」28pxを基準とする。画像がなくても失敗しても同じ入口を維持する。
- 行一覧はタイトル・URL・最終アクセス・操作のtableで、画像を作らない。幅は最低760pxとし、狭い場合は表の中だけ横スクロールする。タイトル17px・1行、交互背景とホバー/枠内フォーカスの強調を使う。
- カードは画像100×134px・タイトル17px最大2行・サイト名/URL/最終アクセスと40pxの「⋯」を使う。高さ164pxを基準に、タイトルと空のサイト名にも枠を確保する。400px以下では画像列を80pxへ縮める。メモ・登録日時は一覧へ表示しない。

タイトルは文字列のまま選択可能とし、全文を標準titleに保持する。小型以外のURLも標準titleと1行省略を使う。画像は全体を収め、表示失敗の案内は枠内へ置く。実際のクリップボード操作や標準titleの表示はDOMテストだけで検証済みとはしない。

一覧の実幅をResizeObserverで観測し、小型は859px超で5列、700px超で4列、それ以下で2列とする。カードは700px超で2列、それ以下で1列とする。ウィンドウ幅だけで判断せずフォーム表示中の有効幅にも追従する。既存のfixed操作パネルの座標系を維持し、親要素へ新しいレイアウト制約を加えず観測値をCSS変数へ渡す。これらの境界と寸法は親#237の実画面で再確認する。

形式または一覧の実幅が変わると開いているパネルを閉じ、利用者が移したフォーカスを奪わない。通常レビューで幅だけの変更では旧位置に残るケースを指摘し、回帰テストで再現後に修正した。画像・URLの処理状態や通知はApp側に維持する。DOMで各形式の一つだけの起動入口・無効条件・画像未設定/失敗・tableの列・タイトルの文字列保持・観測幅による列数を確認する。#252で切替と設定復元を接続し、#237で[実画面確認](./verification/library-layouts.md)を補う。確認範囲と未確認の倍率・操作を分け、Issue完了はレビュー・CI・マージも条件とする。

## 表示形式と2行の操作欄（Issue #252、親#237）

大きな画面見出しと常設の説明を除き、1行目に件数・小型/行一覧/カード・登録フォーム開閉・再読み込み、2行目に漫画名検索を置く。読み上げ用の一覧見出しと検索ラベルは残す。選択中の形式は`aria-pressed`で示す。

初期表示はカードとし、`LoadWorkListMode`の復元完了まで形式ボタンを無効にする。未登録時のカードはAPIが返す。未知値や読込失敗はカードと警告で続行し、自動保存・自動修復をしない。復元時にフォーカスやスクロールを動かさない。

明示的に別形式を選ぶと検索を維持して即座に切り替え、一覧上端へスクロールする。フォーム開閉と形式保存は同じ要求列から操作順に一つずつ送る。APIはそれぞれ自分の設定項目だけを更新する。保存失敗でも表示を戻さず、項目別の警告を残す。古い保存結果で最新操作の警告や保存中表示を変更せず、別項目の保存成功でも警告を消さない。同じ形式の選択では保存を増やさない。

復元要求は世代で識別し、StrictModeやアンマウント前の応答を画面へ反映しない。アンマウント後は待機中の形式保存を開始しない。既に送信した要求は取り消せず、異なるAppインスタンスをまたぐ保存順序の保証はしない。

DOMで復元・読込失敗・連続選択・フォームとの保存順序・失敗後の回復・検索保持・URL/画像処理中の切替と通知保持を確認する。#237で実WebView2の配置、3形式の再起動復元、保存失敗・未知値からの回復、画像処理中の切替と整理警告を確認した。[検証記録](./verification/library-layouts.md)の対象版・合成データ・限界を参照する。

2026-10-24の実画面確認で、利用者は画像と文字の大きさを保ち、一覧の実幅に応じて列数を減らす挙動を承認した。Windows文字サイズ110%の今回の環境では、ウィンドウ幅1200pxで小型5列、1024pxで4列、640pxで2列だった。100%との比較は未実施であり、1024pxで5列を強制するために画像や文字を縮小しない。行・カードの操作ボタンは共通paddingによる寸法超過を避け、40×40px・padding 0へ固定する。小型の28px横長指定は維持する。

## 基本並び順の画面接続（Issue #258）

検索欄右の標準selectで登録・タイトル・最終アクセスの各昇降順を選ぶ。狭い幅は同じ操作領域内で折り返す。ラベルは読み上げ用にも残し、変更時は1ページ目と一覧上端へ戻すが、フォーカスをページ番号へ移さずselectに残す。検索と表示形式の変更では並び順を維持する。

初回は登録古い順。復元完了までは選択とページ操作を待ち、未知値・読込失敗は初期値と安全な警告で続行する。復元だけでは保存・スクロール・フォーカス移動を行わない。フォーム・形式と共有した要求列で明示操作を順に保存し、失敗でも選択を戻さない。古い保存応答で新しい警告や保存中表示を変えず、アンマウント後は待機中の保存を開始しない。

全件を検索してからコピーを整列し、当該ページを切り出す。タイトルは検索の正規化を再利用し、数字列は先頭ゼロを除いた桁数と文字列で比較する。Numberへ変換せず大きな整数の丸めを避ける。文字部分は日本語の照合と、同値時の文字列比較でかな・記号の区別を保つ。読み仮名の五十音順は保証しない。最終アクセスは秒部分を時差込みで比較し、小数秒は9桁へゼロ埋めして別に比較する。APIのナノ秒精度をミリ秒へ丸めず、未設定・解釈不能は両方向で末尾、同順位は常にID昇順とする。

登録後の移動先は表示形式と並び順の初期復元を待って計算する。待機中に利用者が並び順・ページ・検索・形式を変えた場合やモーダルを開いた場合は、その後の操作を優先する。編集・再読込・日時保存後は現在ページを維持し、整列によって作品が別ページへ移る場合がある。最終アクセス順での日時保存成功は共通欄に閉じられる成功通知を残す。保存失敗では日時・順序を変更せず、従来の部分成功案内を残す。

並び順変更ではWorkListを作り直して古い操作パネルを閉じる。開始済み処理・結果・警告はAppに残す。DOMで自然順、同順位、3形式、保存順、復元競合、ページ移動、編集・アクセス・画像処理中の整列を確認する。実画面の確認範囲は[検証記録](./verification/work-sort.md)を参照する。

## 一覧のページ切替（Issue #238）

全件取得とAPIのID昇順を維持し、全件を検索で絞り込んだ後、小型20件・行20件・カード12件で描画を分割する。#258では検索とページ分割の間へ選択中の並べ替えを入れる。上下のページ操作には前へ・番号・次へと表示範囲を置き、現在番号を`aria-current="page"`で示す。多数ページは先頭・末尾・現在付近だけ表示する。0件は操作を出さず、既存の空一覧/検索不一致の案内を使う。

ページ位置は形式・確定検索条件・並び順に属する。いずれかが変わると1ページ目へ戻す。IME変換中の未確定文字だけでは変更せず、フォーカスは検索欄に維持する。ウィンドウ幅・フォーム開閉では同じ作品を同じページへ置く。起動時は1ページ目で、ページ番号の保存APIは追加しない。

登録後の一覧取得が成功し、新作品が検索に一致すれば、その登録IDと登録日時を持つ作品のページへ移る。一致しない場合と一覧取得失敗では現在ページを保ち、既存の成功/非表示/再読み込み案内を使う。後続のページ・形式・検索操作、モーダル開始は移動用の操作番号を進め、古い登録結果で利用者の移動を取り消さない。既存の一覧要求番号も維持し、古い一覧を使った移動を行わない。

編集・削除・再読み込みでは現在ページを維持する。件数減少で範囲外になった場合だけ最後のページへ補正し、その補正値を記憶する。後から作品が増えても、補正前の番号へ戻さない。補正は描画前に行い、空の最終ページを一度表示してから戻す方式にしない。

明示的なページ移動と登録作品への移動は、描画後に一覧上端へスクロールし、上側の現在ページボタンへフォーカスする。検索・自動補正・初期復元ではページ操作からfocusしない。編集/削除ダイアログを閉じる既存の復帰処理は維持する。

全作品、画像/URLの処理状態、結果・警告はAppに保持し、WorkListへは当該ページの作品だけを渡す。ページから隠れても処理は継続し、表示中へ戻ると同じ無効条件と更新値を使う。通知を閉じる復帰先が別ページなら、既存の検索欄への復帰を使い、自動的に別ページへ移らない。

ページ切替は追加API要求を発生させない。取得通信量・全件保持のメモリ使用量を減らす変更ではなく、規模に応じたサーバー側取得は対象外とする。検証では各件数境界・IME・再読込の増減・古い応答・登録/編集/削除・処理中のページ往復と通知を区別する。[自動テストと実WebView2確認](./verification/work-pagination.md)には、登録と初期復元の競合で発見した問題、修正、補助操作の失敗と未確認の範囲を記録する。

## 予定順・未来条件・日付見直し（Issue #290）

## タグ編集の失敗時の合意（Issue #295、未接続）

#303で[公開API](./tag-api.md)を先行した時点の合意を以下に残す。#306の編集画面への接続は次節を参照する。

- 初期の現在タグ・候補を取得できるまで保存を無効にする。初期取得/再取得の失敗は他の入力を保持し、再読み込みかキャンセルを選ぶ。タグを空として保存しない。
- 保存時のtags_changedでは本文・付け外し・複数新規仮追加を残す。最新候補を読み直しても、タグ選択全体を保存済み状態へ戻さない。

- DB停止・結果不明・保存中の閉鎖制御は既存編集の契約を維持し、自動再送しない。保存成功時に編集を閉じる。

## タグ編集の画面接続（Issue #306）

2026-10-28にサンプルの配置が承認された。予定日とメモの間に選択済みタグ・候補検索・明示的な新規仮追加をまとめる。サイト名と予定日は通常幅で横並び、600px以下では縦並びとする。入力部だけをスクロールし、保存・キャンセルは下部へ残す。初期フォーカスは従来どおりURLで、タグの追加・解除・変更確認後は候補入力へ戻す。標準チェック欄を使い、候補入力のEnterは作品保存やタグ作成を起こさない。仮追加は専用ボタンで明示する。

初期取得は候補と現在タグの両方が成功し、ID・正確名・一覧の整合を検証するまで保存しない。片方の通常失敗に隠れたDB停止も観測する。初期取得成功時だけ保存済みタグを採用し、再取得では選択・複数新規仮追加・本文を置換しない。古い世代やアンマウント後の応答は反映しない。読込失敗は再取得可能だが、DB停止では本文を保持して再起動を案内する。

tags_changedでは最新情報を読み直し、選択済みIDの正確名を候補と照合する。改名は明示採用、削除済みは明示解除するまで再保存しない。新規仮追加の名前と保存時の同名候補の解決はAPIへ渡す。完全解除は空配列を明示し、未取得を空として送信しない。保存中・DB停止・結果不明・確定後警告の扱いは既存編集を維持する。

候補は漫画名検索の表記比較を再利用し、保存名には検索用の変換を行わない。タグ名の前後空白はGoのTrimSpaceと一致する範囲で除き、コードポイント数と制御文字を確認する。最後の検証はGo側でも行う。登録・タグ管理・AND絞り込み・削除確認画面への接続は含めない。[検証範囲と残る確認](./verification/work-tag-editor.md)を参照する。

## 削除確認のタグ接続（Issue #310、親#295）

2026-10-28に作品名・URL・タグ一覧をまとめて確認する方針が承認された。初期タグ取得が成功するまでは「未取得」とし、削除を無効にする。取得成功の0件だけを「タグなし」と表示し、正確なID/名前集合をDeleteWorkInput.tagsへ明示する。IDは文字列のまま扱う。多数のタグは一覧内でスクロールし、名前を折り返す。

初期取得中はキャンセル/Escで閉じられる。読込失敗・不正返却値では削除せず、最新情報の再読込か取消を選べる。再取得は作品情報とタグの両方の成功と検証を待ち、片方だけで確認内容を更新しない。途中の失敗では前回の確認内容を未確認と表示し、削除を無効にする。古い世代とアンマウント後の応答は破棄する。

確認後の作品/タグ変更は既存APIのwork_changedで削除を拒否し、最新の作品情報とタグを読み直す。成功後も自動削除せず、作品名・URL・タグを見直してもう一度「削除する」を押す。再確認後はキャンセルへフォーカスを戻す。削除/明示再取得の処理中は従来どおり取消・Esc・二重送信を止める。DB停止は並行する別読取の失敗や不存在に隠さず、削除を止めて再起動を案内する。未確認の応答で今回削除したと扱わず、確定後の画像整理警告と結果不明の契約も維持する。

二つの読取が同じ瞬間のDB状態とは保証しない。既存削除APIは送った作品項目とタグ集合を削除と同じTxで照合し、取得後の変更も拒否する。[検証範囲と限界](./verification/work-delete-tags.md)を参照する。タグ管理・タグ自体の削除・AND絞り込みは含めない。
