# ADR-0017: 画像処理の観測状態を定期取得する

- Status: Accepted
- Validation Status: Verified
- Date: 2026-10-20
- Related: [#186](https://github.com/asam-masa/manga-update-manager/issues/186)、親[#183](https://github.com/asam-masa/manga-update-manager/issues/183)

## Context

#184で要求別の段階コールバックを追加した。コールバックは参照排他や画像資源を保持している間にも呼ばれ、即時復帰する観測専用である。長時間案内のために画面へ段階を渡すが、画像処理が画面への送信を待つ構造にしない。段階や経過時間は正常動作・完了の証明ではない。

## Decision Drivers

- 保存・停止・解放の既存順序と結果を維持する
- 通知の欠落や遅延で別操作・完了済み操作を誤表示しない
- キュー・配送スレッド・再送などの保守を増やさない

## Considered Options

### イベントで全段階を配送する

既存の選択完了イベントに近く即時性がある。一方、同期送信を避ける配送処理や欠落時の復元が必要になる。全段階の履歴は今回必要ない。

### メモリ上の最新状態を画面から定期取得する

処理側は短いメモリ更新だけで済む。画面の取得には遅れがあり、短い段階は見えないことがあるが、最新状態を再取得できる。取得失敗・空配列を処理完了と取り違えない契約が必要である。

## Decision

2026-10-20、利用者はメモリ上の最新状態を処理中だけ約1秒ごとに取得する方式を承認した。段階コールバックは専用mutexの下で固定コードと開始時刻を更新するだけとし、DB・画像・Wails送信を行わない。取得もAppの寿命ロックやI/Oを待たず、コピーを返す。

操作ID付き設定・変更と追加の操作ID付き解除を要求別に管理し、起動時整理は一回の実行を管理する。最初の段階を観測するまで取得結果へ公開しない。設定・変更の計測は生成開始、解除・整理は最初の段階からとし、通常のtime.Nowの単調時計成分で経過時間を求める。段階変更で計測をリセットしない。

返す情報と画面の注意事項は[画像処理の状態取得API](../verification/cover-progress-api.md)を正本とする。終了した記録は削除し、最終結果は既存の操作APIで判断する。履歴・画像パス・内部診断・絶対時刻は保存・公開しない。既存の選択完了イベントと旧APIも維持する。

## Consequences

段階専用の送信キューや再送処理は不要になる。取得間隔分の遅延と短い段階の省略を許容する。操作IDは対応付け用であり認証情報ではない。既存のWails選択完了イベントの配送方式そのものは今回変更しない。

## Validation

#186で計測・コピー・重複ID・完了時削除・古いコールバック・並行取得・実参照更新中・起動時整理中の取得をテストし、生成バインディングとWindowsビルドを確認した。画面の約1秒取得、10秒表示、古い応答の破棄、検索非表示、完了遷移、取得失敗時の非断定は後続の#183に残し、#186時点ではPendingとした。ADR-0013全体の完了とも別である。

2026-10-21、#183で画面へ接続し、境界・単一取得・ID照合・古い応答・取得失敗・完了遷移を自動テストで確認した。分離した合成データと待機を制御した実WebView2で、起動時整理・選択待ちの除外・設定/解除・検索非表示・長時間案内の消去を確認した。この定期取得・表示契約の検証としてVerifiedとする。全競合と実故障を実機で再現したものではなく、失敗・遅延応答の反例は自動テストで補う。[結果と限界](../verification/cover-progress-ui.md)を参照する。ADR-0013全体はPendingを維持する。
