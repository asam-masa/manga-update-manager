# ADR-0018: 作品の編集範囲と確認後の完全削除を決める

- Status: Accepted
- Validation Status: Pending
- Date: 2026-10-21
- Related: [#204](https://github.com/asam-masa/manga-update-manager/issues/204)

## Context

最新話や話数一覧へ移動しやすい入口が、作品固定URLでないサイトがある。登録済みURLを変えるために別作品として再登録すると、画像・メモ・最終アクセスを分断する。通常利用でも入力修正と誤登録の削除が必要になり、利用者は表示切替・タグなどより編集・削除を優先すると判断した。

基準main `699382b35c3c366a9fb81d9a8c96e38ef97d549e`に編集・作品削除はない。URL起動はWorkOpener、画像変更はCoverOperationsが別々に同作品の受付を制御している。DBと画像ファイルの削除は一つの原子的操作にできない。既存の画像機能を拡張済みとは扱わない。

## Decision Drivers

- 入口URLを変更しても同じ作品の情報を引き継ぐ
- 誤削除の対象を利用者が確認できる
- 元画像と他作品の参照を守る
- 初回にゴミ箱・Undo・履歴保存を持ち込まない
- 同作品の競合を防ぎ、別作品を不要に止めない

## Considered Options

### URLだけを編集する

変更は小さいが、タイトルなどの入力修正を別機能へ分けることになる。

### 登録時のテキスト4項目をまとめて編集する

URL・タイトル・サイト名・メモを一つの操作で修正できる。入力検証と既存データ保持、一覧への反映を検証する必要がある。画像と日時の手動編集は含めない。

### ゴミ箱へ移して復元できるようにする

誤削除に対応できるが、復元とURL重複、画像保持期間、通常一覧との区別が必要になる。

### 確認後に完全削除する

状態を単純にできる一方、確認後の誤削除は取り消せない。確認画面と元画像保持、管理画像整理の安全確認が必要になる。

## Decision

利用者が会話で承認した初回の範囲を次のとおり記録する。

- 編集はURL・タイトル・サイト名・メモ。同じ作品IDの情報修正として、画像・登録日時・最終アクセス日時を保持する。画像は既存の専用操作で扱う。
- 各作品の編集ボタンでダイアログを開き、保存/キャンセルで閉じる。保存を実行しなければ変更しない。
- 削除は作品名とURLを表示した確認画面を通す。確認後の完全削除とし、ゴミ箱・Undoを初回に設けない。
- 元画像は変更・削除しない。アプリ管理画像は、他の作品が参照していないことと実ファイルの安全性を確認できたものだけ整理する。確認不能なものを推測で削除しない。
- 同作品の画像操作・URL起動・編集・削除は処理を重ねず、先行操作の完了まで追加操作を拒否する。別作品は利用可能な範囲で継続する。全体の画像選択枠、起動時整理、共通参照排他、DB/画像停止など既存の制約は撤廃しない。

## Consequences

作品URLを手動で最新側の入口へ差し替えられるが、最新話の自動取得や読了管理にはならない。削除後の復元手段はない。管理画像の即時回収を保証せず、削除のために元画像や共有画像を消さない。

これは利用者向け方針の決定であり、API・SQL・受付部品・画面の非同期反映は未実装である。編集を先行し、削除は別Issueで実装する。[実装前の具体化事項](../work-edit-delete.md#実装前に具体化する契約)を満たすまで、実装IssueをDoR達成として扱わない。既存のADR-0013のVerifiedを、新しい作品削除の検証済み根拠として流用しない。

## Validation

### 編集保存の追加合意（Issue #209、2026-10-21）

利用者は、前後空白除去・URL/タイトル必須・他作品との重複URL拒否を登録時と同じ規則にし、変更なしでは更新日時も変えない方針を承認した。変更時だけ更新日時を記録し、既存値より戻さない。登録日時・最終アクセスは保持する。

保存のCommit結果が不明なら自動再試行せず、新たなDB操作を停止して再起動後の状態確認を案内する。入力拒否・URL重複ではDBを停止しない。画面は入力と案内を残し、結果不明を通常の成功/失敗と同一視しない。

検索文字を維持し、保存後に条件から外れた作品は一覧から外すが、成功通知は残す。保存中は連打とキャンセル・Esc・背景クリックで閉じることを防ぐ。編集を開いている間の入力は自動で差し替えず、保存時に4項目だけを更新し、キャンセルで破棄する。これらの画面動作はまだ未実装である。

Issue #209は[入力とSQLite更新の基盤](../verification/work-edit-storage.md)だけを先行実装する。Application・共通排他・API・UIは未接続であり、親#205の完了や本ADR全体のVerified化ではない。

### 共通受付と通常終了（Issue #211）

編集保存中のアプリ本体の通常終了も案内して拒否し、結果後に再度閉じる方針を追加承認した。結果不明でも処理終了後は通常終了できる。ダイアログに入力しているだけの時間は保存中としない。

#211ではApplicationの`WorkOperations`を同Appの正規API入口へ1個接続し、URL起動・画像設定/変更/解除の同作品の重なりを拒否する。AppのDB寿命ロック内で取得し、既存処理の完了・後処理・解放後に返却する。画像段階・参照排他・DBの実行権は別の責務として維持する。これは既存利用側に合わせた局所的な接続方式であり、直接生成したApplication部品の全インスタンスを跨ぐ排他ではない。

後続編集の`BeginEdit`と終了確定を同mutexで順序付け、編集が残る場合は既存の画像終了受付を変更せず拒否する。画像側が終了を拒否した場合も共通受付を閉じない。URL実行中のDB寿命保持は既存のAppロックで継続する。新しい編集API・UIと削除はまだ接続せず、[検証範囲](../verification/work-operation-admission.md)と区別してPendingを維持する。

Pending。設計文書と承認内容の通常・独立レビューを行う。実装後は入力拒否・重複・保持項目・再接続、同作品の相互排他・別作品継続、削除のDB/後処理失敗・共有/不明画像保持、古い一覧応答とダイアログ・実WebView2操作を一時DB/合成画像で確認する。今回、利用者データの編集・削除やGUI試験は行わない。
