# 作品の編集・削除（合意済み・未実装）

Issue #204。重要な判断は[ADR-0018](./adr/0018-edit-and-delete-works.md)。表示切替やタグより先に、編集、削除の順で小さく実装する。現在利用できる機能は[利用ガイド](./usage.md)を参照する。

## 合意済みの操作

| 操作 | 対象・結果 | 保持するもの |
| --- | --- | --- |
| 編集 | URL・タイトル・サイト名・メモをダイアログで変更し、保存またはキャンセル | 作品ID、画像、登録日時、最終アクセス |
| 削除 | 作品名・URLを確認後、作品を完全削除。ゴミ箱・Undoなし | 元画像。他作品の参照中画像、所有・安全性を確認できないファイル |

編集で画像や日時の手動変更は行わない。画像の設定・変更・解除は既存ボタンで扱う。作品削除と画像解除を混同しない。最新話URLの自動判定、履歴・バックアップ、タグや予定の追加は対象外である。

同作品の画像変更/解除・URL起動・編集保存・削除は、処理の受付から完了まで重ねない。後から来た要求は完了後の再操作を案内する。画面のボタン状態だけでなくバックエンドでも保証する。ダイアログを表示して考えている時間と、保存・削除を受け付けた後の処理は区別する。

別作品の受付は継続するが、既存の画像選択枠・DB停止・画像停止・参照排他などによる拒否や待機は残る。「別作品継続」は全I/Oの並列実行や全操作の成功保証ではない。

## 実装前に具体化する契約

以下は未決定の実装契約であり、承認済みの新しい方式として扱わない。実装Issueの着手前に既存コード・テストと照合し、要件や設計に大きな影響がある選択は追加承認する。

- 編集の正規化・必須項目・他作品とのURL重複、変更なし保存とupdatedAt、存在しないID。4項目だけを更新し、古いDTOで画像や最終アクセスを戻さない保存方法。
- URL起動と画像の現在別々の受付をつなぐ方法、操作の解放順序、DB/画像停止と通常終了との関係。画像だけの停止を、根拠なくテキスト編集までの全DB停止へ拡大しない。
- 削除のDB確定と管理画像後処理の順序、結果不明・確定後失敗・不存在の結果、参照排他と起動時整理の接続。作品行が消えたことだけで、対応ファイルを安全に削除できると判断しない。
- 編集ダイアログ表示中の別操作・古い応答、保存失敗時の入力保持、キャンセル・フォーカス復帰、削除確認対象の陳腐化、検索と古い一覧応答による巻戻し・削除作品の再出現を防ぐ方法。
- 正確なAPI入出力・エラー、Store操作と必要なスキーマ変更の有無。現在のメソッド名やDB形式を、未設計のまま確定しない。

## 分割と確認

[編集 #205](https://github.com/asam-masa/manga-update-manager/issues/205)では、保存契約と共通受付を先に具体化し、必要に応じ基盤/API/UIへ分割する。[削除 #206](https://github.com/asam-masa/manga-update-manager/issues/206)はこの設計と編集の基盤を踏まえ、安全な後処理と確認UIを別に検証する。作業状態と受け入れ条件はGitHub Issuesだけで管理する。

編集は全保持項目の非空データ、重複/不正入力と再接続、画像/URL/編集/削除の同作品競合・別作品、失敗・停止・終了を自動確認する。削除は一時SQLiteと合成PNGで、元画像・共有/未知ファイル保持、DB失敗/結果不明・後処理警告・次回整理を区別する。画面は遅延応答と検索、キーボード操作、実WebView2で確認する。未実装の削除を今回テストしたとは扱わない。
