## 合意済みの操作

| 操作 | 対象・結果 | 保持するもの |
| --- | --- | --- |
| 編集 | URL・タイトル・サイト名・メモをダイアログで変更し、保存またはキャンセル | 作品ID、画像、登録日時、最終アクセス |
| 削除 | 作品名・URLを確認後、作品を完全削除。ゴミ箱・Undoなし | 元画像。他作品の参照中画像、所有・安全性を確認できないファイル |

編集で画像や日時の手動変更は行わない。画像の設定・変更・解除は既存ボタンで扱う。作品削除と画像解除を混同しない。最新話URLの自動判定、履歴・バックアップ、タグや予定の追加は対象外である。

同作品の画像変更/解除・URL起動・編集保存・削除は、処理の受付から完了まで重ねない。後から来た要求は完了後の再操作を案内する。画面のボタン状態だけでなくバックエンドでも保証する。ダイアログを表示して考えている時間と、保存・削除を受け付けた後の処理は区別する。

別作品の受付は継続するが、既存の画像選択枠・DB停止・画像停止・参照排他などによる拒否や待機は残る。「別作品継続」は全I/Oの並列実行や全操作の成功保証ではない。

## 削除の追加合意（Issue #221）

以下は承認済みの設計であり、削除機能はまだ実装・検証していない。

| 状態 | 利用者への結果と後続処理 |
| --- | --- |
| DBの削除確定 | 一覧から作品を外す。その後、安全性を確認できた未参照の管理画像だけ整理する |
| 確定後の画像整理失敗 | 作品は削除済みとし、整理未完了の警告を表示する。作品を復元せず、削除を自動再送しない。残った管理画像は次回起動時にも既存の安全確認を通して整理する |
| DBの削除結果不明 | 削除成功とも未削除とも断定しない。自動再試行と画像整理を行わず、新たなDB操作を停止して再起動後の確認を案内する |
| 対象が既に不存在 | 今回の削除成功とは扱わず、不存在を案内して確認画面を閉じ、一覧から外す。この要求による画像整理は実行しない |

元画像・他作品の参照中画像・所有や安全性を確認できないファイルは保持する。次回整理も削除の成功保証ではない。削除確定後にDBや画像の安全な利用を継続できない場合は整理を開始せず、確定済みの削除結果と停止・整理未完了を区別して案内する。

確認画面には作品名とURLを表示する。削除直前に、確認時の編集4項目（URL・タイトル・サイト名・メモ）と画像を現在値と照合する。変わっていれば削除せず、最新の作品名・URLで確認し直す。最終アクセス日時だけの変化では再確認しない。確認と削除の間に変更が割り込まない保証方法、照合に使う画像情報、APIとSQLの正確な形式は後続の基盤・API Issueで具体化する。

確認中は背景の一覧・検索・別作品操作を止めるモーダルとし、開始済み処理は継続する。初期フォーカスはキャンセルへ置き、削除開始前はキャンセル・Escで変更せず閉じられる。処理中は連打・キャンセル・Escによる閉鎖を防ぎ、アプリ本体の通常終了も案内して拒否する。結果が出た後は結果不明でも閉じられる。閉鎖防止を処理時間の上限や実OSフリーズへの回復保証と混同しない。

#227でApplicationの削除手順と確定後の画像整理を先行接続する。画像だけの停止ではDBが正常なら削除を続け、画像整理を警告付きで見送る。参照排他はDB削除から画像後処理・資源解放まで保持する。合意済みの「後処理・資源解放まで通常終了を拒否し、結果後は閉じられる」方針をAppへ接続する作業は、Wails APIとともに親#223へ残す。[Applicationの契約と検証範囲](./verification/work-delete-application.md)を参照する。確認UIは#224であり、利用者向け削除はまだ未接続である。

## 分割と確認

[編集 #205](https://github.com/asam-masa/manga-update-manager/issues/205)は#209/#211/#213/#215で接続し、#219の終了案内検証を補って完了した。[削除 #206](https://github.com/asam-masa/manga-update-manager/issues/206)はこの設計と編集の基盤を踏まえ、安全な後処理と確認UIを別に検証する。作業状態と受け入れ条件はGitHub Issuesだけで管理する。

削除は次の単位へ分け、各Issueで詳細契約とDefinition of Readyを満たしてから実装する。これは分割方針であり、未確定のAPI・型・メソッドをDecisionとして固定するものではない。

1. SQLite基盤: 現在行の照合と条件付き削除、不存在・変更・確定・結果不明・解放失敗を区別する。管理画像ファイルは削除しない。一時SQLiteで保持対象と失敗を確認する。
2. Application・Wails APIと画像後処理: 共通受付・参照排他・停止・通常終了へ接続し、確定した場合だけ安全な管理画像整理へ進む。DB確定後の警告と結果不明を別結果として伝える。
3. 確認UI: モーダル、陳腐化の再確認、処理中の閉鎖防止、検索文字保持、古い一覧・操作応答による再出現防止、フォーカス復帰を確認する。実WebView2での操作確認も行う。

編集は全保持項目の非空データ、重複/不正入力と再接続、画像/URL/編集/削除の同作品競合・別作品、失敗・停止・終了を自動確認する。削除は一時SQLiteと合成PNGで、元画像・共有/未知ファイル保持、DB失敗/結果不明・後処理警告・次回整理を区別する。画面は遅延応答と検索、キーボード操作、実WebView2で確認する。未実装の削除を今回テストしたとは扱わない。
