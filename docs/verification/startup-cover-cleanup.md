# 起動時画像整理の接続

Issue #157。正本は[画像保存契約](../cover-persistence.md#起動時整理)と[ADR-0013](../adr/0013-define-cover-operation-boundaries.md)。

## 実装範囲

起動時に画像受付を整理の操作票で保護し、初回描画機会の後に画面から`LoadCoverWarnings`を呼ぶ。Wails v2.16.0のWindowsのOnDomReadyはnavigationCompletedのウィンドウ表示処理より前に非同期起動されるため、それだけを表示後の保証に使わない。React effect内の二回のrequestAnimationFrameで最初の描画機会を設ける。実OSの可視性・初回paintの観測とは区別する。

初期化を待つ通知、整理のsync.Once、Appの読取ロック、未開始/開始済み/終了前破棄の原子的な区別を使う。未開始なら通常終了でき、遅延した要求でも整理を開始しない。開始済みなら通常終了を拒否し、最終解放までDBと保存先排他を保持する。整理完了を自動終了予約へ変えない。

全管理記録と全ready候補の全参照確認を終えるまで削除しない。共通参照排他は最初の取得から最終解放まで保持する。reserved・参照中は削除せず、未参照候補だけ祖先保持の下で既存の照合削除・不存在確認・条件付き記録整理へ渡す。ファイル列挙はしない。失敗では残りを打ち切り、次回起動まで自動再試行しない。先に成功した削除を戻す機能ではない。

## 自動検証

- Applicationの実PNG・一時SQLiteで、通常回収、参照中保持、reserved保持と警告、不明参照・記録取得失敗・後半の参照取得失敗で削除なしを確認する。
- 欠損時の記録整理、内容改変拒否、削除後の記録整理失敗と再接続後の不存在再処理、最終解放失敗、段階前停止・キャンセルを確認する。作品全項目と未知ファイルは変更しない。
- Appで起動待ち、画像操作拒否、同時要求の合流、結果コピー、正常DB読取の継続、開始済み整理の終了拒否とshutdown待ち、遅延初期化拒否を確認する。
- 未開始の予約だけなら終了でき、遅延した画面要求が整理を始めないことを確認する。DB停止時の安全な警告と後続画像操作拒否も確認する。
- 画面で二回のフレーム後の呼出し、StrictModeの重複予約取消、閉じられる警告、取得失敗時の固定文言、アンマウント時の要求取消を確認する。

## 限界

合成エラーは実OS故障や電源断の再現ではない。参照確認は既存Store処理を候補ごとに実行するため、候補数と作品数に応じて遅くなる場合がある。全件を先に確認する分、メモリも記録数に比例する。画像設定/解除UIと配信、長時間整理中の実WebView2での終了拒否・解放失敗案内は残る。ADR-0013のPendingは維持する。

## 実exeの確認

2026-10-19、Go1.26.9・CGO無効・Wails v2.16.0のexeを、専用の一時APPDATA/TEMPで表示した。合成の未参照ready画像1件・reserved記録1件・未知ファイル・元画像だけを用意し、利用者の保存先へはアクセスしない。

UI Automationで警告ボタンを検出・押下し、そのボタンが消えること、通常の終了要求でプロセスが終了することを確認した。終了後のSQLiteとファイルの検査で、ready実体と記録の回収、reserved・未知ファイルの保持、元画像のバイト列不変を確認した。アプリ自身のPrintWindow画像も確認した。初回の画面全体キャプチャは別ウィンドウが写ったため証跡として採用せず、リポジトリ・PRへ追加していない。

これは自動操作による通常経路の観測であり、人による目視・キーボード操作、最初の描画と削除開始のOSレベルの厳密な時系列、長時間処理中の通常終了拒否、実故障の検証までは含めない。検証用の生成物・データ・スクリプトはGitへ追加しない。
