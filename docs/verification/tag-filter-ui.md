# タグ絞り込みUIの検証（Issue #351）

## 対象と環境

WindowsのWails v2.17.0 / WebView2で、build/bin内の専用合成DBを使う。通常の利用者データは使わない。45作品、マンガ23作品、連載中31作品、両タグ16作品、未使用・長い名前のタグを用意した。設計の正本は[タグ絞り込み](../tag-filter.md)とする。

## 確認済み

- ユーザーが半角「ﾏﾝｶﾞ」の候補検索、Tab/Spaceによるマンガの選択と23件、連載中の追加によるAND16件を確認した。
- Escで候補を閉じ、タグボタンへ戻る操作を確認した。
- 選択を保って小型・行一覧・カードを切り替え、16件が維持されることを確認した。
- 未使用1を追加して0件となり、「タグ条件をすべて解除」で45件に戻ることを確認した。
- 1024×768の候補表示をウィンドウ画像で確認した。候補内のスクロールと長いタグ名の折り返しを確認した。

上記は2026-11-01の確認用実行ファイル（SHA-256: `6A022CC23A8B96179E139F95650E3AEB9BF6982C09F0FCBC2E641FCE9DE2241D`）による確認である。

2026-11-02の修正版（SHA-256: `C1D8A2DE589AA3578D2E27596D3B453DC90B21869BB5222199F8F6F7042472B7`）で、ユーザーが次を確認した。

- 連載中だけで絞って2ページ目へ移り、タグ管理で連載中確認へ改名しても、選択名が変わり2ページ目を維持する。
- 選択中のタグを管理から削除すると、条件解除の通知が出て1ページ目・45作品へ戻る。
- ウィンドウを狭めても候補・長いタグ名が横にはみ出さず、スクロール・選択できる。
- 候補検索のIME変換中に外側クリックで閉じ、開き直して検索文字を消し「未使用」と入力すると、候補が正しく絞られる。
- マンガだけを選択して通常終了できる。親担当が同じ合成保存先・同じ実行ファイルで再起動し、選択タグなし・45件 / 全45件をUI Automationとウィンドウ画像で確認した。再起動確認後も通常終了した。

## 自動試験と限界

2026-11-02、登録完了が候補入力中のページを奪う問題を修正した。回帰試験は修正前にページ2への移動で失敗し、修正後にページ1・入力フォーカス・変換途中文字の維持を確認した。遅延応答は合成Promiseによるjsdom試験であり、実OSの遅延故障を注入したものではない。

続くユーザーの実機確認で、タグの名前変更を開始すると入力欄がすぐ消える問題が見つかった。確認用アプリには、同じ名前への改名成功が表示されていた。編集開始ボタンが保存ボタンへ再利用されることを回帰試験で確認し、表示時と編集時の操作欄を異なるkeyで分離した。この試験は修正前に失敗、修正後に成功した。jsdomでは実ブラウザーの暗黙送信そのものを再現できず、クリック元が送信ボタンへ変わらないことと開始時にAPIを呼ばないことを確認する。修正版の実WebView2でもUI Automationで名前変更を開始し、入力欄・保存・キャンセルが残ること、キャンセルで戻れることを確認した。改名・削除の完了と条件反映は上記のユーザー確認で成功した。

修正後のApp.tag-filterとタグ改名の関連30試験、フロントエンド全437試験、型検査・Viteビルド、Wailsビルドが成功した。

独立レビューでは、compositionEndが届かずに候補が閉じられる合成イベント列で、再オープン後も変換中フラグが残る点を確認した。実WebView2の上記の外側クリック操作では再現しなかった。すべてのIME・終了経路でイベントが必ず届く保証を確認したものではない。コードはこの未確認のイベント欠落を理由に変更せず、実操作と合成イベント列の結果を区別する。

Windows CIと通常・独立レビューの対象版・結果はPRへ記録する。合成データと確認したWindows環境での結果であり、全IME・全ウィンドウサイズ・実OSの故障を保証しない。タグ機能全体の照合は別に行い、ADR-0020はPendingを維持する。
