# バックアップZIPのストリーム書込み

Issue #397。`internal/backup.WriteArchive`はContext、出力Writer、目録JSON、読み取り元を開く関数を受け取り、[形式v1](../backup-format.md)のZIPを書き込む。製品API、通常保存先、SQLiteには接続しない。ADR-0022はPendingを維持する。

## 所有と成功の意味

出力前に上限付きの目録をコピー・検証し、固定名の目録・DB・含有画像だけをStoreで書き込む。読み取り元を開く関数へは検証済みのコンテナー名を渡す。処理側は正常に開いたReaderをCloseし、その失敗も返す。除外画像は開かない。

呼び出し側が出力Writerを所有する。nilはZIPの最終化成功だけを意味し、WriterのSync/Close、保存物の読み戻し、耐久保存、非上書き公開、復元可能性を保証しない。エラー時は出力が部分的またはZIPとして読み込める状態でも破棄する必要がある。その破棄やファイル操作を今回の関数では行わない。

## 検証と失敗

目録・個別/合計上限は既存DecodeManifestと共用する。本文は32KiBのバッファーと宣言サイズ+1で読み、実サイズとSHA-256を照合する。ZIP出力は最終化も含めて全体上限を超えないよう制限し、短い書込みも失敗にする。失敗は`errors.Is(err, ErrArchiveWrite)`で判別し、目録・読込・Close・書込・最終化・取消の下位原因も保持する。

Contextは読み取り元を開く前と読込/書込の境界で確認する協調キャンセルである。ブロック中の任意のopen/Read/Write/Closeを強制中断できる保証や、処理時間の上限は追加していない。キャンセル時も開いたReaderのCloseとZIPの終了処理を行い、未検証の出力を完成物として扱わない。

独立レビューで見つかった、最終化の最後の書込み中に成立した取消を成功扱いする問題は修正済み。書込みが復帰しZIPを最終化した後にもContextを確認する。最終flush内で取消して全量成功を返す合成Writerで修正前の失敗を再現し、修正後の取消エラーを確認した。

`go test ./internal/backup`で合成データの書込みとValidateArchiveによる往復、除外画像を開かないこと、出力前の目録拒否、サイズ/ハッシュ不一致、open/Read/Close失敗、本文書込・最終化失敗、短い書込、開始前/読込中の取消、出力上限の境界を確認する。2GiBの実ZIPや実ディスク容量不足の試験ではなく、上限は合成Writerの残容量と既存目録試験で検証する。

実データの同時点取得、実ファイルの保存/Sync/Close/公開、空き容量・電源断・起動排他、意味的検証と復元は後続である。
