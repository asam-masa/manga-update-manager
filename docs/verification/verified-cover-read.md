# 管理画像の上限付き読み取り

Issue #159。正本は[画像保存・配信契約](../cover-persistence.md#ファイルと配信の安全条件)と[ADR-0013](../adr/0013-define-cover-operation-boundaries.md)。本番HTTP配信には未接続である。

## 部品の契約

`platform.ReadVerifiedCover`は小文字16進32桁の管理IDと期待する`CoverFileInfo`だけを受け付ける。期待サイズが1バイト〜2 MiBの範囲外なら、パスを開く前に拒否する。既存の祖先保持・ローカル保存先検査を再利用し、読み取りでは`covers`を作成しない。既存の保存・削除のフォルダー作成動作は変えない。

共有なし・リンクを追跡しない同じファイルハンドルで、通常ファイル・単一hard link・128bit識別情報・ボリューム・サイズ・SHA-256を照合する。先頭へ戻って期待サイズ+1まで読み、返すバイト列の長さとハッシュを再照合する。途中キャンセルとI/O失敗ではデータを返さない。ファイル・フォルダーを順に解放し、解放失敗の印を保持してデータを破棄する。Closeを再試行しない。

## 自動確認

- `TestReadVerifiedCoverAndRelease`: 実生成PNGとの一致、結果バッファの独立、読み取り後の排他的削除と親フォルダーのリネーム成功。
- `TestReadVerifiedCoverRefusals`: 同一サイズ改変、同一内容の別ファイル、hard link、symlink、ディレクトリ、共有違反、識別情報・ボリューム・サイズ・ハッシュ不一致、キャンセル、不正/大文字ID、祖先リンク、不存在でデータを返さず、既存内容を保持する。
- `TestReadVerifiedCoverSizeAndMissingDirectory`: サイズ0・負・上限+1・int64最大を拒否し、未作成フォルダーを作らず、上限ちょうどは読み取る。
- `TestReadVerifiedCoverCancellationReleasesHandles`: ファイルが開かれた後のキャンセルでデータを返さず、ハンドルを解放する。

## 限界と後続

一時領域と合成データのWindowsテストであり、実OSのClose故障・電源断・全ドライブ種別は未検証である。Close失敗時のデータ破棄はdeferの静的確認と既存解放エラー分類テストで確認し、新関数への実Close失敗注入は行っていない。

この部品はPNGをデコードしない。管理記録が改変されて同じハッシュを持つ不正画像が渡される場合は、後続のPNG検査で拒否する。2 MiBは一読み取りの上限であり、同時リクエスト総量を制限するものではない。HTTP接続時には同時実行量、停止後の新段階受付、現在参照の解決から最終解放までの共通排他、終了待ち、応答ヘッダー、実WebView2での更新・欠損表示を検証する。ADR-0013はPendingを維持する。
