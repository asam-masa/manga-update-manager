# タグ管理の名前変更（Issue #329、親#315）

[画面契約](../tag-management.md#名前変更の画面接続issue-329親315)に従い、既存のRenameTagへ接続する。DB・公開API・生成型・依存関係を変更しない。タグ削除の画面は後続である。

## 自動検証

合成APIのDOM試験で、正確な確認ID/旧名と新名の送信、検索条件と使用数の保持、対象外/表示中それぞれの成功後フォーカス、他タグの編集禁止、二重送信・処理中の閉じる/Esc禁止、IME確定Enterの取消、未保存の破棄確認と入力復帰を確認する。

競合後の再取得と明示確認・再保存、再取得失敗/不存在でも入力を残す動作、同名の拒否、不正入力、再取得と保存の同時受付も扱う。確定結果・不正成功・結果不明・生の診断・確定後停止警告を区別し、親Appでも成功と警告を閉じた後まで保持する。古い別タグ名と返却新名が一致しても、確定済み成功を取り消さず一覧を未確認にする。

結果不明・接続故障等は合成APIであり、物理故障の再現ではない。既存の管理一覧・作品編集/削除・検索・ページ・3表示形式のDOM回帰も維持する。

## 実WebView2

2026-10-30、専用APPDATA/TEMPの合成23作品・24タグでproductionビルドを起動した。利用者が、編集中の検索/他タグ操作の無効化、Esc→「編集に戻る」の入力保持、「マンガ改名」への保存と23作品の件数、閉じた後の成功通知を確認し、「問題なかった」と報告した。

続けて作品「漫画2」の編集で選択済みタグが「マンガ改名」となること、行内キャンセルでは旧名が残ること、未使用タグを「未使用1改名」へ保存できること、Tab/Shift+Tabで入力・保存・キャンセルを操作でき通常終了できることを利用者が確認した。親担当はmode=roのSQLite照合で、タグID1と23作品の関連、タグID5の未使用状態、全23作品のIDの保持を確認した。

初回exe SHA-256は`1736B8E97C4248D717D2C53892B94DA0414B82B069761F38F33336D35E231227`、実装部分はindex tree `23defe33b0dd8ca1026facbb762278708d8b55b9`。通常レビューで「破棄確認中の再取得完了がフォーカスを戻す」ケースをDOMで再現したため、フォーカス初期化を確認画面の開始時だけに限定して回帰試験を追加した。

修正後exe SHA-256は`4E9B14E632C8843E511914EB72691F56AC1059AB773EDFE21CD7D30FE177E10F`。同じ合成保存先で再起動し、利用者が「マンガ改名・23作品」「未使用1改名・0作品」の保持、破棄確認の初期フォーカス・Tab移動・Escによる入力復帰を確認し、「問題なかった」と報告した。最後はキャンセルして通常終了し、親担当も対象プロセスの終了を確認した。

補助スクリプト・合成DB・exeはGit対象外のbuild/binへ保持し、通常の保存先は使っていない。DOMのshowModal/closeは合成実装であり、実描画やIME・フォーカスの実機確認を代替しない。再取得の遅延はDOMで制御したもので、実DBの故障や遅延を注入した確認ではない。

タグ削除・AND絞り込み・実OS故障・全倍率/解像度は今回の検証範囲に含めない。ADR-0020はPendingを維持する。
