# 確認対象の照合とSQLite作品削除

Issue #222、親#206。`manga.WorkDeleteInput`と`Store.DeleteWork`の保存基盤だけを追加する。削除API・画面・画像整理・操作全体の共通受付は未接続であり、利用者向け削除機能の完成ではない。スキーマ・保存形式・依存関係は変更しない。

## 契約

確認時のURL・タイトル・サイト名・メモ・画像参照先を文字列のまま保持し、入力を正規化しない。既存のStore実行受付を取得し、Tx内で現在行を読み、5項目が一致した場合だけIDと5項目を条件に作品行をDELETEする。日時は比較しない。最終アクセスだけの更新やA→B→Aで現在値が一致した場合は削除できる。Txが照合と削除を結び、他接続との競合で書込できない場合も無条件削除へ切り替えない。

画像の確認はDB上の参照先の比較であり、同じパスの実ファイルが外部で改変されていないことを保証しない。ファイルの所有・同一性・未参照確認は後続の画像整理が別に行う。Storeは画像ファイルや管理画像レコードを削除しない。返却された画像パスを削除許可として扱わない。

| 結果 | Storeの返却・継続 |
| --- | --- |
| 不存在 | `ErrWorkNotFound`、空の作品。正常解放なら継続 |
| 確認内容と不一致 | `ErrWorkDeleteChanged`、空の作品。DELETE/CommitせずRollback。正常解放なら継続 |
| 通常の削除拒否・0行削除 | 原因エラー、空の作品。Rollback成功なら継続 |
| Commitエラー | `ErrWorkDeleteOutcomeUnknown`と`ErrDBStopped`、空の作品。自動再試行・再接続なし |
| Rollback・接続返却確認不能 | `ErrDBStopped`と原因。確定前なら空の作品 |
| Commit成功後の返却失敗 | `ErrWorkDeleteCommitted`と停止エラー、削除確定時の作品。確定を不明へ戻さない |
| 通常成功 | 削除直前の作品。最終アクセスは現在行の値 |

`workDeleteOutcome`はTxと接続の解放後に結果を分類する。後続APIは確定済み結果を通常失敗に潰さず、停止状態で画像整理を開始しない必要がある。操作全体の共通受付、画像参照排他、通常終了判断は#223の責務であり、このStoreの直列化だけで代替しない。

## 検証範囲と限界

- 一時SQLite: 削除と再接続、再削除の不存在、他作品と共有する画像参照・管理画像記録の保持、確認後のアクセス日時更新、5項目それぞれの完全一致、不一致後の保持と継続、A→B→A、不存在、取消・停止、トリガーによるDELETE拒否と0行削除。
- 合成PNG: 一時フォルダーの管理画像と元画像に見立てた未知画像が削除前後で同じバイト列であること。管理画像情報は合成値であり、実ファイル検証を通した所有証明ではない。
- 合成driver: 実SQLite Commitを行ってからエラーを返し、実際は削除済みでも結果不明としてDBを停止する。Rollback後の合成エラーでも停止する。独立の再接続はテストでの結果観測であり、自動回復の実装ではない。
- 実SQLiteの読取ロックによるCommit競合: `SQLITE_BUSY`を結果不明として停止し、再起動相当の再接続後に作品が残ることを確認する。合成Commit済みエラーと両側の結果を分けて観測する。
- 確定後の返却失敗: 結果分類関数に共通受付が返す停止エラーと同じ形を渡し、確定済み作品を保持することを確認する。実接続のClose故障・OS障害の再現ではない。共通受付の返却エラー試験とは分ける。

全競合順序、実ファイル整理、物理Commit/Close障害、電源断、API・実WebView2、実利用者データの試験は未実施。実行したコマンドと版、通常・独立レビューはPRへ記録する。ADR-0018はPendingを維持する。
