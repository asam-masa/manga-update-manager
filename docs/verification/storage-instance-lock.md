# 保存先単位の起動排他の検証

## 対象

Issue #58で、Windowsの起動前に固定ロックファイルを共有なしで保持する処理を追加した。通常のDB・利用者画像には触れず、一時領域だけでテストした。判断の正本は[ADR-0014](../adr/0014-lock-storage-before-startup.md)である。

## 自動テスト

2026-10-11、Go 1.25.0・CGO無効で確認した。

- 同じ保存先の再取得・大文字表記・正規化後の同じパス・ディレクトリsymlinkの別名を拒否し、別保存先を許可する
- 既存ロックファイルの内容を変更せず、保持中の削除・名前変更を拒否し、解放後は同じファイルで再取得できる
- 相対パス・欠落先・ディレクトリ型のロック・hard link・symlinkを拒否し、外部ファイルを変更しない
- 同時8件の取得で一件だけ成功する
- 別プロセスの同じ保存先を拒否し、別保存先は同時に使える
- 子プロセスの正常終了・強制終了後に親が再取得できる
- 保存先や排他の失敗ではデスクトップを呼ばず、DBを作らない
- DBを閉じてから排他を解放し、Wails実行のエラー・panic時にも後片付けする
- 終了後まで遅延した起動コールバックは、ロック解放後にDBを作らない。開始済み初期化には終了処理が待つ

初回sandboxではhard link作成がアクセス拒否となった。承認済みの通常権限で再実行し、hard link・symlinkを含む全項目が成功した。権限不足時のskipをリンク拒否成功として扱わない。

## 実exeでの確認

2026-10-11、Go 1.25.0・CGO無効のWindows production exeで、通常のAPPDATAを使わず専用APPDATA・TEMPを設定した。UI Automationで次の6観測がすべて成功した。初回は非表示起動のため画面を観測できず、表示の承認後に再確認した。人による目視・キーボード操作の結果ではない。

1. 一つ目の通常画面を観測し、専用DBが作られる
2. 同じAPPDATAの二つ目が起動中の案内を出し、OK後に終了コード1で終了する
3. 別APPDATAでは同時に通常画面を開く
4. 通常画面を閉じて終了コード0で終了し、再起動できる
5. 今回起動した検証用プロセスだけを強制終了し、再起動できる
6. ロックファイル名にディレクトリを用意した取得不能の保存先で、安全な起動失敗の案内を出し、OK後に終了コード1で終了し、DBを作らない

一時確認スクリプトと保存先はGit対象外の`build/bin`に置いた。起動したプロセスのハンドルだけを保持して後片付けし、成果物は削除していない。通常の保存先と利用者データは使用していない。画面全体のレイアウト、アクセシビリティ、ウィンドウ前面化は検証していない。

全Goテスト・vet、既存画面44テスト、TypeScript/Viteビルド、Renovate設定3テスト、Wails v2.14.0のWindowsビルドが成功した。初回の既存画面テストはsandboxのrealpathアクセス拒否で実行できず、承認済みの通常権限で再実行した。

2026-10-12、独立レビューで指摘された終了後の遅延初期化を修正した。全Goテスト・vet、Windows再ビルド、修正後exeの上記6観測が成功した。遅延初期化の再現テストと開始済み初期化の終了待ちテストも成功した。

## 制約

既存の旧版は排他へ参加しないため、更新時は旧版を終了する。ネットワーク保存先、複数Windowsセッション、祖先パスの外部変更、全種類のreparse pointやファイルシステムでは未実測。今回の排他は画像保存・削除・復旧全体の安全性を証明しない。
