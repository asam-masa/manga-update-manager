# 選択完了通知の検証

Issue #167。正本は[通知契約](../cover-persistence.md#選択完了通知)。既存の選択APIを残し、操作ID付きAPIと選択枠解放後の通知だけを追加する。画面のボタン・イベント購読は追加しない。

## 自動テスト

- `TestSelectionDoneReleasesOnlyChooser`: 通知時に同作品の追加操作は拒否し、別作品の選択枠は取得できること。選択後の読取失敗でも通知は一度だけであること。
- `TestSelectionDoneNotificationBoundaries`: 選択取消・選択エラーでは一度だけ通知し、作品不在と選択枠競合の事前拒否では通知しないこと。
- `TestSelectionDoneCallbacksBelongToRequests`: 一件目の選択後の読取を停止している間、別作品の選択取消が自分のコールバックを呼び、混線しないこと。チャネルで順序を固定し、sleepには依存しない。
- `TestSelectWorkCoverOperationNotification`: 小文字16進32文字以外を選択前に拒否し、連続要求がそれぞれ指定した作品ID・操作IDを返すこと。取消結果と通知なしの旧APIを維持すること。

一時SQLiteと選択・通知の差し替えで確認する。既存の取り込み・解除・停止・最終解放の回帰はGo全体のテストで確認する。Wailsバインディングは採用CLI v2.16.0で再生成する。

## 限界

実OS選択画面からWailsイベントが画面へ到着すること、イベントの遅延・重複・順序逆転に対する画面動作は未検証。画面への接続時に、Promise完了だけでも選択中状態が解除されることと合わせて確認する。元画像のパスは追加APIの入力・イベントの構造に含めない。イベントは確定結果や取消権限ではない。ADR-0013はPendingを維持する。
