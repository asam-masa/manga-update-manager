# 画像処理の段階通知

Issue #184、親#183。正本は[長時間処理の案内](../cover-persistence.md#長時間処理の案内)。要求ごとの任意コールバックに固定の段階コードだけを渡す先行部品であり、Wails API・イベント・画面・タイマーは追加しない。

## 自動テスト

- `TestCoverProgressSelectRemoveAndCleanup`: 一時SQLiteと実PNGで変更・解除・未参照画像の起動時整理を実行し、通知順序、選択完了後の生成、実I/O直前の通知、解放前の通知を確認する。正常な変更・解除の結果と管理記録の整理も確認する。
- `TestCoverProgressFailureAndCancellation`: 選択取消、選択失敗、元画像の読取・解放失敗、選択後の画像機能停止、DB確定後の保持フォルダー解放失敗を分離する。未開始段階を通知しないこと、確定後の成功と警告を維持することを確認する。
- `TestCoverProgressRejectedStagesDoNotNotify`: 停止済み・contextキャンセル済みの段階では実処理も通知も行わないことを確認する。
- `TestCoverProgressCallbacksBelongToConcurrentRequests`: 一件目の元画像読取をチャネルで止め、別作品の解除を進める。要求ごとに通知が分離され、未完了操作が別操作の段階を受け取らないことを確認する。sleepには依存しない。

既存の通知なしの取り込み・解除・整理・停止・競合・解放テストも回帰確認に使う。合成のClose失敗は実OS Close故障の再現ではない。

## 限界

コールバックは信頼された内部の観測専用である。重い処理・panic・I/O・再入をする任意の第三者プラグインを保護する仕組みではない。段階開始通知は成功や動作継続を保証せず、最後の通知だけでフリーズを診断しない。

このIssueではWailsと画面への接続や実WebView2の長時間表示は未検証である。10秒の計測、選択待ちの除外、通知欠落・順序逆転・操作ID照合、検索非表示中の案内、完了時の表示遷移は親#183で検証する。終了制御やADR-0013全体のVerified化も完了していない。

後続#186で、段階通知をメモリへ記録してWailsから取得する接続を追加した。[状態取得APIの契約と検証](./cover-progress-api.md)を参照する。画面の定期取得と10秒表示は引き続き未接続であり、本Issue当時の未検証範囲と区別する。
