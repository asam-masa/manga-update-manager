# バックアップ目録v1の検証範囲

Issue #390。[形式契約](../backup-format.md)の目録部分を`internal/backup`へ実装した。ADR-0022のValidation StatusはPendingを維持する。

`DecodeManifest(io.Reader)`は入力を8MiB+1バイトまで読み、目録モデルを返す。形式不正は`ErrManifest`、読み取り失敗は元のエラーを返し、いずれも部分的なモデルを返さない。ReaderのCloseは呼び出し側が担当する。

確認した項目は次のとおり。

- 未知・重複・欠落キー、不正型、後続JSON、巨大整数、無効なUTF-8を拒否する。整数は小数や指数表記から丸めない。
- 作成日時はUTCのRFC 3339（`Z`または`+00:00`）と暦の妥当性を確認する。
- DBの固定パス、画像IDとパスの一致、小文字のハッシュ、画像と除外記録をまたぐID重複、除外理由を検証する。
- DB256MiB、画像1個20MiB、画像と除外記録の合計1万件、目録8MiB、展開後合計2GiBについて等値を許可し、1単位超過を拒否する。合計には入力した目録の実バイト数を含める。
- 既知の移行001〜009の連続した先頭部分だけを目録上の履歴として認識する。これは旧DBの復元対応を保証する許可リストではない。

`go test ./internal/backup`で正常系、空配列、各拒否条件、読み取り失敗を確認する。深すぎる入れ子や過大な配列も、目録のサイズ上限に加えて解析中に制限する。

この関数はZIPの検査、実ファイルのサイズ・CRC・ハッシュとの一致、DBの実構造・データ・参照整合、旧版の移行、画像内容、通常保存先の切替を実行しない。ハッシュ文字列の形式が正しくても、内容の真正性を示さない。ZIPの限定読込と実バイトの照合は[Issue #391の検証範囲](./backup-archive.md)を参照する。
