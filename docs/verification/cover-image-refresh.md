# 画像変更後の再取得と実WebView2表示

2026-10-19、Issue #172で切り分け、Issue #174で再取得用の目印を追加した。親は#42、判断の正本は[ADR-0013](../adr/0013-define-cover-operation-boundaries.md)。

## 修正前の観測

利用者が実画面でも旧画像の残留を確認した。PrintWindow撮影だけの問題とは扱わない。画像変更UIだけを操作し、別のHTTP取得を省いた検証では、作品1への要求数が変更前後とも2件だった。別HTTP取得では現在画像を返した。Reactのkeyによる作り直しだけでは、同じURLの画像の再取得を保証できていなかった。

## 修正と自動確認

画像要素の作成時に16バイトの乱数を小文字16進32文字へ変換し、`/__covers/works/<ID>?v=<目印>`を使う。画像変更・一覧再読み込みでは新しい目印、通常の再描画では同じ目印となる。配信側はクエリなし、またはこの生の形式だけを許可する。目印で画像の版を選ばず、作品IDの現在画像を解決する。

UIテストでURLの形式・変更・通常再描画時の保持を確認する。HTTPテストで両Wailsハンドラー、no-store/nosniff、未設定・欠損・破損・解除、未知・重複・エンコード・長さ・大文字・非16進の拒否、同じ目印でも現在画像を返すことを確認する。

## 実機確認

Windows、Go 1.26.9、CGO_ENABLED=0、Wails v2.16.0開発モードを使用した。子プロセスのAPPDATA/TEMP/TMPを分離し、合成3作品と合成PNGだけを使用した。確認専用領域は`D:\appdata_local_tmp\mum-dev-cover-a5d100a3f1fd4985a0031b727f0adaac`。利用者のDB・画像は変更していない。

強制前面化なしのUI Automationで作品1を青色48×48からグラデーション120×60へ変更し、HTTPの寸法・中央RGBと所有ウィンドウのPrintWindow撮影が両方切り替わった。続いて青色48×48へ戻し、HTTP・撮影が再び切り替わった。最後の青色表示は利用者が実画面でも確認した。撮影画像、実行補助、DB、ログはGitへ追加しない。

一覧再読み込み後の青色表示と通常終了も確認した。続いてビルド済みproduction exeを同じ確認専用保存先で起動した。非表示起動ではウィンドウを取得できなかったため、当該PIDの所有ウィンドウだけを表示し、強制前面化は行わなかった。青色→グラデーション→青色の両方向で、設定成功と所有ウィンドウの撮影切替を確認し、通常終了した。production exeで利用者の直接確認と別HTTP取得は行っていない。

Goテスト全体、go vet、UIテスト63件、フロントエンドビルド、Wails v2.16.0のWindows productionビルドは成功した。

## 限界

利用者の直接確認は開発モードの最終青色表示である。HMR・自動バックエンド再ビルド、全競合、長時間処理、実I/O故障は対象外である。フォーカスエラー#171を解決したとは扱わず、ADR-0013全体のPendingを維持する。
