# 起動時整理向けの管理記録一覧

Issue #152の先行実装。正本は[画像保存契約](../cover-persistence.md#起動時整理)と[ADR-0013](../adr/0013-define-cover-operation-boundaries.md)。

## 契約

`Store.ListManagedCovers(ctx)`は、管理記録をID昇順に全件返す。reservedとready、作品から参照中の記録も含む。保存ID・生成相対パス・状態・NULL・識別情報はID取得と同じ検証関数を使う。空なら非nilの空配列、失敗ならnilとエラーを返す。途中の不正記録やRowsの自動Close失敗で、読み終えた分を候補として返さない。Rowsを閉じ、共通制御の接続返却を終え、その結果にエラーがあれば一覧を消して返す。

取得は記録・作品・ファイルを変更しない。実ファイルを走査して記録へ追加せず、DBの不正値も自動修復しない。情報が正しく保存されていることと、未参照・実体の所有・安全な削除を確認したことは別である。一覧取得だけでは全参照を確認しておらず、呼び出し側の共通排他も代替しない。

## 自動検証

- 一時SQLiteで空一覧、逆順登録からのID順取得、reservedとready、最大uint64のvolume serial・128bit ID・ハッシュ、参照中記録を確認する。
- ID取得との一致、再接続後の一覧保持、作品・合成の未知ファイルの不変を確認する。
- 正常記録に続く不正状態・ID・不完全なready・不正な確認情報を拒否し、部分一覧を返さず、DBを自動修復しないことを確認する。
- キャンセル・クエリ拒否・Store終了後・停止済みの拒否を確認する。通常の不正記録やクエリ拒否だけではStoreを停止しない。
- 0件/1件を読み終えた際の合成Rows解放失敗で、nil一覧と`ErrDBStopped`を返し、以後のDB操作を拒否することを確認する。

## 限界と後続

このPRは起動処理、全参照確認、削除、警告API/UIへ未接続である。接続返却後のエラーによる一覧破棄はコード上で確認し、共通返却部品の既存テストと合わせる。実OS故障、電源断、起動中の実WebView2の操作は未確認である。ウィンドウ表示後の整理・処理中の終了拒否・最終解放・安全な警告保持を結合検証してから本番へ接続する。ADR全体のPendingは維持する。
