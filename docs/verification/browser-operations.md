# 代表操作のブラウザー検証

## 範囲と実行

Issue [#361](https://github.com/asam-masa/manga-update-manager/issues/361)で、実React画面をheadless Chromiumで操作する5件を追加した。[operations.spec.ts](../../frontend/e2e/operations.spec.ts)と[合成境界](../../frontend/e2e/fixture.ts)を使い、利用者DB・画像・外部サイトへアクセスしない。合成45作品と5タグはテストごとに初期化する。

```powershell
npm --prefix frontend run test:browser -- --grep operations --repeat-each=3
npm --prefix frontend run test:browser -- --repeat-each=3
```

全体はスモーク2件・画像比較6件・代表操作5件の計13件で、CIでは各3回の39件を実行する。画像の基準環境と更新方法は[画像比較の手順](./browser-visual-comparison.md)に従う。ローカルWindowsとCIのフォント差があるため、ローカルの`--ignore-snapshots`による13件成功は操作・配置の検証であり、画像比較成功とは扱わない。

## シナリオと期待結果

| 操作 | 観測する期待結果 |
| --- | --- |
| 検索・ANDタグ・表示切替 | `ﾏﾝｶﾞ`で漫画名・タグを検索できる。タグ選択で23件→AND条件で16件となり、3形式でも条件を保持する。未使用タグを加えると0件となり、全解除で45件へ戻る |
| ページと自然順 | 下側の次へをEnterで操作すると上側の現在ページへフォーカスが移る。検索変更で1ページ目へ戻る。登録の新しい順で先頭が作品45になり、タイトル順へ切り替えるとマンガ物語へ変わって作品2が作品10より先になる |
| タグ改名 | 入力・保存をTab／Shift+Tabで移動できる。Escの破棄確認から戻ると入力を保持する。Enter保存後も選択タグの固定IDと2ページ目を保ち、閉じても成功通知を表示する |
| タグ削除 | 対象23作品を表示し、Escでは削除しない。確定するとタグだけを削除し、45作品を残して条件解除・通知・1ページ目への移動を行う |
| 再取得失敗 | 合成APIが失敗すると前回の23作品とタグ条件を残し、エラーを表示して候補選択と全解除を無効にする |

タグ選択はTab・Space、候補のEscは開いたボタンへのフォーカス復帰も検証する。改名・削除の合成APIは確認時の名前や削除対象を照合するが、Goの競合制御を再実装したものではない。既存VitestとGo試験の役割は残す。

## 結果と失敗の調査

2026-11-03のローカルでは5件を3回ずつ、15件成功した。別途、画像比較を明示的に省いた全13件の操作・配置検証も成功した。CodexはAND候補と改名入力の撮影を開いて確認した。Windows CIの比較を含む結果はPRのResultへ記録する。

Escの伝播をテスト内で一時的に止める故障注入では、候補を閉じた後のフォーカス検証が失敗し、終了コード1・失敗画像・トレースを確認した。一時コードを除去すると成功した。失敗するコードはコミットしていない。

独立レビューで、元の自然順テストは登録順でも作品2が作品10より先に並ぶため、切替が無反応でも成功する点を指摘された。登録の新しい順で作品45を先頭にしてからタイトル順へ戻す検査を追加した。変更イベントの伝播を一時的に止めると、先頭が作品45になる検証で失敗した。一時コード除去後の5件×3回は成功した。

CIの`Browser checks`は`continue-on-error`を使わず、試験の非0終了をジョブへ伝える。`if: always()`の証跡アップロードは失敗を成功へ変えない。artifact `browser-checks`にHTMLレポート・失敗画像・差分・トレース・環境情報・基準画像を7日間保持する。成功時のAND候補・改名入力の撮影もHTMLレポートに添付する。操作の失敗には必ずしも画像差分はなく、画像比較の失敗に実撮影と差分が付く。

ワークフローが失敗することと、GitHubがマージを拒否することは別である。後者は[保護ルールへの追加案](../develop/workflow/browser-required-checks.md)の承認・適用・再取得確認まで未完了とする。

## 手動確認との対応

| 自動化済みの範囲 | 引き続き別に確認する境界と理由 |
| --- | --- |
| 3形式の代表配置・画像、上記検索・タグ・ページ・管理操作とフォーカス | 新デザインの初回合意は利用者が見て判断する |
| ChromiumでのTab・Space・Enter・Escと文字列入力 | 実WebView2の描画・Windows IME変換・OSフォーカスはブラウザーの文字列入力だけでは再現しない |
| 合成タグAPIの成功・再取得失敗と画面反映 | 実Wails・Go・SQLiteの保存・再起動復元・競合・終了制御はこの試験に接続されていない |
| 合成SVG・意図した404の表示 | ネイティブのファイル選択・実画像の取り込み・安全な配信は合成HTTP応答では保証しない |

通常の変更で自動化済み項目を利用者へ毎回再確認しない。対象版での試験成功とCodexの撮影確認を記録する。表の未自動化境界に影響する場合は対象と理由を添えて実機確認する。[実Wails接続Spike #362](https://github.com/asam-masa/manga-update-manager/issues/362)は別作業である。
