# 製品バックアップ画面の実Wails結合確認

Issue #614。2026-11-20、製品React画面から標準保存ダイアログ・実保存・除外詳細までを合成データで確認した。復元や全異常系の実機検証ではない。

## 対象と分離

- 対象はPR #613マージコミット`e5fb61e58bfb2fe2d7819291ae9668a0f1493546`。Windows 10.0.26300、Go 1.26.5、Wails v2.17.1、go-webview2 v1.0.22を使用した。
- `npm --prefix frontend run build`後、`go build -tags desktop,production -overlay build/bin/614-overlay.json -o build/bin/614-backup-product.exe .`で確認用exeを生成した。SHA-256は`800EEA31D65EA12DCDA885D1F3CF3CC86AFA019E65B2EC42BA52041242D3EB44`。
- overlayは一時的な起動用mainだけを置き換える。製品React資源、Appの公開API、画像配信、保存先選択、保存処理、終了判定は実装をそのまま使った。保存先選択を返す試験用関数や別HTMLへの差し替えは行っていない。
- `build/bin/614-fixture-*`の新規領域へ、DB・covers・元PNG・保存ZIP・WebView2用APPDATAを分離した。専用マーカーを確認してから初期化し、合成3作品（正常画像確認・欠損画像確認・画像未設定確認）を登録した。画像は自作PNGから通常の画像取込処理で管理登録し、欠損用だけ今回作成した管理ファイルを除去した。
- 一時ハーネス、DB、画像、ログ、ZIP、撮影画像はGitへ追加しない。通常データ、外部サイト、OS/ACL設定は変更していない。開始後の観測補助は状況・結果・場所の読取APIだけを呼ぶ。保存先選択は製品画面から開き、選択の取消は標準ダイアログで行った。処理開始後の取消APIは今回呼んでいない。

## 確認結果

操作はCodexのUI Automationと、所有する確認用ウィンドウの前面状態を確認したEnterキーで行った。ネイティブ保存ダイアログの欄入力とボタンはUI Automationで操作した。WebView2内のボタンではInvokePatternを取得できなかったため、直接実行できたとは扱わない。利用者への追加手動操作は依頼していない。

| 確認 | 観測結果 |
| --- | --- |
| 初期表示 | 製品一覧に3作品、正常画像は横長の緑系グラデーション、欠損画像は仮表示。撮影画像をCodexが確認した |
| 保存先選択 | タイトルは「バックアップの保存先（既存ファイルには保存できません）」。ファイル名が日時付き`manga-update-manager-YYYYMMDD-HHMMSS.zip`であることを検査した |

| 実保存 | 専用領域の新規saved.zipへ保存。実行ID1はfinished / confirmed / saved_with_warnings。除外画像1件、作品名詳細available、対象作品1件。保存先と確認済み完成名は選んだ専用パスだった |
| 除外詳細 | 製品画面の画像一覧に「欠損」、対象作品一覧に「欠損画像確認」が表示された。実WebView2の作品一覧を撮影してCodexが確認した |

| 結果保持と終了 | 再度保存先を開いて取消してもcollisionの案内が残った。製品ダイアログを閉じると「バックアップ」入口へフォーカスが戻った。その後の本体終了要求でプロセスが終了し、OnShutdown完了の記録を確認した |

## 保存内容の照合

既存の`backup.ValidateArchive`で63,149 bytesのZIPを検証した。目録はformatVersion 1、DBコピー61,440 bytes、正常PNG1枚480 bytes、missingの除外画像1件だった。格納PNGはデコードに成功した。

検証済みZIPから専用領域の新しいファイルへDBだけを抽出し、`storage.ValidateDatabaseCopy`（integrity_checkとforeign_key_check）が成功した。読み取り専用SQLで作品3件を確認した。これはZIPとDBコピーの限定的な検証であり、復元・移行・全ドメイン規則の検証ではない。

## 残る範囲

短時間・画像2件の合成データである。長時間処理の実取消、取消と公開の競合、資源解放未確認、実OS故障、電源断、多数詳細の実WebView2ページ送り、画面だけの再読込は今回追加実測していない。ページ境界と失敗回復は[合成APIのPlaywright検証](./backup-app.md)、API画面での再読込・選択中の終了要求は[#590/#591の記録](./backup-wails-api.md)と区別する。

製品画面から実保存と除外詳細まで通ったことを、全異常系の成功や復元の完成とは扱わない。ADR-0022のValidation StatusはPendingを維持する。
