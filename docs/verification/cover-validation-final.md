# ADR-0013の検証完了判定

Issue #199、親#42。2026-10-21、[ADR-0013](../adr/0013-define-cover-operation-boundaries.md)で承認済みの四項目を最終照合した。新しい必須条件の除外や仕様変更は行わない。

## 対象と結論

基準mainは`0f38ab7ea6b7af0096968749d9938d5c429c988a`（PR #198）。#191の[初回照合](./cover-validation-audit.md)と、#192・#193・#194の後続結果を合わせ、下表の範囲で必須検証を完了したと判断する。ADR-0013をVerifiedへ変更する。通常・独立レビューと最終の自動検証結果は#199のPRに記録する。

本PRは文書だけを変更する。既存記録の実画面試験を今回再実行したとは扱わず、各記録の対象版・方法・限界を引き継ぐ。#192以降の変更は追加テストと文書で、本番コードの変更はない。過去の試作だけで本番の成立を判断していない。

## 四項目と根拠

| 必須項目 | 根拠と判断 | 検証方法の限界 |
| --- | --- | --- |
| 停止・DB結果不明の案内と保全 | [#180/#181](./cover-stop-ui.md)の実SQLite Commit競合、画像のみの停止、確定後警告。API・画面テストと実Wails経路で、結果不明の専用案内、新旧保持、自動再試行・書戻しなし、DB停止と画像停止の区別を確認 | 解放失敗・確定後警告は合成注入を含む。停止画面は開発モードの制御付きビルド。未改変productionでは通常エラーの輸送を確認したもので、実OS Close故障の試験ではない |
| 長時間案内 | [#183](./cover-progress-ui.md)の自動テストと実WebView2。10秒境界・選択待ち除外・検索非表示でも継続・完了後消去・観測失敗を確認 | 実画面は代表待機を制御。全順序は自動テストと分担。最後の観測値であり、フリーズ診断・正常継続や残り時間の保証ではない |
| 処理中の終了拒否と結果後の通常終了 | [#189](./cover-close.md)で変更・解除・整理の全段階の依存境界と参照待ちを自動確認。代表的な実画面待機で終了拒否・案内・処理継続・結果後の再要求終了を確認。表示読取の終了待ちは別契約 | 全段階を実画面で再現したものではない。OS強制終了を防がず、処理が必ず終わる保証や強制中断・終了予約を追加しない |
| 保存・削除・復旧 | [#191の対応表](./cover-validation-audit.md)の正常系、Close/DB/削除失敗、参照確認、競合、起動排他、限定配信に、下記三件の不足を補った。開発/productionの表示・キャッシュ・欠損は既存の[再取得](./cover-image-refresh.md)・[表示](./display-current-cover.md)・操作記録と対応 | 実SQLite・実ファイル、境界注入、実子プロセス、実WebView2は役割が異なる。件数やCI成功だけで未確認条件を埋めない |

## 初回照合で不足した三件

| 初回の不足 | 後続の確認と判断 | 残る限界 |
| --- | --- | --- |
| 生成・保存失敗から取り込み全体の保全 | [#192](./cover-failure-preservation.md)の8ケースで生成拒否、通常書込・ENOSPC相当・同期失敗と解放失敗併発を確認。旧作品全項目・画像・参照・元画像・ready記録を保持し、未確認出力とreservedを次回整理でも保持 | 実OS書込/Sync故障ではなく、Application境界と書込部品の注入を分ける。実ディスク満杯の再現ではない |
| 処理途中終了と次回整理 | [#193](./cover-interrupted-recovery.md)でreserved・部分出力・ready確定・参照確定・旧ファイル削除後の5地点で自身の子を終了。再接続・ロック再取得・本番整理・現在参照・元画像・未知ファイル保持を確認 | 同期した処理境界の終了。partialはwrite境界の置換。電源断・OS書込内部やCommit内部の全位置ではない |
| 破損管理画像の実画面 | [#194](./corrupt-cover-webview.md)で開発/productionの対象だけの仮表示・案内と正常カード分離を確認。両テーブル全列比較で参照・日時・管理記録を保持。同じ実体の内容復元後、明示再読み込みで回復 | 先頭バイト反転による期待ハッシュ不一致。全PNG破損位置ではない。復元は検証補助で、自動修復ではない。利用者の直接目視・実キー追試ではない |

## 未修正の既知制約と再評価

#176は未修正で継続する。[再現条件](./webview-focus-exit.md)は選択ダイアログ中の無効な親への特殊な強制前面化である。#178で、この修正自体を本ADRの完了必須条件としない判断が承認済みである。今回その除外範囲を広げない。通常操作で再現した場合、または保全・通常操作を阻害する新たな根拠が出た場合は、必須条件へ戻して完了判定を再評価する。

同じユーザー権限の悪意ある別プロセスとの完全防御、全ファイルシステム・全競合・電源断・実OS故障の保証は行わない。一方、通常の保存失敗や途中終了の根拠不足をこの制約へ付け替えていない。確認できないreservedや出力を残すのは保全契約であり、全不要ファイルを必ず自動回収する保証ではない。

Verifiedはこの文書と既存記録の条件での検証完了であり、無故障・データ無損失・再起動成功の保証ではない。本PRでは本番動作・依存・DB形式・#176を変更せず、親#42の状態も自動変更しない。
