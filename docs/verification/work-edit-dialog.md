# 作品編集ダイアログ

Issue #215、親#205。正本は[ADR-0018](../adr/0018-edit-and-delete-works.md)と[API契約](../work-api.md#編集apiissue-213)。

## 契約と自動検証

一覧の編集ボタンから4項目のモーダルを開く。背景操作は止めるが、開始済み処理は取り消さない。標準`dialog.showModal()`を使用し、フォーカスの封じ込めと背景の非活性化をブラウザーへ任せる。新しい依存ライブラリは追加しない。背景クリックでは閉じず、入力中はキャンセル/Esc、保存中はどちらも拒否する。[HTML標準](https://html.spec.whatwg.org/multipage/interactive-elements.html#the-dialog-element)を参照する。

- 開いた入力はその時点の4項目だけを保持し、背景の一覧応答で自動差替えしない。IME確定Enterを送信にしない。キャンセルでは保存せず、次回は保存済み値から開く。
- 保存中はrefでも二重要求と閉鎖を防ぐ。失敗時に入力を保持する。結果不明・DB停止・伝達不能・不正成功応答では追加保存を止め、入力を控えて再起動確認する案内を出す。処理終了後は閉じられる。確定後警告では成功を維持し、警告は一覧外の通知へ残す。
- 検索文字を維持する。保存で条件外になった作品は消すが、成功通知はカード外に残す。閉鎖後は元の編集ボタン、消失・無効なら検索欄へフォーカスを戻す。
- 一覧取得開始時の編集revisionと保存済み4項目を保持し、古い応答へ重ねる。画像・アクセス応答はそれぞれの所有項目だけを更新する。更新日時は戻さない。同作品のURL/画像/編集ボタンは処理中に無効化し、refで同tickの追加要求も防ぐ。バックエンドの共通受付を置き換えない。

`App.edit.test.tsx`はStrictMode、合成DTOと遅延Promiseで上記を確認する。jsdomには`showModal/close`のテスト用最小代替を用意するが、背景inert・実Tab移動の検証ではない。既存画像テストの、同作品URL/画像を重ねる古い前提を更新した。実行結果と対象版はPRへ記録する。

## 実画面の確認

2026-10-22、Wails v2.16.0の確認用productionビルドを専用APPDATA/TEMPと合成3作品・画像で起動した。UI Automationで編集を開き、背景の一覧が操作要素から除かれること、タイトル変更の保存と成功通知、再度開いた保存値、未保存変更のキャンセルと破棄を確認した。スクリーンショットでダイアログと背景の表示を確認した。普段の保存先・exe・元画像は使っていない。

同じ確認用アプリで、検索文字を保持してタイトルを条件外へ変更し、作品が非表示になっても成功通知が残ることをUI Automationで確認した。利用者もTab/Shift+Tabがダイアログ内を移動すること、Escで閉じて元の編集ボタンへ戻ること、再度開いて変更した入力をキャンセルしても保存されないことを手動確認し、問題なしと回答した。

初期フォーカスの独立した観測、保存中の通常終了案内の実WebView2操作、物理Commit/Close故障と長時間の実OS障害、利用者データ試験は未実施。保存中の閉鎖拒否・結果不明・停止警告は合成境界の自動テストと区別する。削除が残るためADR-0018はPendingを維持する。
