# 画像停止・結果不明のAPIと画面案内

Issue #180と#181、親#42。2026-10-20、既存の保全テストと実Wails経路の案内を照合した。エラー伝達の正本は[ADR-0016](../adr/0016-preserve-safe-api-errors-through-wails.md)、保存結果・停止の正本は[画像保存契約](../cover-persistence.md)。

## 発見した不具合と修正

修正前は実SQLiteの参照Commit競合でGoが結果不明・DB停止を返しても、画面は汎用の「画像の操作結果を取得できませんでした」になった。Wails v2.16.0のCallbackが構造化オブジェクトをErrorで包み、code/messageが失われていた。Goから識別可能なJSON文字列を返し、画面共通処理で限定的に復元する。成功DTO、保存・停止の分類は変更していない。

## 自動テストの役割

- `TestCoverAPIRealCommitBusyPreservesBothImages`: 実PNG・実SQLiteで旧画像を設定後、管理記録確定後に別接続の読取Txを保持し、参照Commitを競合させる。結果不明のAPI・文字列形式、次の画像/DB操作拒否、新旧PNGと元画像保持、再接続後の旧作品情報と管理記録保持を確認する。結果不明を常に旧状態と判断する実装ではなく、この競合ケースの実結果を再接続後に観測する。
- `TestCoverAPIImageOnlyStopKeepsDatabaseUsable`: 選択境界で合成の解放失敗印を返し、画像停止・次の解除拒否、一覧/登録継続、旧作品情報と元画像保持、内部診断非公開を確認する。実Close故障の再現ではない。
- `TestAPIErrorTransportKeepsSafeFields`: Dispatcherの外側JSON輸送、改行を含む安全な情報の保持、内部診断と上限超過の固定案内化を確認する。
- 画面テストはWailsと同じ`Error(string)`を使い、結果不明・DB停止・画像停止で成功表示や自動再試行をせず、一覧・検索・画像URLを保持することを確認する。確定後警告では新しい画像と成功を保持する。未知・破損・上限超過の形式を表示せず、DB停止と誤判定しない。

## 実WebView2の確認方法

Windows、Go 1.26.9、CGO_ENABLED=0、Wails v2.16.0の開発モードを使用する。子プロセスのAPPDATA/TEMP/TMPを分離し、合成3作品と緑系グラデーション120×60・青色48×48だけを使用する。UI Automationは対象PIDに限定し、所有ウィンドウだけをPrintWindowで撮影する。強制前面化や利用者データの操作はしない。

一時的なGo側の検証コードで、実SQLite読取競合、選択境界での合成解放失敗、実参照確定後の後処理境界での合成解放失敗を分ける。画面のAPIをモックせず、Wailsバインディングと本番のエラー変換・画面表示を通す。ただし、故障注入付きの確認用ビルドであり、未改変の配布exeによる実故障試験とは扱わない。一時コード・環境設定・確認用スクリプトは本番へ残さない。

修正後の結果不明は`H:\appdata_local_tmp\mum-cover-stop-e3ae818d150d4f53a1858a15ab339ab3`、画像だけの停止は`H:\appdata_local_tmp\mum-cover-stop-78f7aa3bcce54c0faed60c4017988631`で確認した。前者は専用の結果不明案内、明示的な再読み込み後のDB停止案内と既存一覧保持、後者は画像停止の専用案内と一覧再取得の継続を確認した。通常終了後の`quick_check=ok`、起動ロック再取得、旧PNGと合成元PNGの一致を確認した。結果不明では新旧2ファイル、画像だけの停止では旧1ファイルを保持する。

確定後警告は`H:\appdata_local_tmp\mum-cover-stop-17028021814e4d69ac292f58c0297101`で確認した。実参照確定後に合成の解放失敗印を返し、設定成功と画像停止の警告を同時に表示した。停止後は画像配信も拒否されるため、再取得した画像は表示失敗の仮表示となった。青色の実描画成功とは扱わない。明示的な一覧再取得は継続し、通常終了後に旧PNG・新しい青色PNGの保持、現在参照が新PNGであること、元画像との一致・DB整合性・ロック再取得を確認した。

確定後警告の最初の注入は起動時整理にも作用し、意図した選択画面を開けなかった。検証補助の問題として分け、実参照確定後だけに限定して再実行した。本番の不具合としては扱わない。3ケースの確認用アプリは通常終了し、一時コードを除去した。

## 限界と完了判定

故障注入を除去してビルドしたproduction exeでは、別の分離領域`H:\appdata_local_tmp\mum-cover-stop-prod-db1d91ca9d5e487fb18e09fd11667012`の合成URLを登録フォームへ再入力し、`duplicate_url`の「この作品URLは登録済みです」を確認して通常終了した。停止の実故障試験ではなく、通常のエラーが配布ビルドのWails包装でも復元できることの確認である。

実ディスク故障、電源断、実OS Close故障、全競合の再現ではない。確定後DB返却失敗の画面案内は合成のAPI結果テストであり、実接続返却故障の再現ではない。実機案内と既存のApplication/Storage保全テストを組み合わせ、同じ検証結果として混同しない。

長時間案内、処理中の終了拒否と完了後の通常終了、保存・削除・復旧全体の最終照合は本Issueの完了だけでは達成しない。ADR-0013はPendingを維持する。
