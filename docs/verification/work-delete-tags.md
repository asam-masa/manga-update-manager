## 自動検証

## 実WebView2

2026-10-28、専用APPDATA/TEMPと合成3作品を使う通常productionビルドで確認した。削除対象「削除確認」には「連載中」「ファンタジー」、別作品には同じ「連載中」を付与し、タグなし作品も用意した。普段の利用者データには触れていない。

利用者が、2つのタグ表示、Tab/Shift+Tabでのキャンセル・削除への移動、Escで削除せず一覧へ戻る操作を確認した。その後、同じ作品の削除画面を開き直して明示削除し、その作品だけが消えることも「問題なかった」と報告した。

親担当のread-only SQLite照合では、削除対象ID1がなく、他のID2/3は残っていた。タグ候補はID1「連載中」とID2「ファンタジー」の2件とも残り、「連載中」は作品3との関連を保持し、「ファンタジー」は未使用だった。タグなし作品の確認画面も開き、「タグなし」と有効な削除ボタンを確認してキャンセルした。通常終了・同じ保存先での再起動後も残る2作品だけが表示され、最後に通常終了した。

対象はreview tree `3e1b190e2e1e3068ac32c0e5b13144f721248edd` の実装部分、exe SHA-256は`F6F6FF5EFE8E1A0EF90317E4C410C6F1A21D027323B60210AFD4AF3FC2C52984`。専用セッション・画面画像・補助スクリプトはGit対象外のbuild/bin内に保持する。初回のUI Automationによるメニュー操作は要素を取得できず失敗し、画面の存在をキャプチャで確認した後の標準展開操作で開いた。CIはローカルexeと別に対象SHAと結果を確認する。

改名/削除・読込故障・DB停止は合成APIによるDOM試験であり、実OS故障の検証ではない。タグ管理・AND絞り込み・全倍率と全解像度は未検証。ADR-0020はPendingを維持する。
