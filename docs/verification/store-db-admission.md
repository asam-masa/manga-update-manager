# StoreのDB実行制御

Issue #139。2026-10-18、#137の候補を本番Storeへ導入した。DB形式・マイグレーション・新規依存は変更しない。画像API・UIへの接続と物理接続隔離は対象外。

## 承認済みの境界

登録、ID取得、一覧、最終アクセス保存、表示設定の取得・保存、管理画像の予約・確定・取得、作品画像参照の設定・解除を同じ実行制御へ通す。Storeを使用後にコピーしない。公開前のOpen/Ping/マイグレーションは起動処理だけで実行し、途中失敗ではStoreを公開しない。

直列枠を得てから接続を取得し、停止と同じmutex内で停止・contextを再検査した時点を実行開始とする。SQL、Rowsの消費とClose、TxのCommit/Rollback、接続返却まで枠を保持する。処理中は停止mutexを保持せず、停止通知が後始末を妨げない。枠内から公開Store操作を再入呼出ししない。

`Store.Close`は受付を永久停止し、既存の実行権が解放されてからDBを閉じる。実行中処理の強制中断や、終了予約UIを導入するものではない。枠待ちは停止/contextで戻り、接続取得中は取得が戻ってから再検査する。取得自体の停止キャンセルや即時終了を保証しない。

## 保守的な停止条件

初回は、作品画像参照のCommit失敗では接続の再利用安全性を確認できないため新規DB操作を停止する。結果不明の印を検出しただけで健全性を断定するのではなく、現在の後始末確認手段が不足することを根拠とする。Commitの自動再試行・確認読取・書戻しを行わない。

Commit前の明示Rollbackがエラーを返した場合（キャンセルと競合するErrTxDoneを含む）、接続返却やRowsのCloseが失敗した場合も停止する。Rows反復エラーは自動Closeの失敗も含み得るため保守的に停止する。単一行取得もQueryContext・Next・Scan・Closeへ分け、Rows取得前のクエリー拒否や、Closeが成功したScan変換失敗・正常なErrNoRowsとは区別する。設定列欠損だけで作品管理を止める既存契約の変更は行わない。元原因・元の操作エラーに`ErrDBStopped`を加えて返す。入力拒否・URL重複・後始末が成功した通常拒否は停止しない。SQLiteのすべてのエラーを健全/不健全に分類する実装ではない。

| 結果 | 返却契約 |
| --- | --- |
| 画像参照Commit失敗 | `ErrWorkCoverOutcomeUnknown`と`ErrDBStopped`と元原因。作品ゼロ値・旧パス空 |
| Commit前の失敗、Rollback確認不能 | 元の失敗と`ErrDBStopped`とRollback原因。作品ゼロ値・旧パス空 |
| Commit成功後の接続返却エラー | 確定した作品と旧パスを保持し、`ErrWorkCoverCommitted`と`ErrDBStopped`と元原因。未確定へ戻さず、新たな削除許可にしない |
| 停止後のDB実行要求 | `ErrDBStopped`。入力検証で先に拒否する経路は入力エラーを返すがSQLを実行しない |

他のStore操作も、接続返却の失敗を操作エラーへ追加する。返却エラーは実行済み書込の取り消しを意味せず、利用者や上位層は自動再試行しない。Applicationの`CoverOperations.ObserveError`はDB停止の印でも画像受付を止める。ただし、本番画像処理からの通知と、確定成功＋警告への変換、DB停止専用のWails/UI案内は後続である。既存APIの一般的な保存先エラー・再起動案内は残る。

## 検証と限界

`internal/storage/admission_test.go`で、停止したStoreの全11経路、通常拒否の継続、実際のpool待ち後の停止/キャンセル、Closeの実行権待ち、接続返却エラーの原因保持を検証する。停止と実行開始も100回競合させる。返却失敗は合成二重Closeであり実OS故障ではない。単一行と一覧の合成Rows Close失敗を検証し、設定列欠損時の継続は既存回帰テストで確認する。

Tx故障試験では一時SQLiteのドライバーを包み、実Commit/実Rollbackの後に合成エラーを返す。Rollback失敗で元の不存在拒否を失わず、Commit応答失敗で成功情報を返さず、それぞれ以降のDB取得を停止することを確認する。これは失敗したRollback自体や電源断の再現ではない。Commit成功後の接続返却失敗の同時発生は実行注入していない。

既存のBUSY結合テストでもDB停止と、終了・別Storeでの再接続後の作品状態を確認する。再接続は試験用の観測であり、その起動中の自動回復ではない。全Store操作の通常動作・既存データ互換性は既存テストも併用する。

同じStore経由の新規操作だけを止める。`sql.Conn.Close`はpoolへの返却であり物理隔離を証明しない。pool内部の処理・他のStore・他プロセスは制御しない。自動再開はなく、再起動による復旧も保証しない。画像の実処理・配信・全経路通知、race検出、実I/O故障、専用UIは未検証でありADR-0013はPendingを維持する。
