# 画像処理の途中終了と次回整理

Issue #193、親#42。[最終照合](./cover-validation-audit.md)で不足した、実際の子プロセス途中終了から再接続・本番整理までを確認する。[保存契約](../cover-persistence.md)と通常終了の方針は変更しない。

## 子プロセスと同期

`TestCoverInterruptedProcessRecovery`は一時SQLiteに非空のサイト名・メモ・最終アクセスを持つ作品と旧管理画像を用意し、元ファイルと未知ファイルも保存する。親のStoreを閉じてから、自身のテストバイナリを`TestCoverInterruptionChild`だけの指定で起動する。子は同じ保存先の起動ロックをDB接続前に取得する。

子は本番CoverImporter・Store・platformを使う。テスト用Repositoryラッパー等で次の境界まで実処理を進め、標準出力で到達を通知して標準入力待ちに入る。段階通知からの再入や固定sleepを同期の条件にしない。

| 終了地点 | 終了前の状態 | 次回整理の期待 |
| --- | --- | --- |
| reserved | 新規ID予約済み、ファイルなし、旧参照 | reserved保持・未確認警告。出力を勝手に生成しない |
| partial | reserved、生成PNGの半分だけの未確認出力、旧参照 | 部分出力と予約を保持・未確認警告 |
| confirmed | 実WriteNewCoverとready確定後、参照更新前 | 新しい未参照ready画像と記録を安全に整理。旧参照と旧画像は保持 |
| referenced | 実参照Commit後、旧画像削除前 | 新参照と画像を保持し、旧未参照画像と記録を整理 |
| deleted | 旧実ファイルの削除・不存在確認後、記録整理前 | 新参照を保持し、旧ファイルの安全な不存在再確認から記録を整理 |

partialだけはApplicationのwrite境界を置き換え、CREATE_NEWした実ファイルに半分を書いて閉じた後で待機する。WriteNewCoverのOS書込途中を停止したものではない。他の地点は本番処理が成功して戻った後の境界である。進行を待たせるテストコードは`_test.go`だけに置き、本番へ残さない。

親は到達通知と保存先ロックの使用中を確認してから、取得したcmd.ProcessだけをKillしWaitする。対象は親が作成した子とt.TempDirに限る。正常終了ではなく、親が意図した終了であり試験のcontext期限切れではないことを確認する。試験失敗時も同じ子のハンドルだけで後片付けする。30秒contextと子の25秒テスト期限は試験のハング検出であり、本番タイムアウトではない。

## 再接続と保全の確認

子の終了後、同じ保存先のロックを再取得してからStoreへ再接続する。SQLite quick_check=ok、二つの管理記録と予約/readyの状態、終了地点に対応する現在参照と作品全項目、新旧実ファイルの存在と内容を確認する。

新しい受付で本番Cleanupを実行し、上表の警告と整理結果を照合する。現在参照の画像・元ファイル・未知ファイルはバイト列を保持し、作品全項目と保持する管理記録も変更しない。自動書戻し・画像復元・所有推測によるreserved削除は行わない。ロックは再接続と整理の間も保持し、Storeを閉じてから解放する。

## 範囲と実行記録

Windows・一時領域・合成PNG/SQLiteだけの自動テストである。5ケースの反復、Go全体テスト・静的解析・画面テスト・ビルドの最終版と結果はPRへ記録する。利用者データ、利用者プロセス、OS設定へ触れない。

実プロセスの強制終了を含むが、電源断・実ディスク障害・SQLiteのCommit内部全タイミング・OS書込途中の全位置・全競合を再現したものではない。画面操作や通常終了拒否の再試験とも別である。途中終了の残条件はこの5地点の範囲で確認し、破損画像の実WebView2確認#194とADR-0013全体の最終判断は残す。
