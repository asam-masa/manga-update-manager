# 復元元ZIPの読取保持Spike

Issue #635。2026-11-22、PR #636のマージコミット`b4980a1e6ba19f8364d84cea0075ce30c132f762`を基準に、30分を目安とする合成調査を行った。採用方針は[正本](../restore-preparation.md#復元元zipの読取保持6342026-11-21)を参照する。製品コード・通常データ・既存のZIPパーサーは変更していない。

## 対象と方法

`tools/spikes/restore-source/hold_windows_test.go`は、`t.TempDir`に作成した小さな合成ファイルだけを扱う。名前はsource.zipだが、本文はアプリのバックアップではない固定バイト列である。試験用ファイルへの書込・改名・削除は、元ZIPを製品の片付け対象へ含める実装ではない。

候補は`CreateFile`の読取専用アクセス、`FILE_SHARE_READ`、`OPEN_EXISTING`、`FILE_FLAG_OPEN_REPARSE_POINT`で保持する。取得済みの同じ`os.File`から`ReadAt`とSectionReaderで読取り、パス再取得で同一性を判断しない。これは製品のパス・種別・識別検査を備えた入力APIではない。

## 実測結果

| 条件 | この環境での観測 |
| --- | --- |
| 保持中、選択した名前から書込用に開く | 共有違反で拒否 |
| 同じファイルの別ハードリンク名から書込用に開く | 共有違反で拒否 |
| 保持中、選択した名前を改名・削除する | 共有違反で拒否 |
| 保持中、別ハードリンク名を改名・削除する | 許可された。操作後も保持中の同じハンドルから元の内容を読めた |
| 先行する読取ハンドルがある | 先行側が全共有を許可した条件では、候補の取得と読取が成功 |
| 先行する書込用またはDELETEアクセスのハンドルがある | 候補の取得を共有違反で拒否 |
| 書込可能なマッピングとviewだけを残し、元のハンドルを閉じる | 候補の読取取得を共有違反で拒否。共有なし・読取共有の両候補で同じ結果 |
| 保持中、入力の直上の親フォルダーを改名する | 今回の条件ではアクセス拒否。同じハンドルの読取は成功 |
| ハンドル解放後 | 書込用の取得・実書込・改名・削除が成功 |

マッピングは、先にviewへ1バイトを書き、元のハンドルでその変更を読めることを確認してから試験した。書込先は自プロセスの合成マッピング内に限定する。今回、保持取得後にマッピングから変更できるケースは成立しておらず、その分岐を実測済みとは扱わない。

取得前の取消では取得・Closeとも0回、取得直後の取消では取得1回・Close1回となった。不在ファイルの取得失敗ではハンドルを返さない。Close失敗模型では実際にはCloseした後にエラーを加え、取消原因とClose原因が両方残ることを確認した。これは実OSで解放に失敗した結果ではなく、製品の解放確認契約を確定するものでもない。

## 観測と保証の違い

最初の試行では「別ハードリンク名も改名できない」と期待し、改名が成功して試験が失敗した。選択した名前の拒否条件と、別名の挙動を調べる条件を分離して再実行した。別名の改名・削除が可能という結果は、成功条件へ隠さず上表に残す。

試験のPASSは、意図した拒否条件と観測処理が成立した意味であり、すべての名前・環境で変更を拒否できる保証ではない。別名や親改名、マッピングの試験では、許可と拒否を区別してログへ記録する。将来の環境で結果が変われば、PASSだけで採用条件の成立を判断しない。

選択した名前への通常の変更を拒否する候補は確認できたが、全ハードリンク名の固定まで要求する条件では成立していない。入力側の複数リンクの扱いを、この結果だけで許可・拒否に確定しない。

## 確認環境と限界

- Windows 10.0.26300、Go 1.26.5 windows/amd64、ローカルNTFS。
- `go test ./tools/spikes/restore-source -count=1 -v`で5トップレベル試験・9サブ試験がskipなしで成功。非NTFSでは能力未確認としてskipし、成立確認へ含めない。
- 実測は同一プロセス内の別ハンドルとマッピングであり、別プロセス・ドライバー・全共有方式の挙動を実証したものではない。
- 上位祖先の改名、シンボリックリンクやジャンクション、ネットワーク/非NTFS、全種類のマッピング、実OS解放故障・電源断は未検証。
- ZIP形式・サイズ上限・CRC/ハッシュ・実SQLite/画像の意味的検証、展開、退避・切替・復旧、App/UIは本Spikeの対象外。
