# 登録済み作品の画像操作UI

Issue #43。承認済みの配置・処理中の操作範囲・通知の寿命を[画面設計](../work-screen.md#登録済み作品の画像操作issue-43)へ記録する。保存API・選択完了通知は既存実装を使い、DB構造やファイル操作を変更しない。

## 自動確認

`App.covers.test.tsx`でAPI・イベントを差し替えて次を確認する。

- 選択中は全作品の選択を止め、同作品の解除も止める。別作品の解除、検索とURL起動は止めない。
- 通知の作品ID・操作IDを照合する。同作品の古い通知、別作品の通知、古いPromise完了が新しい選択枠を解放しない。未受信ならPromise完了で解放する。
- 同一tickの二重操作を防ぐ。取消は通知なし。解除成功と後処理警告を分ける。既知の安全なエラーと未知の内部診断を区別する。
- 検索で非表示でも結果を保持し、検索とフォーカスを変更しない。古い一覧・アクセス応答で新しい画像を戻さず、画像応答で新しい最終アクセスを戻さない。
- Enterによる画像操作、通知を閉じた後のフォーカス、アンマウント時の購読解除を確認する。
- 独立レビューで、別作品の選択待ち中に解除成功通知を閉じると、無効な設定ボタンへフォーカスを戻せないことを指摘された。有効なボタンがない時は画像操作領域へ戻すよう修正し、選択中・通常時の両方をテストする。

既存の画像表示、登録、検索、URL起動、IME、表示設定の回帰も全UIテストで確認する。DOMテストは実OSダイアログとWebView2描画の代わりにはしない。

## 実画面確認と限界

2026-10-19、Go 1.26.9、CGO_ENABLED=0、Wails CLI v2.16.0のproduction exeを、一時APPDATA・合成PNG・確認専用の3作品で確認した。保存先は`D:\appdata_local_tmp\mum-cover-actions-8d3b2d9b76a74187943970029725965d`。利用者のDBや元画像には触れていない。

- 未設定作品へOS選択画面から合成PNGを設定し、画像と成功通知、変更・解除ボタンを確認した。
- 選択をキャンセルし、既存画像の操作を維持したまま結果通知を出さないことを確認した。
- 解除で未設定へ戻り、解除成功を表示した。別の設定済み作品の画像変更も成功した。
- 一覧再読み込み・通常終了・同じ確認用保存先での再起動後も、変更と解除を保持した。再起動後に以前の結果通知は復元しない。
- 合成元画像のSHA-256が変わらないことと、通常終了を確認した。
- 所有ウィンドウが前面であることを検査してから実キーを送り、Tabで変更から解除へ移動、Enterで解除、Enterで通知を閉じた後に画像設定ボタンへフォーカスが戻ることを確認した。

UI Automationと所有ウィンドウのPrintWindow撮影を使用した。画像選択中の解除などの全競合・遅延通知・内部故障のUIはAPI差し替えテストの確認であり、実I/O故障の再現ではない。開発モード、狭幅の全配置、全キーボード順序、全ての競合順序と長時間停止は未確認。ADR-0013全体の検証完了とは扱わずPendingを維持する。
