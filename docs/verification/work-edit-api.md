# 作品編集APIの検証

Issue #213、親#205。正本は[ADR-0018](../adr/0018-edit-and-delete-works.md)と[API契約](../work-api.md#編集apiissue-213)。一時SQLiteと合成操作だけを使う。

- Applicationテストで不正入力を保存・時刻取得前に拒否し、正規化した4項目、ID、context、時刻、結果とエラーを保存境界へ渡す。
- Appと一時SQLiteで4項目更新、画像参照・登録日時・最終アクセス保持、日本時間DTO、変更なし、重複・不正・不存在、画像だけの停止後の編集、終了後拒否、再接続後の保存を確認する。画像は合成の参照文字列で、実ファイルの取り込みは行わない。
- 編集を保存境界で待機させ、同作品の編集・URL・画像拒否、別作品編集、通常終了拒否と案内、完了後の再要求終了を確認する。既存5経路のURL/画像待機テストにも実編集APIの拒否確認を追加する。
- 保存境界の合成エラーで、結果不明・確定後解放失敗・DB停止・一般失敗を区別し、安全なDTO/エラー、呼出し1回、予約解放を確認する。これは実Appから物理Commit/Closeを故障させた試験ではない。Store自身の故障注入とDB停止は[保存基盤](./work-edit-storage.md)の検証を併用する。
- TypeScriptでWailsのError包装後の既知コード復元と結果不明のDB停止判定を確認する。

編集UI、実WebView2の保存・終了案内、実OS障害、利用者データは未検証。削除は対象外。自動検証・ビルドの対象版と実行結果はPRへ記録する。親#205とADR-0018はPendingを維持する。
