# 長時間の画像処理を画面で案内する

Issue #183。方式は[ADR-0017](../adr/0017-poll-cover-progress-snapshots.md)、保存・終了の正本は[画像保存契約](../cover-persistence.md#長時間処理の案内)。画面の案内は停止判定やフリーズの確定診断ではない。

## 実装と自動テスト

Appが進行中の作品ID・操作ID・種別と、実行を要求した起動時整理を観測対象にする。画像解除も操作ID付きAPIを使う。検索やカードの寿命から独立した`CoverProgressNotice`が約1秒ごとに取得し、応答が未完了の間は重ねて要求しない。対象がなくなればタイマーを止める。

バックエンドで計測が始まり、取得した経過時間が10000ミリ秒以上の場合に、画面上部へ段階と「最終確認時の経過」を表示する。画面だけで経過を推測・加算せず、選択待ちは長時間処理に数えない。進捗率や残り時間を出さない。

応答の形・固定段階・時間・重複を検査し、取得開始時と現在の両方で作品ID・操作ID・種別が一致するものだけを使う。完了済み・別操作・アンマウント前の応答で表示を復活させない。成功・失敗・取消・確定後警告の判断は既存の操作APIが担当する。

取得失敗・不正応答では時間にかかわらず固定の「現在の処理状況を確認できません」を案内する。前回情報がある場合はそれを保持し、未確認であることを示す。既に観測した要求が配列から欠落した場合も、結果確定と扱わず前回情報を保持する。未観測の要求が空配列に現れないだけなら、段階や開始を推測しない。取得失敗は停止・完了・画像操作の自動再試行の根拠にしない。観測の定期取得は継続する。

`CoverProgressNotice.test.tsx`で短時間完了、10秒境界、選択待ち、単一取得、複数要求、ID/種別の不一致、古い応答、完了後・StrictMode・再マウント、欠落・取得失敗・回復、不正応答を制御時計と遅延Promiseで確認する。Appの画像操作テストで検索非表示とフォーカス維持、成功・失敗・警告・取消後の案内消去、整理テストで実行中だけの観測と完了遷移を確認する。

独立レビューで、段階が配列`["saving"]`でもObject.hasOwnの文字列変換で検査を通る問題を指摘された。Goの通常DTOからは発生しないが、不正応答の契約に合わせて段階の文字列型を明示的に検査し、配列・オブジェクトの拒否テストを追加した。以下の実画面確認はこの型検査追加前の表示経路で行い、修正部分は自動テストとビルドで再確認する。

## 実WebView2（2026-10-21）

Windows、Go 1.26.5、CGO_ENABLED=0、Wails CLI v2.16.0の開発モード。保存先・TEMP/TMPを`H:\appdata_local_tmp\mum-progress-b01aef53de40457a99ff4109d8a8d35d`へ分離し、合成3作品と画像だけを使用した。PID34940の所有ウィンドウだけをUI Automationで操作し、PrintWindowで撮影した。無効な親の強制前面化は行っていない。

一時的なRepositoryラッパーで、起動時一覧確認、設定の参照更新、解除の参照更新に入った後、検証専用の解除ファイルを待つ。段階・経過時間は本番のApplication、状態取得API、Wails、画面を通す。実I/Oの故障や通常の処理時間の実測ではなく、待機を制御した検証用ビルドである。

- 起動時整理の「情報を確認」と経過時間を画面上部で確認し、待機解除後に案内が消えて画像表示・画像操作を利用できた。
- 選択画面を10秒以上開いても長時間案内は出ず、選択後に計測した「保存情報を更新」と経過時間を確認した。
- 検索で0件にして対象カードを隠しても、作品名付きの案内は残った。待機解除・処理完了後に案内が消えた。
- 解除処理でも10秒超の段階表示を確認し、待機解除後は案内が消えて「画像を外しました」と未設定表示へ遷移した。

最初の検索操作はラベルのUI要素を取得したためValuePattern非対応で失敗した。検証補助を入力欄IDの指定へ直して再実行し、本番不具合とは扱っていない。確認用アプリは通常終了した。終了後のSQLite `quick_check=ok`、3作品、起動ロック再取得、元画像の存在とSHA-256 `C97C8C8535E7B1C7DA5962C8C3C7ED19ADE26E9ABBA2C1E9665A88F9F1DFFF42`を確認した。検証用ラッパー・起動呼出しは除去し、データ・撮影・補助スクリプトはGit対象外とした。

2026-10-21、後続#189で[終了拒否と結果後の通常終了](./cover-close.md)を追加検証した。以下の終了拒否の残件は#183時点の記録であり、現在の検証範囲と限界は後続記録を参照する。

## 限界

短時間の段階は取得間隔の間に終わり、見えない場合がある。取得API自体が返らない場合は次の取得を重ねず、最後の観測値を表示するだけで時間を推測しない。動き続ける時計やアニメーションで正常動作を保証しない。

古い応答・取得失敗・不正応答・複数操作の全順序は自動テストで確認し、実WebView2で全競合・実故障を再現したとは扱わない。未改変production exeで10秒超の実故障を起こす試験は未実施である。処理中の終了拒否を全段階で検証する作業、保存・削除・復旧の最終照合、#176の既知問題は別であり、ADR-0013はPendingを維持する。
