# 作品操作パネルと共通通知の実WebView2確認

Issue #236、親#44。2026-10-24、基準main `681b9871ea66ff7f68b1d2a9937601e2b3236bb0`（PR #248）で、#243/#245/#247の接続をWindowsの実WebView2で確認した。製品コード・設計判断・ADRの検証状態は変更しない。

## 対象と方法

`go.mod`のGo指定は1.26.0、今回使ったGoは1.26.5（windows/amd64）、Wailsはv2.16.0である。frontendのTypeScript解析・productionビルド後、`wails build -s -m -nosyncgomod`相当で通常のproduction exeを生成した。計測用の待機点や模擬APIは加えていない。exeのSHA-256は`5259409ba9e1984f56593e01f74bc32f0ce34e82cf29060453f173d2cf3651a0`。

基準mainの[Windows CI実行](https://github.com/asam-masa/manga-update-manager/actions/runs/40089414205)は同SHAで成功している。今回のローカル作業では実画面確認を行い、Go/DOMテスト全体の再実行結果としては扱わない。先行の自動テストとレビューはPR #244/#246/#248を参照する。

専用APPDATA/TEMPと、合成3作品「表示確認」「欠損確認」「未設定確認」、合成PNGを使った。普段のDB・画像・設定は操作していない。検証補助は対象exeの絶対パス・プロセスID・専用保存先の目印を照合し、キー送信前に対象ウィンドウの前面状態と有効状態を確認する。画像選択中の無効な親への強制前面化や、強制終了は行っていない。

UI Automationの操作・読取と、対象ウィンドウの撮影を併用した。利用者によるTab/Shift+Tab・上下キー・Escと、ネイティブ画像選択の取消確認は自動操作と分けている。

## 確認結果

| 条件 | 観測した結果 |
| --- | --- |
| キー操作 | 「⋯」から下キーで最初、Home/Endで先頭/末尾へ移り、Escで元の「⋯」へ戻った。利用者もTab/Shift+Tab・上下キー・Escを確認し、問題なしと回答した |
| 同時に一つ・外へ移動 | 別作品の「⋯」へ移ると前のパネルが消えた。検索欄へのフォーカス移動で閉じ、検索欄のフォーカスを維持した |
| 狭い画面と端 | ウィンドウを640×640へ変更し、下側の作品のパネルがウィンドウ内に収まることをUIA矩形と撮影画像で確認した。確認後は1024×768へ戻した |
| 編集と復帰 | 「表示確認」を「表示確認_編集」へ保存し、成功通知と「⋯」への復帰を確認した |
| 別種操作の通知保持 | 同作品の画像を解除しても編集通知が残り、両方の作品名付き通知を一覧上部で表示した |
| 検索非表示 | 検索を「未設定」にして対象カードを隠しても、編集・画像解除の通知が残った。撮影画像も確認した |
| 通知閉鎖 | 非表示作品の画像通知を閉じると検索へ戻り、編集通知は残った。表示中の編集通知を閉じると、その作品の「⋯」へ戻った |
| 削除確認と取消 | 「欠損確認」の確認画面で最初はキャンセルへフォーカスし、Escで取り消すと「⋯」へ戻った |
| 削除と通知 | 改めて削除するとカードが消え、削除通知と別作品の編集通知が共存した。削除通知を閉じると検索へ戻った |
| 画像選択中 | 「未設定確認」の画像選択で親が操作不可となる間も、処理中通知が存在し、プロセスは動作を継続した。利用者が何も選ばず取消し、アプリへ戻れたと回答した |
| 通常終了・再起動 | 手動確認後に通常終了し、同じ専用保存先で再起動した。編集名・画像解除・削除が保持され、再起動後も通常終了できた |

## 補助操作の失敗と切り分け

最初は展開状態を持つ「⋯」やフォーム開閉にUIAのInvokePatternを使い、Unsupported Patternとなった。対象はExpandCollapsePatternを公開していたため補助側を対応させ、再実行した。アプリの不具合として扱っていない。

通知確認の途中で補助側が編集前の作品名を使い、対象groupを取得できず停止した。実画面には編集後の名前の通知が存在した。名前と検索条件外の通知文を修正し、現在の状態から残る確認を再開した。編集・画像解除を重ねて再実行した結果とは扱わない。

## 限界と後続

実画面では通常の編集・画像解除・削除・画像選択取消と通知の共存を確認した。故障による警告・結果不明、API応答の遅延・ID再利用・全競合順序は先行のDOM/Goテストの範囲であり、実OS故障や本番の長い取り込みを今回再現したわけではない。10秒以上の観測案内は[既存の画像進捗検証](./cover-progress-ui.md)と区別する。

Ctrl＋拡大キーを送ったがパネル寸法は変わらなかったため、文字拡大を確認済みとはしない。3形式の配置・切り替え・設定復元と、形式変更時にパネルを閉じる実接続は#237へ残す。これらを実装済みと扱わず、ADR-0005はPendingを維持する。

この記録で#236の実装済みメニュー・通知の確認を補う。Issueの完了は本記録のレビュー・CI・マージも条件とし、検証条件を削ったり安全条件を緩めたりしない。
