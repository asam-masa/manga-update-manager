# 削除処理中の通常終了と再起動

Issue #230、親#206。2026-10-23、基準main `4a2b2efed0c3f7a052bec2e3ef993fb1bbf5be78`で確認した。[ADR-0018](../adr/0018-edit-and-delete-works.md)、[削除API](./work-delete-api.md)と[確認UI](./work-delete-dialog.md)の検証を補う。

## 方法と通常版との差

通常の削除は短いため、#219と同じGoの`-overlay`で起動入口だけを置き換えた計測用exeを使った。startup後にWorkDeleterのRepositoryを一度だけラップし、共通`BeginDelete`と画像参照排他を取得した後、実Storeへ入る前で待機する。`entered`を新規作成し、`release`がない状態で終了要求を送った。最大60秒で削除せず失敗する制限を設けたが、成功試行では期限切れではなく明示的な解除を観測した。

差分は専用領域の起動前確認、タイトル、startup後のRepository差替え、起動エラー出力である。画面・削除確認・共通受付・`OnBeforeClose`・既存の案内・`OnShutdown`・API変換は通常経路を使用する。解除後は本物のStoreと既存の画像整理へ委譲し、削除成功を合成して返さない。実ファイルの削除段階やCloseの途中で待機する試験ではなく、後処理中の予約保持は先行APIテストの根拠と区別する。

GUID付きの専用APPDATA/TEMPに合成3作品と画像を作り、普段のデータ・元画像・exeを変更しない。補助コード、マーカー、exe、データ、画像はGit対象外の`build/bin`へ保持した。パスの文字列検査とマーカーは誤操作防止であり、敵対的なjunction差替え等への耐性を実証するものではない。

## 観測結果

UI Automationで「表示確認」の削除を実行した。人による目視・マウス・キーボード確認とは区別する。

| 操作・状態 | 結果 |
| --- | --- |
| 削除境界へ到達、未解除 | entered作成、release不存在、削除ボタンの無効化、処理中メッセージを確認 |
| 通常終了要求 | 「作品を削除中です」「作品の削除・画像の後処理中は終了できません。処理結果を確認してから、もう一度閉じてください。」をUIAで取得。プロセスは生存 |
| OK後に待機解除 | 実削除が完了し、対象カードが消え、削除成功通知と残る2作品を表示 |
| 自動終了の予約でないこと | 完了後も生存し、別作品の削除確認を開いてキャンセルできた |
| 結果後の再要求 | CloseMainWindowによる2回目の要求で通常終了し、WaitForExit成功 |
| 待機点なし通常版で同じ専用保存先を再起動 | 残る作品を表示し、削除済み作品が復活しないこと、通常終了を確認 |

アプリ本体の撮影画像は処理中の確認画面と削除後の成功画面を読み、表示を確認した。別ウィンドウのネイティブ案内は本体のPrintWindow画像に含まれず、案内文の根拠はUIA取得結果である。

最初の補助実行ではウィンドウ生成を待たずUIAの対象がnilになった。同じプロセスで待機を追加して再開したが、実際には変わらないボタン名を「削除中…」として検索し、待機中にタイムアウトした。finallyで解除され、削除は完了した。この試行は終了拒否の成功根拠に使わない。対象プロセスを通常終了し、新規GUIDの専用データでボタン無効化と実在する処理中メッセージを確認する方式に直し、上表を最初から最後まで通して確認した。強制終了・ACL変更は行っていない。
