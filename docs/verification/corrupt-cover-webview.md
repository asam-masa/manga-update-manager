Issue #194、親#42。[最終照合](./cover-validation-audit.md)で不足した破損画像の実画面確認である。欠損の過去記録やHTTP/DOMテストの成功だけで代替せず、本番の配信と画面を通して確認した。

## 対象と方法（2026-10-21）

- 本番コード: `40cc9467fdee042fd211f77116eecb8f9c41c2e9`（PR #197マージ後）。本番コード・UI・依存・DB形式は変更せず、故障注入も追加しない。
- Windows、Go 1.26.5、CGO_ENABLED=0、Node 24.18.0、Wails CLI v2.16.0。開発モードは`dev -m -nosyncgomod -nogorebuild -noreload -nocolour`、配布用は同じコードのproductionビルドを使用した。
- 子のAPPDATA/TEMP/TMPを`H:\appdata_local_tmp\mum-corrupt-7540d19eddff4cbcb6c7234e85f222b6`へ分離し、合成の「破損確認」「正常確認」「未設定確認」3作品と生成PNGだけを使用した。利用者データ・設定は使わない。
- ready管理画像の先頭1バイトを反転する。同じ実ファイルへ同じ長さで書き、管理記録の識別情報・期待ハッシュを更新しない。元画像は別ファイルで保持する。復元も同じ実体へ元の内容を書き戻す検証補助操作であり、アプリの自動修復ではない。
- UI Automationは起動した開発PID42776、production PID26272の所有画面だけを対象とした。所有ウィンドウのPrintWindow撮影を開いて、仮表示・案内・正常カード・回復画像を確認した。利用者による直接目視や実キー操作の追試ではない。

## 検証補助と限界

productionの非表示起動では所有ウィンドウを取得できなかったため、当該PIDとexeパスを照合し、その所有ウィンドウだけShowWindowの非アクティブ表示で開いた。表示直後はUI要素が未準備だったため再取得した。SetForegroundWindowは行わず、#176を解消したとも扱わない。撮影・補助・DB・画像はGit対象外である。

今回は管理記録と一致しない内容を実ファイルへ用意した検証であり、あらゆるPNG破損位置や、破損に合わせて管理記録まで書き換えた状態、実ディスク障害・全競合・全画面幅の証明ではない。別HTTP取得で個々の応答コードを計測せず、アプリの配信を通した実画面結果と既存のHTTP/PNG拒否テストを区別する。

Go全体テスト・vet、画面89テスト、TypeScript/ViteビルドとWails productionビルドは成功した。今回の変更は記録だけであり、四項目の根拠・レビュー・既知制約を合わせたADR-0013全体の最終判断は別PRへ残す。Validation StatusはPendingを維持する。
