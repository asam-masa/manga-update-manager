# タグ管理の削除確認（Issue #331、親#315）

[画面契約](../tag-management.md#削除確認の画面接続issue-331親315)に従い、既存のLoadTagDeletePreview/DeleteTagを接続する。DB・API・生成型・依存関係は変更しない。削除するのはタグと関連だけであり、作品本体を削除するAPIは呼ばない。

## 自動検証

合成APIのDOM試験で、対象タイトルと件数、未使用の明示的な空配列、未取得/不正/部分結果の拒否、同件数でも対象が入れ替わった後の再確認を扱う。再取得失敗は前回表示を残して削除不可とし、不在を今回の成功と区別する。ID上限・9桁の小数秒を送信時も保持し、不正日付・余分な精度・別表現やゼロ日時を採用しない。

連打・処理中の戻る/閉じる/Esc、StrictModeの旧応答、確認中の取消、結果不明/不正成功/停止/確定後警告、次/前/検索のフォーカスを確認する。親AppのDOM試験では、管理画面を閉じた後も削除通知と停止警告が残り、作品一覧の23作品が残ることを確認する。取得で判明した現在名/件数を一覧へ戻っても古くしない。通常レビューで、確認情報の取得失敗から一覧へ戻ると変更操作を再開できるケースを再現し、親一覧へも未確認を伝えて、再取得成功まで変更・削除を止めるよう修正した。

## 実WebView2

2026-10-31、専用APPDATA/TEMPの合成23作品・24タグでproductionビルドを起動した。利用者が、共有タグ「マンガ」の23作品のタイトルをスクロール表示できること、Tab/Shift+TabとEscの取消を確認した。再度開いて明示削除し、タグだけが消え、管理画面を閉じても23作品と削除通知が残ることを確認し、「問題なかった」と報告した。

利用者は続けて、「漫画2」の編集に選択済みタグがなく、「漫画1」の編集にはシリーズ等の他タグが残ること、漫画2の削除確認が「タグなし」となりEscで削除せず戻れることを確認した。最後は通常終了し、親担当も対象プロセスの終了を確認した。mode=roのSQLite照合では、共有タグID1がなく、23作品と他タグの関連が残っていた。

初回exe SHA-256は`54DD99452BEDB71806F749ADEDC09B2BD85089980417BE061AFE4126BB198EAF`、実装部分はindex tree `2118cfabfa4d4d77ff6480900e12d3643808089d`。鮮度伝播の修正後exeは`B68DC617080195AAD1EAD0FFAD62FC8EA35B447ABA934A490B288D1ED3E67495`。同じ合成保存先で再起動し、利用者が23作品と共有タグの削除状態の保持、未使用タグの0作品表示と削除、削除後に近くのタグの名前変更へフォーカスが戻ること、通常終了を確認した。

最終のmode=ro照合では、共有タグID1、未使用タグID5/6がなく、23作品とシリーズ等の他タグの関連が残っていた。ID6「未使用2」は利用者が追加で明示削除したことを確認しており、意図しない削除として扱わない。親担当も修正後アプリの対象プロセス終了を確認した。

合成DB・exe・補助スクリプトはGit対象外のbuild/binへ保持し、普段のデータは使っていない。合成APIの遅延や故障試験を、実OS故障の再現とは扱わない。

AND絞り込み・実OS故障・全倍率/解像度は今回の検証範囲に含めない。ADR-0020はPendingを維持する。
