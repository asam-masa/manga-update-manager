# バックアップ形式と整合した退避のSpike

Issue #380。2026-11-03、Wails設計ではなく保存候補を30分上限で調査した。modernc.org/sqlite v1.61.1とdatabase/sql、Go標準archive/zipを使用し、新規依存は追加していない。以下は推奨案であり採用済み仕様ではない。

その後、利用者はZIP＋版付きJSON目録＋VACUUM INTOを承認し、[形式v1](../backup-format.md)を具体化した。#390/#391の入力検証も実装済みで、現在の進捗は[初回設計](../backup-restore.md)と[ADR-0022のValidation](../adr/0022-manual-backup-and-replacement-restore.md#validation)を参照する。以下の比較・未決定・次の判断は調査時点の記録として残す。後続の合意は、本Spikeの試験範囲や回復保証を拡張するものではない。

## 比較と推奨

| 候補 | 利点 | 負担・限界 |
| --- | --- | --- |
| ZIP＋DBコピー＋JSON目録 | 標準ライブラリで1ファイル化でき、画像と版・除外記録を分けられる | 展開パス・サイズ・重複・圧縮爆弾・検証順序を別途制限する必要がある |
| 独自バイナリー形式 | 入力と構造を専用に定義できる | 独自のパーサー・互換性・検証の保守が増える |
| 全データをJSONで再構成 | DB実装から分離できる | ID・関連・日時・設定の忠実な再構成と移行規則が増える |

初回はZIPにDBと管理画像、版付きJSON目録を入れる案を推奨する。CRCだけでなく各内容のサイズとSHA-256を目録へ記録し、欠損/破損のため意図して除外した画像を別に列挙する。ハッシュは偶発的な破損検出用であり、攻撃者による改変の真正性を保証しない。暗号化・署名は今回採用しない。

DB取得はVACUUM INTOを第一候補とする。SQLite Backup APIも候補だが、今回そのdriver公開経路は検証していない。接続を閉じてDBだけを単純コピーする案は、再接続・WAL等の扱いを含めて別途確認が必要になる。

## 公開仕様と実行結果

[SQLite公式](https://www.sqlite.org/lang_vacuum.html)はVACUUM INTOを整合したDBコピーの作成手段として説明する。既存の非空出力先は拒否され、実行中の中断では出力が不完全になり得る。同接続のトランザクション内では実行できない。DBコピーの整合性は、外部画像の同時点取得を保証しない。

`go test ./tools/spikes/backup-snapshot -v`が成功した。試験は[再現コード](../../tools/spikes/backup-snapshot/backup_snapshot_test.go)を参照する。

- 合成DBでDELETE/WAL両モードを試し、明示INTEGER PRIMARY KEY・文字列・user_versionの保持とquick_check=okを確認。退避後の元DB変更はコピーへ反映されない。
- 非空出力先とトランザクション内の実行は拒否された。
- 標準ZIPで合成目録と画像相当のバイト列を書込み、全エントリーを最後まで読み戻した。末尾を切り落としたZIPは拒否された。
- 書込失敗のWriterではZIPのCloseが失敗した。エントリーへの書込みだけで成功判定せず、最終化の失敗を確認する必要がある。

画像相当の内容はPNGのデコード試験ではない。製品Store、全移行、画像ハンドル、通常アプリの排他には接続していない。試験内だけの一時ディレクトリはt.TempDirで管理し、合成DBやZIPをGitへ保存しない。通常保存先・OS設定・既存データは変更していない。

## 整合性と完成判定に必要な後続条件

既存の起動排他は他の通常アプリとの保存先共有を防ぐが、アプリ内の全操作や外部プロセスの変更を一括停止するものではない。WorkOperations、画像受付・起動整理、設定保存等を含む通常操作停止の境界を別途設計する。DBコピーと、その参照先の画像を同じ保護期間内に取得・照合する案であり、今回の個別試験で実現済みとはしない。

目録にはformatVersion、アプリ/schema識別、作成UTC、DBと画像の相対名・サイズ・ハッシュ、除外理由を持たせる案とする。正確な項目・上限値・旧新版互換は未決定。コピー元DBの参照を無断修正せず、除外画像と復元後の仮表示の整合を#381で確認する。

専用の一時出力でDB生成・画像照合・ZIP Close・ファイルSync/Closeと読み戻し検証を完了し、最後に完成物として公開する案を推奨する。最終ファイルへの直接書込みや、既存バックアップの無条件上書きは推奨しない。Windowsの公開切替・上書き方針・容量不足・電源断・中断時の残置と回復は未検証であり、安全な原子的公開を保証しない。

復元前の展開では絶対パス、親参照、リンク、重複名、未知エントリー、個別/合計展開サイズ・件数の制限が必要となる。単にZIPを開けたことやquick_check成功だけで、信頼できる入力・完全な製品データとは判断しない。具体値と入力DBの安全検証は#381の問いに残す。

## 次の判断

ZIP＋版付き目録＋VACUUM INTOという候補について利用者と判断し、#381で復元入力・退避・切替と復旧の最小検証へ進める。製品への組込みや全体Verifiedは本Spikeの成果ではない。判断の正本は[ADR-0022](../adr/0022-manual-backup-and-replacement-restore.md)で、ValidationはPendingを維持する。

参考: [SQLite Backup API](https://www.sqlite.org/backup.html)、[Go archive/zip](https://pkg.go.dev/archive/zip)。
