# 画像解除APIの結合検証

Issue #150。設計正本は[画像保存契約](../cover-persistence.md)と[ADR-0013](../adr/0013-define-cover-operation-boundaries.md)。

## 接続範囲

`App.RemoveWorkCover`からApplication、Storeの参照解除、既存の旧管理画像削除までを接続する。設定と解除はDB確定・警告分類・停止通知・フォルダー解放を共用し、解除では選択と新規生成保存だけを省く。祖先保持と共通参照排他はDB更新から削除・記録整理・最後の解放まで続ける。

未設定の解除はDBの既存規則で日時も変更しない。確認できない旧パスを削除許可に使わず、確定後の後処理失敗で参照や日時を戻さない。結果不明では成功と断定せず旧画像を保持する。

## 自動テスト

- `app_cover_test.go`: Wails境界の設定→変更→解除→再解除、空警告配列、解除DTOにcancelledなし、元画像不変、不正ID・不存在・停止後拒否。
- `cover_remove_test.go`: legacy解除、他項目保持、未設定時の変更なし、選択・元画像読取なし。準備失敗・安全性拒否・キャンセル・停止・合成結果不明・合成確定後DB失敗・最終解放失敗。参照排他待ち、同作品の選択/解除拒否、別作品の選択受付、通常終了拒否。
- `cover_cleanup_test.go`: 設定変更と解除の両経路で、実PNG・一時SQLiteの通常削除、共有と大小文字違いの共有、未知別表記、内容変更、記録なし、reserved、記録整理失敗、解放失敗、削除前/記録整理前停止を確認する。

## 限界と後続

実SQLiteの読取トランザクションで解除CommitをBUSYにし、結果不明・Store停止・画像保持・再接続後の参照保持も確認する。ただし、このケースで旧状態だったことをすべてのCommit失敗へ一般化しない。合成エラーは実OS故障や電源断の再現ではない。自動起動整理、配信、画像UI、実WebView2での解除・警告・終了案内は未実装または未確認であり、ADR-0013のPendingは維持する。テストは一時領域と合成データだけで行い、利用者データを削除しない。
