# 画像フォルダー準備のWindows境界

Issue #109。`platform.PrepareCoverDirectory(ctx, directory)`は既存のアプリ保存先を受け、固定名`covers`を必要なら作成し、祖先からそのフォルダーまでを保持する`io.Closer`を返す。Application・起動処理・Wails・画像保存からはまだ呼び出さない。

## 処理と対応範囲

ドライブ文字付き・バックスラッシュ区切りの正規形絶対パスだけを受け付ける。相対、UNC、デバイス形式、ドライブルート単体、親参照、予約名、末尾の区切り・空白・点、ストリーム等を拒否する。ドライブ種別は固定・リムーバブル・RAMのみを許可するが、各種ドライブでの実測済みを意味しない。実アプリが解決する保存先との接続・表記互換性は後続で確認する。

ルートから既存保存先までを、通常読取・読み書き共有・削除共有なしで順に開く。同じハンドルの種類・ディレクトリ属性・reparse属性を確認し、親を保持したまま次へ進む。保存先自身や祖先が不在なら作らず失敗する。保存先まで保持した後、直下の`covers`だけを作成し、存在する場合も必ず開いて検証する。リンク・通常ファイルを通常ディレクトリとして扱わず、取得失敗時に共有設定を緩めない。

失敗時はnilの結果とエラーを返し、部分取得の全ハンドルを逆順で解放することを試みる。キャンセルは開始時・各階層の前・完了前に確認する。Windows API実行中の即時中断は保証しない。作成後のエラーでもフォルダーを削除せず、既存内容・画像・DBも変更しない。フォルダーの保持だけで画像所有や削除許可を証明しない。

成功時は呼び出し側が処理を終えてからCloseする。Closeは全ハンドルを逆順で一度だけ閉じ、失敗しても残りを試す。二回目以降は保存した結果を返し、同じOSハンドルを再Closeしない。Close失敗は必ず解放済みという意味ではない。#113で解放を確認できない場合の画像機能停止・再起動案内と、画像処理中の通常終了拒否を合意した。[上位の契約](../cover-persistence.md#close失敗と通常終了)を参照する。この境界だけでApplicationの停止・警告・終了制御が実装されたとは扱わない。

## 検証

2026-10-17、Windows・Go 1.26.9・CGO無効で一時領域を用いて検証する。利用者画像・DB・ACL・システム設定は変更しない。

- 作成、既存内容の保持、二重取得・列挙・子の読み書き、保持中の移動拒否と解放後の移動成功
- 保存先・coversのsymlink/通常ファイル、不在祖先、対象外パス、既存DELETEハンドルとの共有違反を拒否
- 事前キャンセルで作成なし、作成後キャンセルでフォルダーを残して部分ハンドルを解放
- Close失敗の合成注入で逆順・全件試行・エラー保持・二重Close防止を確認。OSの実Close失敗や実際のリーク復旧の実証ではない

```powershell
$env:GOTOOLCHAIN='go1.26.9'
$env:CGO_ENABLED='0'
go test ./internal/platform -run 'TestPrepareCoverDirectory|TestCoverDirectory' -v
go test ./...
go vet ./...
go build ./...
```

本番コードへの未接続の境界追加であり、画像機能全体の採用完了や安全性保証ではない。ドライブ再割当・悪意ある属性変更・全reparse tag・実ネットワーク・各種FSの検証は対象外。参照確認から削除までの排他、配信、終了待ち、部分成功は後続で確認し、ADR-0013はPendingを維持する。
