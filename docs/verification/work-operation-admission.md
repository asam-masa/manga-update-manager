# 同作品操作の共通受付

Issue #211、親#205。正本は[ADR-0018](../adr/0018-edit-and-delete-works.md)。`WorkOperations`はAppに1個あり、Appの寿命ロック内でURL起動・画像設定/変更/解除の全正規APIが予約する。操作ID付き画像APIも同じ経路を通る。既存のApplication部品を直接呼ぶテストや別Appはこの受付を共有しない。

## 契約

- 同作品は待ち行列にせず競合拒否する。別作品の受付は継続する。画像選択枠・整理・画像停止・Store停止・参照排他の制約は維持し、画像停止だけで作品共通受付を止めない。
- AppのAPIは既存処理・通知と後始末・解放が終わってから予約を返す。解放はidempotentで、古い解放が新しい予約を消さない。失敗・選択取消でも予約を返す。
- `BeginEdit`は後続用で未接続。編集中の通常終了は案内して拒否し、拒否時に共通受付を閉じたり未開始の整理を取り消したりしない。編集がなければ、同mutex内で画像側の終了判断を行い、許可された場合だけ共通受付も閉じる。待機はmutex/Appロックの外で行う。
- URL実行中の終了は従来のAppロックによるDB寿命保持を維持する。共通受付は画像/DBの段階開始権や全停止機構ではない。

## 検証と限界

Unit Testで同作品拒否・別作品受付、二重解放と古い解放、画像側の終了拒否後の再受付、編集開始と終了確定の100回競合を確認する。APIテストはURL起動、通常/操作ID付きの選択と解除の5経路を依存境界で待機させ、同作品のURL/画像/編集受付拒否・別作品URL継続・完了後再受付を確認する。選択は合成の取消で戻し、ブラウザーはGo関数で置換する。

Appの編集受付を保持して、通常終了拒否・案内関数・受付継続・未開始整理保持・結果後の再要求終了・以後の新規受付拒否を確認する。編集APIはまだなく、実保存での終了拒否確認ではない。既存の画像故障・停止・終了テストも再実行する。

一時SQLiteと合成操作だけで、実OSダイアログ/ブラウザー/新規GUI試験・実利用者データ操作は行わない。全競合順序やUIボタンの無効化を実証したとは扱わない。新しい編集終了案内の実WebView2確認はAPI/UI接続後へ残す。最終対象版と自動検証・ビルド・通常/独立レビューはPRに記録し、親#205とADR-0018のPendingを維持する。
