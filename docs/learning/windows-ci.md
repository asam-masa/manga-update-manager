# CIでクリーンな環境を確認する

CIは、開発端末では成功する変更が別の環境でも成立するかを確認する仕組みです。判断の正本は[ADR-0009](../adr/0009-verify-windows-build-in-ci.md)、手順は[CI運用](../develop/workflow/continuous-integration.md)です。

## 順序もビルドの条件になる

このアプリはGoから`frontend/dist`を埋め込みます。ローカルには前回のビルドが残りますが、Gitに含めない成果物は新しいrunnerにはありません。Goテストより先に画面をビルドするのは、この差をなくすためです。

`npm ci`はlockfileに合わせて依存を導入します。その後にWailsが`npm install`をやり直すと、どの導入手順で検証したのかが曖昧になります。画面を先に作り、Wailsには再ビルドを省略させます。

## 固定するものと更新するもの

Goはプロジェクトの設定、Wails CLIはアプリが使う版と合わせます。Goの自動切り替えを止めると、古い設定では動かない依存を検知できます。Node.jsは24系列の更新を取り込みます。runnerや配布サーバーまで完全に固定するわけではありません。

Actionsのタグは移動できるため、確認したコミットSHAを使います。ただし固定したままでは修正を取り込めません。更新案とレビューを組み合わせる必要があります。

## CIの成功に含まれないもの

DOMテストとビルドは、実WebView2や日本語IMEの操作確認とは別です。また、読み取りトークンでもPRのコード自体はrunner上で実行されます。秘密情報を渡さず、公開やマージを自動化しないことが最初の安全境界になります。
