# 外部操作の部分成功を扱う

ブラウザー起動とSQLite保存は同じトランザクションにできない。先に日時だけ保存すると、起動に失敗しても「アクセス済み」になる。そのため起動要求の成功後に日時を保存する。

逆に、起動成功後に保存が失敗する場合は残る。開いたページを閉じることも、表示済み日時だけ更新して成功に見せることもしない。部分成功を利用者へ伝え、保存済み日時を維持する。

時刻は起動成功後に取得する。起動関数・時刻関数・保存境界を注入すると、ブラウザーや利用者DBに触れずに順序と失敗を検証できる。OSの要求受付、ページ表示、読了は違う事実であり、テストでも混同しない。

画面には別の競合もある。一覧取得を始め、その間にアクセス日時を保存すると、後から届いた古い一覧が日時を戻す可能性がある。読取開始後に保存した日時だけを重ねることで、一覧に追加された別作品を失わずに新しい日時を保つ。

正本: [作品API](../work-api.md)、[ADR-0005](../adr/0005-define-library-behavior.md)、[Issue #25](https://github.com/asam-masa/manga-update-manager/issues/25)。実ブラウザーとWebView2の確認は自動テストでは代替できない。
