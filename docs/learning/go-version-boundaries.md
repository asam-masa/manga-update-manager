# 最低Go版とビルドするGo版を分ける

`go.mod`の`go`行は、モジュールが必要とするGoの下限を示す。今回のx/image更新では、この下限も上がった。依存版だけを見ると開発環境への影響を見落とすため、依存のgo.modとPR全体を確認する。

最低版1.26.0と、修正を含む1.26系の最新実行版は役割が違う。CIで最低版を直接選び続けると、その後の修正を取り込めない。今回は系列を固定して最新修正版を選び、実行した版をログに残す。変動する版を使うため、後から検証を再現するときは当時の実行版を指定する。

`GOTOOLCHAIN=local`は、依存がさらに新しいGoを要求したとき、暗黙の取得で成功させず判断が必要な変更として発見するために残す。ローカルで`GOTOOLCHAIN=go1.26.9`を指定する場合も、システムGoを置き換えず明示した検証版を使う。

この説明は判断の正本ではない。[ADR-0015](../adr/0015-separate-go-minimum-and-validation-version.md)と[CI運用](../develop/workflow/continuous-integration.md)を参照する。最低版での実行、将来の修正版、Go 1.27の成立を今回の成功から推定しない。
