# 入力表示と検索条件を分ける

## IMEの入力はまだ検索条件とは限らない

日本語IMEの変換途中でも入力欄には文字が現れる。それを毎回一覧へ適用すると、候補を選んでいる最中に一覧が変わる。入力表示と確定した検索条件を分けることで、利用者の入力を見せつつ一覧を安定させられる。

## 検索用の変換は保存値に適用しない

全半角を区別しない検索のためにタイトル自体を書き換える必要はない。比較する文字だけを変換すれば、表示・コピー・保存は元のタイトルを維持できる。

NFKCは幅の違いだけでなく「①」と「1」などの違いも除く。今回は全半角の同一視だけを合意しているため、幅の文字範囲に限定して使う。変換の便利さと、何を同じと扱うかという仕様を混同しない。[Unicode UAX #15](https://www.unicode.org/reports/tr15/)で正規等価と互換等価の違いを確認した。

## 表示条件と保存処理は独立させる

検索中に登録しても検索を解除しない。保存が成功して一覧へ表示されないことは矛盾ではなく、検索条件に合わないだけである。その理由を成功通知に含める。また、非同期処理の開始時ではなく、完了時の現在の検索条件に合わせて案内する。

フォームを閉じることと、入力を破棄することも別の操作である。入力状態をAppが保持し、フォームだけを隠すことで両者を分離する。再起動後の永続化は別Issueとし、今回の画面状態を保存ファイルへ結び付けない。
