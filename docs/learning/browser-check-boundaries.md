# 見た目・操作・マージ条件を分ける

画像が基準と一致しても、Escや保存が動くとは限りません。#361では同じ実React画面に対し、画像比較とは別に「Escで候補が閉じ、開いたボタンへフォーカスが戻る」という観測を加えました。Escを一時的に遮るとフォーカス検証が失敗したため、この操作の回帰を検出できる根拠になりました。全キーボード操作を保証した結果ではありません。

合成APIを使うと、利用者DBを変更せずタグの改名・削除後の画面を検証できます。一方、実際のトランザクションや再起動復元は通りません。画面試験を増やしてもGo・SQLite試験と必要な実機確認を残す理由は、経由する境界が異なるためです。

また、CIコマンドが非0で終わること、ジョブが失敗すること、GitHubがマージを拒否することは別の段階です。`continue-on-error`を外すだけではGitHubの必須チェックは設定されません。今回の調査でもclassic protectionは404でしたが、別のrulesetは有効でした。設定方式を確認し、既存の保護を保持した追加案を作り、個別承認後に読み戻す必要があります。
