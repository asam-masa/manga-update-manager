# 保存処理より先に画像の通り道を確かめる

画像を生成できても、Go側のファイルをReactの画面へ渡せるとは限りません。開発時のViteと、exeへ組み込む画面では、リクエストの経路が違います。

今回は通常アプリとは別の小さなWailsアプリを作り、赤と青の合成画像を使いました。同じURLを二度取得して画素が変わるかを、実WebView2内で確認しました。URLに毎回違うクエリーを付けるとキャッシュの問題を隠すため、今回はURLを固定してno-storeの応答を調べました。

GoのHTTPテストは経路と不正入力を詳しく確認できます。一方、実WebView2の観測は実行環境の結合を確認します。どちらも必要ですが、本番の保存・DB・削除や目視確認の代わりにはなりません。

試作の成功は、候補方式を使える根拠です。本番方式の採用や安全性全体の証明ではありません。技術的に可能かという問いと、どの方式を採用するかという判断を分けます。
