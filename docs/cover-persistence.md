# 画像保存・配信契約

Issue #42の実装前の設計メモ。本番未実装であり、具体API名・型は実装予定である。成功境界は[ADR-0013](./adr/0013-define-cover-operation-boundaries.md)、起動排他は[ADR-0014](./adr/0014-lock-storage-before-startup.md)を正本とする。

## 保存順序

1. 同じ作品の操作権を確保し、作品の存在を確認する。
2. 元画像を読み取り、既存の`thumbnail.Generate`でPNGを生成する。
3. アプリ専用領域の`covers`へ別名で保存する。既存画像を上書きしない。
4. 書き込み・同期・ファイル確定の失敗を確認してからDB参照を変更する。
5. DB確定後、旧管理画像が未参照と確認できた場合だけ削除する。失敗は成功結果の警告とする。

DB確定前の失敗では旧画像と旧参照を保持する。新規未参照ファイルの後処理にも失敗した場合は残置し、次回の安全な起動時整理で再試行する。解除はDB参照を外してから同じ削除条件を確認する。元画像は変更・削除しない。電源断やストレージ自体の故障に対する完全な耐久性は保証しない。

画像の設定・変更・解除がDBへ確定した時点で、作品内容の`updatedAt`を同じDBトランザクションで更新する。キャンセル・DB確定前の失敗・すでに未設定の解除では更新しない。DB確定後の削除警告では更新済み日時を戻さない。`createdAt`、`lastAccessedAt`、漫画の更新予定は変更しない。時計が戻った場合も日時の既存規則を壊さず、保存済み`updatedAt`より前へ戻さない。

## APIの実装予定

| API | 入力 | 成功結果 |
| --- | --- | --- |
| `SelectWorkCover` | 作品ID | `cancelled`、`work`、`warnings` |
| `RemoveWorkCover` | 作品ID | 更新後の`work`、`warnings` |
| `LoadCoverWarnings` | なし | 起動時整理の警告配列 |

`work`は既存作品DTO、`warnings`は安全な`code`と`message`の配列。選択キャンセルでは`cancelled: true`、`work: null`、空の警告配列を返し、変更と通知を行わない。成功結果に元画像のパスや内部診断を含めない。DB確定前の失敗は既存の`{code, message}`によるrejectへ変換する。

選択画面はアプリ全体で一つ。同作品の選択・取り込み・解除は完了まで拒否し、失敗・キャンセルでも処理中状態を解放する。別作品は選択画面が閉じた後なら受け付け、生成は既存処理で直列化する。終了処理は開始済み操作の終了を待ち、DBを先に閉じない。画像操作UIと警告表示はIssue #43で扱う。

## ファイルと配信の安全条件

DBには管理領域内の相対パスだけを保存する。元ファイル名や画面指定のパスを管理名へ使わない。新規名の衝突時は上書きしない。既存の任意の相対パスを削除してよいアプリ生成画像と同一視しない。

管理ディレクトリと対象のreparse point・複数hard link・ディレクトリを拒否し、チェックと操作の間の付け替えも検証する。`os.Root`による領域制限だけで領域内リンクも拒否できたとは扱わない。Windowsの開いたハンドルの属性・種類・共有制御を使う具体方式は、実装テストが成立してから確定する。保存・削除・配信で同じ安全条件を守る。

Middlewareは固定接頭辞と正の作品IDからDBの現在画像を解決する。任意パスを受け取らず、GET以外、余分なパス・クエリ、エンコードされた区切り・二重エンコードを拒否する。正常な管理PNGを`image/png`、`no-store`、`nosniff`で返す。未設定・不存在・欠損・破損は画像を返さず、DB参照を自動解除しない。内部パスをHTTP応答へ含めない。

## 起動時整理

排他とDB初期化の後、画像操作を受け付ける前に行う。全参照の取得に失敗したら何も削除しない。管理領域内のアプリ生成ファイルで、通常ファイル・安全なリンク状態・DB未参照を確認できたものだけを処理する。名前だけで所有や安全性を証明しない。未知名・サブディレクトリ・判定不能なファイルは削除しない。整理失敗でも一覧を利用可能にし、まとめた警告を保持する。保存先全体の再帰削除は行わない。

## 検証計画と未決定事項

一時SQLite・一時ファイル・合成画像で、保存段階ごとの失敗、容量不足相当の書き込み失敗、同期・Close失敗、DB失敗、削除失敗、途中終了と次回整理、参照取得失敗を確認する。同作品競合、別作品並行、選択多重要求、キャンセル、終了待ちも確認する。

別作品が同じ旧参照を持つ場合に削除しないこと、リンク・管理外参照・未知名・付け替えの拒否を検証する。開発版とexeで正常配信、差し替え後の再取得、未設定・欠損・破損、メソッド・エンコード拒否を確認する。

画像操作と`updatedAt`の関係は2026-10-12に承認された。ファイル命名の識別子、アプリ生成ファイルと判断する根拠、OS呼び出し、具体的なエラーコードは実装前に記録する。特に「名前だけで所有を証明しない」を満たす方式は、起動時整理を実装する前の確認条件である。未決定の間はIssue #42のDoR達成とは扱わない。通常レビューに加えて独立レビューを行い、本番実装の安全性は実行検証で確認する。
