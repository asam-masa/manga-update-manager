# タグ保存と作品編集の内部契約

Issue #301、親#294/#30。[ADR-0020](./adr/0020-confirm-tags-with-work-edits.md)の保存境界を具体化する。テーブルは[データ仕様](./データ仕様.md#タグ保存の構造issue-299)を参照する。#303の[公開API](./tag-api.md)、#306の[編集画面](./work-screen.md#タグ編集の画面接続issue-306)、#310の[削除確認](./work-screen.md#削除確認のタグ接続issue-310親295)へ接続する。管理の保存処理は#313、取得APIは#320、変更APIは#314へ接続し、管理画面・絞り込みは後続である。

## 接続と読取

`Store.Open`は専用の`modernc.org/sqlite.Driver`を`manga-sqlite`として使う。インスタンスの接続フックで物理接続の作成ごとに`PRAGMA foreign_keys=ON`を実行し、値が1であることと検査用Rowsの解放を確認する。DSNより後に適用し、失敗した接続は使用しない。プール再接続も対象とし、標準名`sqlite`の設定は変更しない。新規依存や接続数の変更はない。

`ListTags`は未使用を含む全タグ、`WorkTags`は指定作品のタグを取得する。`manga.Tag{ID, Name}`のID昇順で、空は空一覧を返す。作品不存在は`ErrWorkNotFound`。タグは既存の比較可能な`manga.Work`から分離する。候補検索・表示順のUI規則は呼出側で扱う。

ID・保存名を検証し、不正値や資源解放失敗があれば部分一覧を返さない。LEFT JOINは参照先不在を黙って省かずエラーにする。不正値を正規化して修復しない。受付・取消・停止とRows解放は既存Storeの境界を使う。同Storeの受付枠を保持するが、外部ツールが直接変更するDBの読み取りスナップショットを保証しない。

## 編集と削除確認

内部`EditWorkInput.Tags`は任意の`*manga.TagEdit`。nilは現在の関連を保持し、非nilの空選択は全解除する。`Existing`は保存済みID・正確な名前、`NewNames`は複数の新規作成意図。入力をコピーして同じID/同名の重複をまとめ、同IDの異なる名前・不正名を拒否する。検索用の表記正規化はしない。

既存選択はTx内でID・名前を照合する。不在・改名は`ErrWorkTagsChanged`で拒否し、作品も保存しない。新規名は前後空白除去後の完全同名を再利用し、なければ作成する。既存選択との重複も一つの関連へまとめる。実際に差がある関連だけを追加・削除し、変更件数1を確認する。

作品のテキスト・予定日・タグ作成・付け外しは既存`EditWork`と同じTxで確定する。同じ関連の再選択や順序違いだけなら変更なし。テキストも同じならUPDATE/Commitをしない。タグだけの変更でも`updated_at`を更新し、既存日時より戻さない。登録日時・アクセス・画像・予定日など、今回指定していない値を保持する。

確定前の拒否・SQL失敗はロールバックし、未確定タグだけ残さない。Rollback失敗はDB停止、Commit結果不明は成功値なし・DB停止・自動再試行なし。確定後の接続解放失敗は既存の`ErrWorkEditCommitted`と成功結果を維持する。結果不明を未保存と断定しない。

内部`WorkDeleteInput.Tags`は任意の正確なID/名前集合。指定時はTx内で順序に依存せず比較し、差は`ErrWorkDeleteChanged`。未指定は従来呼出しと互換にし、タグ照合を追加しない。作品削除のCASCADEは関連だけを外して未使用タグを保持する。#301時点では公開削除DTOは未変更だったが、#303で任意のタグ集合を受け取る。#310で画面からスナップショットを伝え、変更後の再確認へ接続する。

## 検証範囲と後続

#317で管理用の使用作品数と削除確認情報の読取、#313で改名・削除の内部確定を追加する。[管理の契約と検証範囲](./tag-management.md)を参照する。取得APIは#320、変更APIは#314へ接続し、管理画面は引き続き後続である。

一時DBで複数新規・同名再利用・大小別名・重複・無変更・未指定保持・明示解除・再接続・タグだけの更新・削除スナップショットを検証する。接続再作成とDSNのOFF指定でも外部キーが有効なこと、別ドライバーへ設定を広げないことを検証する。既存公開編集APIからのタグ保持も合成DBで確認する。

改名・削除・UPDATE拒否・関連INSERT拒否・RAISE(IGNORE)の0件変更を模擬する。最初の0件INSERTケースは作品だけが保存されて失敗したため、変更件数検査を追加し、作成/追加/削除の0件ケースを成功確認した。

実SQLiteのCommit後に失敗を返す合成ドライバーでは、応答は結果不明/DB停止だが再接続で作品とタグの一括確定を確認する。Rollback後に失敗を返す合成故障、不正保存名とRows.Close失敗も区別する。物理障害・電源断や、Wailsのタグ操作を実機検証した結果ではない。

#303で公開API・DTOの省略互換とエラー分類、#306で編集画面、#310で削除確認画面の再確認手順を検証する。管理の競合・削除後の選択条件、絞り込みは#296/#297に残す。ADR-0020はPendingを維持する。
