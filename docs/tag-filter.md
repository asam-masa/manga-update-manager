# タグによる作品一覧の絞り込み

Issue [#323](https://github.com/asam-masa/manga-update-manager/issues/323)、実装の親は[#297](https://github.com/asam-masa/manga-update-manager/issues/297)。2026-10-31の相談と合成サンプルで承認された設計を記録する。製品への接続は未実装であり、[ADR-0020](./adr/0020-confirm-tags-with-work-edits.md)のValidation StatusはPendingを維持する。

## 条件と候補件数

- 選択タグをすべて持つ作品を表示するAND条件とする。未選択ならタグで制限しない。選択操作で作品のタグ自体は変更しない。
- 漫画名検索・予定条件・タグ条件を全作品へ適用し、既存の並べ替え後にページ分割する。表示中のページだけを検索・集計しない。
- 候補の件数は「現在の漫画名検索・予定条件・選択済みタグに、その候補も加えた場合の作品数」。選択済み候補を重ねても条件を増やさず、現在の一致件数になる。
- 管理画面の使用作品数は全作品に対する数であり、この候補件数と混同しない。候補検索の文字は候補名だけに適用し、作品の条件や件数を変えない。
- 未使用タグや追加すると0件になるタグも表示・選択できる。0件は取得失敗とは区別し、条件を減らす案内とタグ全解除を表示する。タグ全解除では漫画名検索や予定条件を解除しない。
- 候補はタグ名の自然な昇順、同順位はタグID昇順に揃える。検索とタイトル順の既存比較を再利用し、件数の変化で候補を移動させない。
- 候補検索は既存の全半角・英字大小の違いを吸収した部分一致とする。保存名の同一性やタグ統合は変更しない。

## 配置と操作

通常幅では漫画名検索・並び順・「タグで絞り込み」を横並びにする。ボタン近くに候補のポップアップを開き、内部に候補検索とスクロール可能なチェック欄を置く。狭い幅では操作を折り返し、ポップアップを画面幅に収める。一覧を押し下げずに候補を開ける反面、開いている間は一覧の一部が隠れる。

選択済みタグは検索操作の下に解除ボタン付きで並べ、「すべて解除」を置く。多数・長い名前は折り返し、横にはみ出させない。閉じている間は候補欄の高さを取らない。候補の選択・解除は即時反映し、複数選択中も開いたままにできる。

- 開くと候補検索へフォーカスを移す。Tab／Shift+Tabで操作し、標準チェックボックスのSpaceで選択する。モーダルとしてフォーカスを閉じ込めない。
- Esc・閉じるボタンでは候補だけを閉じ、開いたボタンへ戻す。外側クリックでも閉じるが、クリック先の操作・フォーカスを奪わない。いずれも選択を保持する。
- 条件変更による再描画で、操作中のチェック欄のフォーカスを失わない。候補名検索中のIME入力を壊さない。
- 管理・作品編集等の既存ダイアログを開く場合は候補を閉じ、既存のモーダルと処理受付を維持する。

## 条件変更とページ

| 操作・変化 | 条件とページ |
| --- | --- |
| 選択・個別解除・全解除 | 即時反映し1ページ目へ戻す。検索と予定条件は維持 |
| 表示形式の切替 | タグ条件を維持し、ページは既存の形式切替方針に従う |
| 再起動 | 選択タグ・候補検索を解除。新しい永続設定は追加しない |
| 選択タグの改名 | 固定IDの条件を維持し、新しい表示名へ更新。現在ページを維持 |
| 選択タグの削除 | 削除された条件だけ外し、通知して1ページ目へ戻す。残る条件で作品が増える場合がある |
| 作品編集で一致対象が変化 | 現在ページを維持し、範囲外なら最後の有効ページへ補正 |

改名・削除は、管理APIの確定した結果または取得に成功した完全な最新情報から判断する。読込失敗・部分応答・古い遅延応答で選択条件を削除しない。削除による条件解除通知は候補を閉じても残す。既存の操作結果やDB停止警告を上書きして消さない。

登録後の対象ページへの移動、予定日の見直し等は[一覧設計](./library-design.md)の既存契約を維持する。絞り込みから外れた作品でも、開始済みの編集・画像処理・ページ起動等を取り消さず、結果通知を保持する。

## 同じ時点の情報をまとめて取得する

作品一覧・未使用を含む全タグ候補・作品とタグの対応を、一つの読取スナップショットとして取得するAPIを追加する。既存のListWorks・LoadTags・LoadWorkTagsや管理APIは互換性のため残す。既存APIを作品数分呼ぶ方式は採用しない。

Storeは一式を同じ時点の状態として読み、Applicationが利用する読取interfaceを経由してWailsへ公開する。複数SQLを使う場合も同じ読取トランザクション等で整合性を保証する。具体的な公開名・型と実現方法は取得APIの実装Issueで固定し、既存WorkDTOや識別子精度の互換性を確認する。異なる取得結果を画面で寄せ集めて一式と扱わない。

- 空の成功配列と未取得を区別し、全作品・全候補・全対応が成功・検証済みの場合だけ一式を採用する。不正ID・重複・不存在への関連等は修復や黙示除外をせず、失敗として返す。
- 作品の同一性は既存のIDと登録日時の扱いを維持する。削除後に同じ数値IDで登録された別作品へ古い関連や応答を適用しない。新しいDTOのID表現と照合は既存の[タグAPI](./tag-api.md)の精度を損なわない。
- 読取から検証・DTO変換までDBの寿命を保ち、内部診断やパスを利用者へ返さない。DB停止を通常の読込失敗へ戻さない。
- 画面は要求の世代と操作結果の反映順を管理する。新しい取得や編集・削除の確定後に、古い応答で作品・候補・条件を巻き戻さない。必要な再取得で失敗しても、確定済みの操作を未確定や通常失敗へ変えず、自動再送しない。

## 取得中・失敗時

再取得中・再取得失敗時は選択条件と前回の一覧を残し、「最新情報は未確認」と明示する。成功するまでタグの追加・個別解除・全解除を止め、再読み込みを用意する。再取得中に一部だけ新しい作品や件数へ切り替えない。前回情報を使う場合も候補件数を最新と表示しない。

初回失敗はタグなし・作品0件の正常状態として扱わず、エラーと再読み込みを表示する。選択中のタグが見つからなくても、完全な取得に成功するまでは削除と判断しない。DB停止・結果不明を観測した場合は既存の停止と警告保持を優先し、再読み込みで書込可能へ戻さない。

## サンプル確認と検証の限界

[HTMLサンプル](../tools/mockups/tag-filter/index.html)は30作品・8タグの合成データだけを使う。通常・多数選択・0件・再取得失敗・初回失敗・選択タグ削除後の表示例を切り替えられる。DB・Wails・ネットワーク・外部ページ起動・永続化は接続しない。

2026-10-31にChromeの1200×900、520×960で描画を確認し、利用者は通常幅のポップアップと狭い幅の選択タグの折り返し配置を承認した。ブラウザー内の簡易チェック7項目でAND件数・未使用候補・半角カナ比較・開いた後のフォーカス・閉じた後の選択とフォーカス・0件案内・取得失敗時の条件変更停止を確認した。人による全操作の試験、実APIの原子性、遅延応答や競合、実WebView2のIME・キー操作・3形式は未検証である。

サンプルの6件ページ、行へのタグ補助表示、2種類だけの並び順、静的な予定表示と状態切替は確認用の仮動作。製品の小型20件・行20件・カード12件や既存の並び順・予定条件を変更しない。サンプルのIntl.Collatorは概略比較であり、製品の正確な自然順比較の試験を代替しない。

## 後続の分割と着手条件

設計PRのマージ後、#297を親として次の単位を具体化する。API層の変更が大きい場合は内部取得と公開APIをさらに分ける。

1. 同一時点の一括取得と公開API：型・識別子・空/不正/部分結果・寿命・停止・別接続での途中変更・既存API互換を確認する。
2. AND条件と候補件数の計算：全件で検索・予定・タグを合わせ、自然順、0件、未使用、候補検索との独立性、ページ分割前の集計を試験する。
3. 画面接続と実機検証：承認配置、初回/再取得失敗、遅延応答、改名/削除後の条件、作品編集・ページ補正・通知保持、3形式、再起動解除、Tab／Space／Esc・IME・狭い幅を合成保存先の実WebView2で確認する。

設計サンプルの承認だけで#297の実装・機能全体の検証完了とはしない。OR、タグ統合・階層、検索/選択タグの再起動保持、新しい並び順、通常の利用者データでの検証は対象外とする。
