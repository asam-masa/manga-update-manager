# PR・レビュー運用

## PRの原則

- 一つのPRでは一つの目的を扱う
- 背景、変更内容、確認結果、対象外、既知の制約を記載する
- 大きな変更は、独立して検証できる単位へ分割する
- 設計上の重要な判断はADRへリンクする
- 自動生成物や個人データを含めない

## レビューコメント

指摘には重要度と根拠を含めます。

| Prefix | 意味 |
| --- | --- |
| `[must]` | マージ前に対応が必要 |
| `[should]` | 原則として対応する。見送る場合は理由を残す |
| `[question]` | 意図や前提の確認 |
| `[suggestion]` | 任意の改善提案 |
| `[praise]` | 良い判断や実装の共有 |

## マージ条件

- 受け入れ条件を満たしている
- `[must]`がすべて解決されている
- 必須のテスト、静的解析、ビルドが成功している
- 必要な文書とADRが更新されている
- 個人データと秘密情報が含まれていない
- 未対応事項がIssueまたはPRへ記録されている
