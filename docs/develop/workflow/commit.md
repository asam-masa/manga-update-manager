# コミット

## 粒度

- 一つのコミットでは一つの論理的な変更を扱う
- リファクタリングと振る舞いの変更は可能な限り分ける
- コードと、その変更に必要なテスト・文書は同じコミットに含めてよい
- ビルドまたはテストが失敗する中間状態を共有しない
- フォーマットだけの変更を機能変更へ混在させない

## メッセージ

```text
#<issue-number> <変更後の状態を表す日本語>
```

例:

```text
#12 作品を登録できるようにする
#18 未アクセス期間の境界値を修正する
```

Issueがない軽微な変更では番号を省略できます。「修正」「対応」だけで終わらせず、何が変わるかを現在形で記載します。

## コミット前の確認

- `git status`と`git diff`で対象を確認する
- ファイルまたは差分を明示的にステージする
- 個人データ、秘密情報、キャッシュ、デバッグ用ファイルを含めない
- 必要なテストと文書更新を含める
