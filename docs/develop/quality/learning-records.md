# 学習に使える判断記録

## 目的

設計と実装から学んだ内容を、後から根拠に基づいて振り返れる状態にします。結論だけでなく、判断時点の問題、制約、代替案、採用理由、実施後の結果を残します。

## 記録先

同じ内容を複数の場所へ重複して書かず、情報の役割に応じて記録します。

| 記録先 | 残す内容 |
| --- | --- |
| GitHub Issue | 解決する問題、受け入れ条件、対象外、依存関係、未決定事項 |
| ADR | 判断時点の事実、判断基準、現実的な選択肢、トレードオフ、Decision、Consequences、Validation |
| PR | 実際の変更、実装上の判断、確認結果、未実施項目、既知の制約、後続作業 |
| 安定した設計文書 | 現在有効な要件、データ仕様、安全設計、開発規則 |
| コミット | 変更の目的を表す簡潔な要約と関連Issue番号 |

重要な判断はPR本文だけで完結させず、ADRの作成基準を満たす場合はADRへ記録します。小さく容易に戻せる実装判断は、PR本文へ理由と結果を記録します。

## 記録する観点

後から判断を再現できるよう、該当する観点を記録します。

- 何が問題だったか
- 判断時点で確認できた事実は何か
- どの制約と失敗条件を考慮したか
- どの現実的な選択肢を比較したか
- 各選択肢の利点、欠点、リスクは何か
- 何を選び、なぜ選んだか
- 何を実施したか
- どのテストまたは手動確認を行い、結果はどうだったか
- 何を未検証として残したか
- どの条件で判断を見直すか

すべての変更に全項目を要求しません。判断の大きさと変更リスクに応じ、後から選択理由を説明するために必要な情報を残します。

## 時系列と確度

- 判断時点で確認できた事実と、実施後に判明した結果を分ける
- 事実、推論、提案、Decisionを混同しない
- 未検証の項目を成功として記録しない
- 後から結果が判明した場合は、当時の記録を書き換えて経緯を消さず、Validationまたは後続PRへ追記する
- 文書と実装が異なる場合は、どちらかを推測で正しいとせず不整合を明記する

## 学習での利用

`.agents/skills/quiz-project-decisions`は、Git履歴、GitHub Issues、PR、ADR、設計文書を読み取り専用で確認し、実際の判断を自由回答の問題として構成します。

クイズのために架空の正解を作りません。根拠が不足している場合は、追加資料を確認するか、別の題材を選びます。回答、成績、出題履歴はリポジトリや外部サービスへ保存しません。
