# コードレビュー観点

次の順序で確認します。

1. Issueの目的と受け入れ条件を満たすか
2. 責務と依存関係が妥当か
3. 正しく安全に動作するか
4. 重要な振る舞いがテストされているか
5. 読みやすく保守できるか

## 確認事項

- 正常系、主要な異常系、境界値が考慮されている
- UI、ドメイン、永続化、外部通信の責務が混在していない
- 将来の可能性だけを理由に抽象化を増やしていない
- エラーを握りつぶさず、利用者が次の行動を判断できる
- 時刻、ファイル、データベース、外部通信をテストで制御できる
- URL、パス、外部入力を検証している
- Cookie、認証情報、閲覧履歴をログやリポジトリへ出していない
- 自動取得が利用規約と安全設計に従っている
- 新しい依存関係の必要性、保守状況、ライセンスが説明されている
- 変更に伴う文書とADRが更新されている
